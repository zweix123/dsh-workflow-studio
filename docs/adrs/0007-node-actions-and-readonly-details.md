# 节点操作、只读详情与插件自管交互

为保持独立节点插件的业务控制权，同时让实例画布保持统一，Studio 提供卡片公共外壳和三个明确编号的操作位，节点通过公共契约定义各位置的动作、图标、排列与可用状态；图标和按钮由 Studio 统一渲染，节点不替换公共卡片或改变 DAG 排布及编排状态。三个位置不绑定统一的业务含义，允许留空，以容纳不同节点的交互方式。

详情只承担只读展示与浏览，业务动作从卡片操作位进入；复杂输入由相应节点插件自行管理浮窗，并复用宿主公开组件。相较继续在详情内编辑或由 Studio 统一管理所有输入界面，这一选择使通用详情保持稳定，插件能够独立定义交互生命周期，也要求插件负责草稿、错误与浮窗关闭规则。

公共接入协议继续归属独立的 `dsh-workflow-node`，沿用 [ADR 0005](./0005-node-owned-business-state.md) 的业务状态与持久化分工和 [ADR 0006](./0006-independent-node-plugin-registry.md) 的插件登记边界。设计已于 2026-10-13 逐项确认并实施；行为、内置节点排位和验收目标见[节点操作位与输入界面](../specs/node-action-positions.zh.md)。

2026-10-15 的[运行记录规格](../specs/node-run-records.zh.md)调整只读导航范围：详情公共区域提供统一历史外壳，各节点负责当次专属内容，可导航对应宿主原生执行记录；详情仍不提供业务动作或主对话导航。台前 Agent 仅从详情历史打开“交付记录”，卡片第 3 位留空；台后最新与旧“执行记录”也统一从侧边详情抽屉历史访问，最新默认展开，无地址项说明原因且不提供导航；台后金刚位只保留业务交互，启动后第 1 位留空，取消多条选择浮窗。主对话及节点明确登记的各次原生记录均可通过宿主标题栏返回实例，按持久会话身份定位节点，不沿宿主父链推断归属；见[会话返回规格](../specs/session-agent-instance-navigation.zh.md)。已接受结果交付失败统一使用“重试交付”，Bash 首次执行与失败/未知后的重新执行分开命名。
