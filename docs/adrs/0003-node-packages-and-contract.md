# 节点按包组织，契约归属于 studio

为使节点的业务行为与专属界面能够按统一接口独立开发，每种节点类型在 `packages/` 下独立成包，包内分别提供服务端与前端实现；dsh 的安装单元仍然只有 studio 插件。studio 负责装配与工作流协调，通过契约使用节点，不解释节点内部交互。

公共节点契约放在 studio 的 `src/contract/node/`，由 studio 内部调用方与节点包共同引用，不单独建立契约包。契约自身不依赖 studio 的工作流、DAG、存储或具体节点实现。此处选择在已有插件中开放独立契约入口，避免仅为接口归属增加一个包；源码依赖方向与包依赖环的构建处理需分别验证，不能以类型导入推断包依赖环已消失。

节点可以声明并使用装配时注入的固定版本 dsh 公开服务，不要求 studio 再封装全部宿主能力。studio 可以提供节点界面的挂载区域，节点自主实现区域内全部内容与业务交互，不被限定为统一业务界面中的内容插槽，也不以 form 的界面形态限定其他节点；具体挂载与画布协作方式在这些约束下实现。

本决定确认模块组织和契约归属；行为与验收范围见[节点模块契约与表单节点规格](../specs/node-modules.zh.md)，具体接口和构建方式按其约束落实。本期实现 chat/bash 模块化及最小 form 的真实输入输出链路，不设计或创建模板契约。
