# 按 kind 解释节点配置，允许不同类型复用字段名

节点定义通过唯一的 `node_kind` 选择实现，因此不同节点类型使用同名业务配置字段不会产生解释歧义。为支持节点包独立开发，配置字段由当前 kind 的实现解释和校验，取消全局字段名排他规则，也不再根据其他 kind 的字段归属判定误用；一个节点的配置合法性不应因新增无关节点包而改变。

kind 标识仍须唯一，节点不得覆盖 `id`、`type`、`node_kind`、输入输出契约等公共字段的语义。未知配置字段延续透传规则：框架校验公共字段，节点校验自己声明的字段，其余字段保留但不解释。必需字段缺失、已知字段类型错误仍报错，不能用其他 kind 的字段清单判断当前配置是否合法。

本决定替代 [ADR 0002](./0002-workflow-node-field-ownership.md) 中的全局字段排他与跨类型误用检查，暂不改变代码。代价是失去原先基于全局字段归属的错误提示；收益是节点配置与无关节点实现解耦。相关术语改为“节点配置字段”，见 [CONTEXT.md](../../CONTEXT.md)。
