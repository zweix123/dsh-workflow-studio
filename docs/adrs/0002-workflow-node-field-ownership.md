# 工作流节点的字段归属与校验边界

本文的全局字段排他与跨节点类型字段误用检查决定，已由 [ADR 0004](./0004-node-config-scoped-by-kind.md) 替代；节点模块组织与契约归属以 [ADR 0003](./0003-node-packages-and-contract.md) 为准，生命周期和控制权分工以 [ADR 0005](./0005-node-owned-business-state.md) 为准。下文保留原始决策背景；新决定尚未实施到代码。新阶段范围见[节点模块契约与表单节点规格](../specs/node-modules.zh.md)。

session_agent 和 bash 是工作流内置节点族，不提供脱离工作流的独立执行能力。节点定义共享基础字段，各节点族声明自己的专属字段；这里的继承表达字段归属，不要求执行过程沿类继承链调用。

DAG 编排字段保持原有含义：`type` 区分 `node`、`dag` 和 `edge`，`id` 标识定义。工作流节点以显式必填的 `node_kind` 区分 `session_agent` 和 `bash`，未来可以增加节点族；`is_auto_start` 是控制自动启动的公共字段。`prompt` 归 session_agent，`command` 归 bash。DAG 引擎继续解释编排字段，工作流模块负责选择内置节点能力并管理执行状态。

公共字段由基础定义统一声明，节点族可以继承使用；同名专属字段不得被不同节点族重复声明，这属于节点族定义冲突，与具体配置是否使用该字段无关。配置引用其他节点族的专属字段时必须报错；没有已知归属的字段则保留原始值，不解释其业务含义。选择这一边界，是为了发现内置功能的错误配置，同时保留 DAG 对自定义字段的透传能力，而不采用拒绝所有未知字段的封闭配置结构。

完成规则由节点族决定，不建立所有节点共有的人工验收阶段，也不提供 `is_auto_finish`：bash 成功执行后完成，失败不推进下游；session_agent 本期由用户明确标记任务完成。命令退出与对话任务完成的含义不同，不能仅为统一字段而增加一道通用验收步骤。

配置细则、模板迁移和本期执行边界见 [工作流节点规格](../specs/workflow-nodes.zh.md)。session_agent 的自动完成判定留待后续讨论。
