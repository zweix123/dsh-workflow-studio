# 节点输入输出与统一顶点来源校验规格

状态：正式规格，已确认并实施。本文是实施与代码审查的验收依据；验证结果和未验证项见[宿主验收记录](../acceptance/node-input-output.zh.md)。

后续 form 扩展（2026-10-07）：[对象与数组字段规格](./form-structured-fields.zh.md)已实施，补充结构化填写、预填、默认值与逐层提交校验规则，验证范围见[扩展验收记录](../acceptance/form-structured-fields.zh.md)。本文将对象与数组编辑列为范围外仅指原阶段；既有验收记录不证明后续扩展已通过。

## Problem Statement

模板作者能够声明输入输出 Schema，却无法清楚表达三类节点如何使用输入、交付真实输出。当前 session_agent 只发送原始提示词，bash 只执行原始命令；两者完成后按输出声明生成占位值。命令日志或会话内容并没有因此成为下游的业务数据。

form 已能将正式提交作为真实输出，但其输入与输出的关系需要明确：用户可以收集上游尚未产生的新字段，已有输入用于同名预填，不能要求两份 Schema 完全相同。

工作流创建界面不接受外部业务输入，当前实现却根据根输入声明自动补空字符串、零、false 等占位值。这使声明看起来有数据来源，却没有实际提供业务数据。普通节点与 DAG 都是顶点，应遵守统一的来源规则。

条件边关闭还会使部分声明输入正常缺失。模板作者需要知道哪些缺失合法、文本模板如何处理这种缺失，以及命令结果不合法时为什么节点没有完成。工作流使用者不能修改运行实例中的模板脚本，错误恢复不能建立在运行时编辑脚本的假设上。

## Solution

在模板判定阶段，统一检查所有顶点的输入声明来源与类型兼容，并由各节点类型补充自己的能力约束。没有来源的输入声明不能靠占位值成立；来源边关闭造成的实际缺失则是正常情况。

session_agent 通过提示词中的 Django 风格变量引用使用输入，本期不声明或生成业务输出。bash 通过命令中的变量引用取得安全转义后的参数；声明输出时，以 stdout 中完整的 JSON 对象交付结果，日志使用 stderr。form 按输出契约收集用户数据，以有效正式提交交付下游。

用户可以查看错误并通过已有执行操作重试原命令。合法结果一经接受，后续 DAG 提交失败只重试已保存结果。模板本身错误的修正属于源模板维护；已有实例继续保留创建时的模板快照。

## User Stories

1. 作为模板作者，我希望普通节点和 DAG 使用同一套输入来源规则，以便不用学习两种编排模型。
2. 作为模板作者，我希望每个声明输入都有合法的声明提供方，以便模板不能依赖凭空出现的数据。
3. 作为模板作者，我希望输入来源不存在时在模板判定阶段得到错误，以便执行前修正图结构。
4. 作为模板作者，我希望来源与目标的字段类型兼容，以便数据传递不会依赖隐式转换。
5. 作为模板作者，我希望对象属性和数组元素的声明结构也被检查，以便嵌套数据契约同样可靠。
6. 作为模板作者，我希望不同来源的同名字段继续被拒绝，以便合并结果没有覆盖歧义。
7. 作为模板作者，我希望无入度的结构入口从所属 DAG 查找输入来源，以便入口与普通连接保持一致。
8. 作为模板作者，我希望嵌套 DAG 的来源检查沿输入边界继续向外查找，以便嵌套不成为额外的来源例外。
9. 作为模板作者，我希望根 DAG 也通过公共规则检查输入来源，以便根声明不被当作真实数据本身。
10. 作为工作流使用者，我希望没有外部业务输入时不被自动生成的占位值误导，以便下游使用的是真实来源数据。
11. 作为模板作者，我希望来源边关闭造成的字段缺失被视为正常，以便条件分支仍能汇合。
12. 作为模板作者，我希望部分普通入边关闭、其他普通入边激活时仍沿用既有执行条件，以便此次变更不改写分支调度。

18. 作为模板作者，我希望未支持的条件、循环和过滤器得到明确错误，以便不会误以为已经支持完整 Django 模板。

22. 作为工作流使用者，我希望正常缺失字段在文本模板中替换为空字符串，以便关闭来源不会被误判为模板配置错误。

## Implementation Decisions

- **公共顶点模型。** 普通节点和 DAG 都是顶点，共享输入输出契约、依赖关系与数据传递语义。普通节点执行当前 kind 的业务，DAG 执行内部图并按既有规则交付出口合并结果；不引入继承体系或新的通用节点抽象。
- **来源与声明分开。** 模板判定检查每个顶点输入声明的潜在提供方及类型兼容，不能将目标自己的声明当作实际提供方。来源覆盖继续递归检查对象属性和数组元素，声明键冲突规则保持不变。
- **一致的来源查找。** 有入边时关联前置边提供的字段；无入边的结构入口关联所属 DAG 输入，并沿该 DAG 的来源继续查找。嵌套沿同一规则处理，不增加独立的缺失原因持久化或传递协议。
- **工坊根输入边界。** 工坊创建实例没有外部业务输入来源，根 DAG 同样接受公共来源检查，因此非空根输入声明无法通过；不靠自动生成占位值补足来源，不另加独立的根节点禁止规则。不为工坊新增创建时输入编辑器或输入请求参数。
- **保持编排激活语义。** 等待全部结构前驱完成或跳过后，无 for 入边的目标只要仍有普通入边激活就按既有规则执行，全部入边不激活则跳过；for 的实例数量、空项跳过、聚合与递归规则保持不变。静态来源存在与本次实际到达数据是不同事实。
- **合法缺失与严格交付。** 来源关闭或跳过引起的字段缺失正常，不据此拒绝需要执行的目标。激活来源的声明输出仍必须完整且类型正确，实际已有输入值继续按原有契约检查；不得用放宽输出校验弥补缺失。
- **节点能力约束。** session_agent、bash、form 保持独立节点包及已有装配方式。公共层检查编排字段和来源规则，当前 kind 检查自己的业务配置及能力限制，不恢复全局字段排他，也不让节点包依赖 DAG、工作流或存储内部类型。
- **最小输入模板。** 仅在 session_agent 的 prompt 与 bash 的 command 中支持 Django 风格的变量替换与对象字段访问，写法为 {{ name }} 与 {{ object.field }}。不用 $. 前缀，不支持条件、循环、过滤器、数组索引或通用表达式求值；不自动附加整份输入。
- **引用契约。** 引用必须在当前节点 input_schema 中声明；对象访问的每段须符合声明结构。未知、未声明或不支持的引用在模板判定阶段明确拒绝，不能静默留下未处理的模板表达式。
- **文本转换。** 字符串使用原值；数字、布尔值、对象和数组使用 JSON 文本。零、false 与空字符串不视为缺失。正常缺失引用替换为空字符串；对象路径因对应正常缺失输入而不可到达时同样按正常缺失处理，不进行类型猜测。
- **命令参数边界。** bash 占位符作为独立、未额外加引号的完整参数使用，节点负责 Shell 转义；模板判定拒绝不符合这一规则的用法。含空格、引号、换行或 Shell 特殊字符的输入仍是一个数据参数，不能成为可执行命令片段。正常缺失形成空参数，不省略参数位置。
- **session_agent 输出。** output_schema 省略或为空均表示不声明输出，非空声明拒绝。提示词使用渲染后的输入文本；用户手动完成时提交空对象，不生成占位业务字段，不提取聊天结果，不自动透传输入。会话创建、原关联恢复、人工完成及防重复发送行为继续保留。
- **bash 输出通道。** 非空 output_schema 要求成功命令的 stdout 整体解析为一个 JSON 对象，再按公共输出契约校验，普通日志使用 stderr。省略或空 output_schema 时 stdout 只作日志，完成结果为空对象；不增加结果文件、输出字段映射或命令日志猜测机制。
- **结果校验时机。** 成功退出不等于节点业务完成。非法或空 JSON、非对象 JSON、声明字段缺失、类型错误以及捕获结果截断都不能发布成功输出或推进下游；保留实际输出与错误。声明输出的空命令或空 stdout 也须满足同一规则，不再补占位结果。结果必须能按已声明类型可靠持久化与恢复。
- **失败与重试。** 命令执行或结果构造失败沿用节点失败状态和已有执行操作，重试原模板命令，不自动重跑。用户不能通过运行实例修改模板脚本，接口不能接受命令覆盖来绕过快照。模板本身错误经源模板维护修正后用新实例运行，旧实例快照不热更新。
- **成功结果与提交分离。** 已接受合法业务结果先可靠保存，再提交 DAG；后续编排提交失败保留完成事实与结果，只重试已保存结果。保存失败不得声称结果已被接受；重启恢复不能重做已确认成功的命令，也不能把未知执行结果推断为成功。
- **form 输入输出。** 字段及类型以 output_schema 为准，输入输出无需相同。input_schema 仅声明用于同名预填的上游字段，并与对应输出类型一致；用户新填写的字段不需要上游来源。既有原生标量类型、字段注解、控件、枚举、默认值、页面草稿、服务端提交校验和完成只读规则继续保留。
- **form 真实结果。** 服务端接受的有效正式提交构成输出，上游其他字段和草稿不隐式混入；输入原值不被编辑过程修改。完成结果提交失败仍重试已接受结果，不重新接受表单数据。
- **现有模板迁移。** 同步调整中英文模板中的占位根输入、节点输入来源、session_agent 输出声明与 bash 输出交付方式，使其满足新规则。保持模板原有业务意图；真正消费的字段须获得合法来源，不能用占位值或删除仍被消费的契约来绕过校验。此迁移针对源模板，不改写已有实例快照。
- **文档生效范围。** 本规格更新既有节点规格中的占位根输入、session_agent/bash 占位输出和未消费输入行为，其他已确认功能与 ADR 约束继续有效。实施交付时同步用户语法与使用说明，区分真实日志、业务输出和执行依赖。公共引擎由外部调用方明确提供根输入的接口边界，不等同于工坊无外部输入的模板场景；本期不借此另行建设外部输入产品。

## Testing Decisions

- **测试入口已由用户确认。** 复用现有工作流实例 HTTP 集成入口作为主要测试边界，保留公共 DAG 引擎回归；实现涉及 UI 时按项目技能进行隔离的真实宿主浏览器验收。不新增测试接口或测试框架。
- **测试外部行为。** 断言模板是否可用、实例能否创建、宿主实际收到的提示词与命令参数、接受或拒绝的节点动作、下游实际数据、用户可见错误及重启后的行为；不依赖私有函数名称、解析器内部对象、状态字段布局或队列形状。
- **既有先例。** 工作流实例集成测试已经提供真实临时存储、宿主服务注入、动作请求、并发控制、失败重试、模板快照与重启恢复；公共引擎测试已有声明来源覆盖、类型兼容、条件关闭、嵌套入口、逐项展开与提交回滚场景。新增行为优先在这些公开入口验证。
- **模板判定。** 覆盖普通节点与 DAG 的无来源声明、类型不兼容、嵌套覆盖、工坊无来源根输入、session_agent 非空输出、form 预填声明与输出类型冲突、未知或未声明的模板引用、不支持的模板语法及不符合完整参数规则的命令引用。
- **输入链路。** 从真实 form 提交产生数据，经执行依赖传入 session_agent 与 bash；验证提示词确实使用输入、bash 参数确实使用输入，session_agent 仍只提交空对象，下游所需数据具有另外的真实来源。
- **正常缺失。** 覆盖来源边关闭但另一普通入边激活、关闭分支向后传播、嵌套 DAG 与内部入口继承缺失；确认需要执行的节点不因正常缺失报契约错误，引用替换为空文本或空参数。保留全关闭跳过及 for 特殊规则的原有回归。
- **值与安全。** 覆盖字符串、数字、布尔值、对象字段、对象和数组 JSON 文本，以及零、false、空字符串。通过宿主调用或无破坏性执行验证空格、单引号、换行及 Shell 特殊字符始终保持为一个数据参数，不额外执行输入内容。
- **bash 结果。** 覆盖有无输出声明、stdout/stderr 分离、合法完整对象、空输出、非法 JSON、数组或标量 JSON、缺失字段、嵌套类型错误和截断标记；确认合法输出进入下游并驱动既有 if/for，非法结果显示失败且不推进。
- **失败与恢复。** 验证失败后重试原命令、拒绝命令覆盖、源模板改变不影响已有实例、合法结果提交失败仅重试结果、持久化后重启不重复命令，以及结果未知时保持既有提示和人工重试规则。不能只以内存重置冒充重启恢复。
- **form 与现有管理回归。** 保留同名预填、默认值、页面草稿、枚举和服务端校验、完成只读、独立分支并发、同节点防重、bash 运行时删除保护及删除实例不删除宿主会话。
- **模板与构建。** 验证全部内置中英文模板通过新判定，并保持对应语言版本的 DAG 结构、字段和外部能力一致；运行项目类型检查、构建和完整测试。不得用旧构建缓存或跳过关键断言来宣称交付。
- **真实宿主与验证边界。** 若实现涉及 UI，使用固定 dsh 0.2.0-rc.1、临时 DSH_HOME、非默认端口与 Codex 内置浏览器，按规格记录预期、实际与通过/失败。模拟宿主、接口测试和 jsdom 不替代真实浏览器验收；未运行或被环境阻止的步骤明确标注未验证，不安装或升级 dsh CLI。

## Out of Scope

- 从 session_agent 聊天中提取结构化结果、自动透传输入、自动标记会话任务完成或新增会话取消机制。
- 完整 Django 模板引擎、条件、循环、过滤器、数组索引、通用表达式、额外业务字段的模板化或创建时业务输入编辑器。
- 结果文件、stdout 日志启发式提取、额外输出映射配置、将输入作为可执行命令片段或依赖作者手工转义。
- 为根 DAG、普通节点或嵌套 DAG 建立互不一致的来源规则，新增缺失原因实体、持久协议或通用节点继承体系。
- 改变普通入边激活、跳过、for、聚合、递归、键冲突、额外字段和原子提交回滚语义。
- 运行实例修改模板脚本、热更新历史快照、结果手工编辑、工作流回退、已完成节点重跑或新的自动重试机制。
- form 新增嵌套对象、数组编辑、文件上传、复杂表单设计器、服务端草稿持久化或跨页面同步。
- 安装或升级 dsh CLI、插件发布分发、节点独立安装或将参考目录纳入 Git。
