# Chat 节点结果交付提案

状态：头脑风暴记录，待讨论；不作为当前实现与验收依据。

## 用户故事

作为 develop workflow 的使用者，我希望一个 chat 节点能把工作中确定的关键文件路径交付给下游节点，以便后续步骤直接使用这些文件。

## 问题与初步结论

chat 节点对应普通的 dsh ReAct 对话。仅靠前置提示词，难以保证对话最终准确产出符合 DAG `output_schema` 的字段。虽然插件可以读取会话历史，但历史可能经历上下文压缩；完整记录也可能超过结果提取时的上下文容量。因此，不能把“提交时将全部聊天记录交给模型提取”作为可靠前提。

节点行为由各节点自行定义，chat 节点可以围绕主体对话增加开始前和提交时的操作。初步方向是：用户提交时，先形成一份有界的交付材料，再从中提取关键文件路径等结构化结果；结果通过校验后才交付 DAG。信息不足或提取失败时保留会话与未完成的节点，供用户补充或重试。对必须保留的结论，可在对话过程中写入文件等明确产物，避免只依赖长聊天的回忆。

这只是可讨论的方向。交付材料由谁生成、何时生成、如何核对文件路径，以及失败后的具体交互，均待进一步沟通。本提案不改变当前 chat 节点提交占位输出的行为。
