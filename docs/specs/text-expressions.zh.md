# 文本插值与表达式求值

状态：已实施（2026-10-15）；项目自动化与真实宿主回归通过，覆盖与未验证范围见[验收记录](../acceptance/text-expressions.zh.md)。本规格从早期标识符与数据引用讨论中独立整理，是本功能后续实施及验收的依据；早期讨论中的 JSONPath、自定义定界符及库比较不属于本规格。标识符后续需求由[标识符字符规则与定义名称](./identifiers-and-data-references.zh.md)维护。

## 已确认的范围与契约

- 使用 Nunjucks 默认文本语法 `{{ ... }}` 与普通上下文变量访问，不增加 `$` 根变量或自定义定界符。
- Agent `prompt`、Bash `command` 的文本插值与边 `if` / `for` 共用库的解析、求值能力，不另写条件表达式解释器。
- 语法和求值沿用 Nunjucks，不另行维护同用途语言。通用语法说明直接链接 [Nunjucks 官方文档](https://mozilla.github.io/nunjucks/templating.html)，项目文档仅说明上下文、业务结果契约、环境配置及实际支持边界。
- 边的上下文来自该边上游的有效输出，节点文本的上下文来自自身合并输入；不先把工作流定义当模板生成或重写。
- `if` 消费原生 boolean；字符串 `"false"` 等其他类型不能作为条件结果。
- `for` 保留对象数组及 `key` 业务契约；文本循环不等于创建工作流节点实例。
- 静态检查语法、实际支持范围和能确定的 Schema 引用，运行时严格检查表达式结果；不另建完整表达式类型推导系统。动态访问或计算结果的结构无法静态确定时，允许执行，不仅为静态证明而裁剪库表达式。
- 能确定来源数组元素声明的 `for` 继续进行原有逐项输入声明检查；无法确定时，相应的类型与合并冲突检查留至运行时，不能宣称编译时已证明全部输入来源。原有输入允许缺失的规则保持，不把运行时类型检查解释为要求所有输入字段必填。
- 缺失值在表达式内部遵循库语义，包括存在性测试、默认值与短路。只检查最终业务结果：直接以缺失值作为 `if` 或 `for` 结果会因结果契约失败；表达式可以显式产生合法布尔值或默认数组。文本缺失值按库规则输出为空文本。
- 文本输出沿用库规则，不再自动将对象和数组转换为 JSON；需要 JSON 时显式使用内置 `dump` filter。关闭 HTML 自动转义，Bash 在表达式文本结果之外自动进行参数编码。显式编码 filter 自身的语义仍由库解释。
- 提供字段内模板、库内置 filter、test 和全局函数；不配置外部模板加载器或自定义扩展。外部模板文件加载的搜索目录和生命周期不属于本次范围。
- Bash 插值继续是独立、未额外加引号的数据参数，由系统自动进行 Shell 参数编码；不允许插值生成命令名或命令片段，不通过模板控制结构生成 Shell 命令骨架。
- 依赖协调、跳过传播、实例展开、输出聚合及提交回滚继续由 DAG 引擎负责。
- 不要求兼容旧格式；实施时同步项目模板及相关文档、示例，不增加旧格式兼容分支。
- 当时的表达式统一变更未决定或收紧定义 ID、节点 kind、插件契约名称、业务字段名及 `for.key` 的字符规则；后续已实施的现行规则由[标识符字符规则与定义名称](./identifiers-and-data-references.zh.md)维护。

静态保证与库能力之间的取舍见 [ADR 0008](../adrs/0008-library-expressions-and-runtime-contracts.md)。

## 消费位置与表达式边界

| 位置 | 写法 | 业务数据上下文 | 最终结果 |
| --- | --- | --- | --- |
| 边 `if` | 不带模板定界符的单个表达式 | 该边上游有效输出；实例组使用聚合输出 | 原生 boolean |
| 边 `for` | 不带模板定界符的单个表达式 | 同上 | 带合法 `key` 的对象数组 |
| Agent `prompt` | Nunjucks 文本模板 | 当前节点合并后的输入 | 文本 |
| Bash `command` | 文本中的表达式插值，受独立参数位置约束 | 当前节点合并后的输入 | 参数自动编码后的命令文本 |

工作流定义不先作为文本模板生成或重写；不通过节点 ID 隐式读取其他节点数据。普通变量与属性访问遵循库，不增加特殊根访问语法。

Agent 文本可使用库的条件、文本循环、局部变量、宏、raw 和注释等字段内能力；Bash 仍受已确认的消费限制。边表达式取得原生值，不通过渲染字符串后再做 JSON 解析或真值转换模拟类型。比较等内部运算遵循库，不保留旧自定义 `==` / `!=` 的特殊严格比较实现；严格比较使用库提供的对应运算符。

`for` 的每项仍须为对象，显式提供符合[现行标识符规则](./identifiers-and-data-references.zh.md)的字符串 `key` 且同次展开内唯一；移除 `key` 后其余字段参与输入合并。显式空数组按原规则跳过目标，不改变零项时的输出语义。

## 静态检查与运行时检查

执行前检查全部定义中能够确定的 Schema 引用、类型、来源覆盖与声明冲突，包括本次不会执行的分支。模板局部变量、宏参数、循环变量和库内置名称应与业务字段正确区分。

固定业务属性路径能够从 Schema 确定时，仍须有对应声明；运行数据中的额外字段不能使静态非法引用变成合法。动态访问或计算结果无法确定时，允许执行，并明确相应静态保证的限制；未知部分不能使其他已知的非法引用或冲突免于检查。

运行时严格检查最终结果、逐项身份、实际输入类型及合并冲突。输入允许缺失的规则保持；推迟未知来源检查不表示新增所有输入必填规则，也不保证运行时会拒绝每种缺少潜在来源的情况。已有声明字段的错误类型仍须按原有 Schema 校验拒绝，不能通过默认值行为掩盖。

## 文本与 Bash 编码

文本字段始终产生文本，即使只有一个插值也不切换为原生对象或数组。数据插入后不再次作为模板执行；字面模板标记使用库的 raw 等标准写法，不增加项目专用转义定界符。Agent 渲染结果继续用于原有业务启动流程，包括台前已有的空白提示词处理。

Bash 每个插值先按库规则得到文本，再自动进行 Shell 参数编码，不要求作者添加 `shellarg`，也不对整段命令编码。显式文本 filter 不能绕过参数编码。

继续拒绝将插值放在命令名、参数拼接、引号、注释、命令替换、heredoc 等现有禁止位置。插值边界须与库解析一致，不能把属性名或字符串字面量内的 `}}` 误识别为结束位置。

环境关闭 HTML 自动转义，不配置外部模板加载器、文件系统搜索目录、异步扩展或自定义扩展；不承诺外部模板文件的加载生命周期。使用库语法不表示项目自动提供 `include`、`import`、`extends` 所需的外部文件。环境配置依据见 [Nunjucks API](https://mozilla.github.io/nunjucks/api.html)。

## 执行、错误与恢复

上游被跳过时不求值该边；`if` 为 false 时不求值同边 `for`。这些顺序不免除能够执行的静态检查。

语法与可确定引用的错误在模板校验或 DAG 编译阶段报告。运行时求值与结果契约错误沿用现有边界：初始化失败不发布执行对象；提交失败整体回滚本次提交触发的内部变化，历史成功状态保持。节点文本渲染错误沿用所选节点的业务错误与重试流程。

错误应能定位节点或边及 `prompt`、`command`、`if`、`for` 字段，保留库提供的可用原因和位置；复杂计算结果不能伪装成一个确定的原始字段路径，能确定来源时再提供相应数据路径。

保留现有求值时机，不增加求值结果缓存、随机种子或跨重试的相同结果保证：

- 已成功保存的 DAG 边状态、展开项和实例输入输出在普通恢复时直接还原，不重新求值已保存决策。
- 提交回滚后重提，以及节点成功结果已保存但 DAG 状态尚未保存时的恢复重提，会再次求值尚未提交的边。
- Agent/Bash 新的业务执行尝试会重新渲染文本；已有成功结果只重提 DAG 时，不重复已确认的外部业务。
- 库内置 `random` 等非确定性能力可在重新求值时产生不同分支、展开集合、提示词或命令参数；已保存的决策仍按上述契约恢复。

## 用法示例

以下是独立字段片段，不是完整模板，也不表示这些字段可以放在同一种实体上：

```yaml
if: 'review.approved and review.score >= 80'
for: 'review.jobs'
prompt: |
  请处理 {{ review.summary }}
  {% if review.notes is defined %}
  补充说明：{{ review.notes }}
  {% endif %}
command: "printf '%s' {{ review | dump }}"
```

边从该边上游读取 `review`，节点文本从自身输入读取 `review`；相关声明与来源仍须满足本规格的检查边界。`review.jobs` 每项必须包含合法 `key`。

## 验收预期

以下定义验收预期；实际覆盖、结果和未验证范围见[验收记录](../acceptance/text-expressions.zh.md)：

| 场景 | 预期 |
| --- | --- |
| 同一属性在边与节点中读取 | 使用相同库语法，各自从上游输出与节点输入取值 |
| 比较、逻辑、算术、filter、test 与模板局部变量 | 求值遵循库；不恢复旧自定义比较语义，不把合法局部变量当作未声明业务字段 |
| `if` 分别返回 false、字符串 `"false"`、缺失值 | false 关闭边；字符串和缺失值违反 boolean 结果契约 |
| 缺失值存在性检查或显式默认值 | 遵循库；最终满足消费位置的结果契约即可 |
| 合法空数组、非对象数组、非法或重复 `key` | 空数组按原规则跳过；其余拒绝；key 须符合[现行标识符规则](./identifiers-and-data-references.zh.md)且同次展开内唯一 |
| 可静态确定的未声明引用或类型冲突 | 编译时拒绝，包括不会执行的分支 |
| 动态引用、无法推导元素声明的计算数组 | 不因无法证明而拒绝；执行时检查实际类型和合并冲突，仍允许原规则中的输入缺失 |
| Agent 条件段落、文本循环、raw、注释 | 库处理文本模板；不生成额外工作流实例；插入的数据不二次当模板执行 |
| 对象、数组与显式 `dump`，以及 `<`、`&` 等字符 | 默认输出遵循库；`dump` 生成 JSON；无隐式 HTML 转义 |
| Bash 参数含空白、换行、引号及 Shell 元字符 | 仍是一个数据参数；缺失值是空参数；命令名、拼接及其他原有限制位置拒绝插值 |
| 上游跳过、if 为 false、求值失败 | 保留不求值的顺序和创建失败/提交回滚边界；不把文本条件当作边结果契约 |
| 普通重启恢复非确定性表达式的已保存决策 | 保持已保存分支、展开项和输入输出，不重新抽样 |
| 回滚重提、尚未提交的恢复重提及新业务尝试 | 重新求值或渲染，允许随机结果变化，不承诺与前次相同 |
| 已保存成功节点结果的 DAG 重提 | 不重复已确认的 Agent/Bash 业务执行 |
| 外部模板加载 | 不提供文件系统搜索路径或隐式加载目录；不宣称支持外部模板文件的加载生命周期 |
| 项目模板及独立引擎入口 | 模板和示例迁移完成，公共文本能力、节点调用与独立 DAG 产物均可使用 |

实施需覆盖公共文本能力、DAG 表达式与编译/运行集成，以及 Agent/Bash 调用、模板迁移与恢复回归；UI 功能若发生改变，按仓库约定增加真实宿主 E2E。文档验证与库独立试验均不能替代这些项目验证。
