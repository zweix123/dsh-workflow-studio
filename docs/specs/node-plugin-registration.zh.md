# 节点插件化注册与实例 UI 标准化

状态：第一阶段节点侧实现及自动化验证已完成（2026-10-04）；固定 rc.1 的内置/第三方节点、导航、前端降级与错误隔离、语言主题及窄屏场景已通过；真实模型回复未验证，模板通用分发及联合装配待第二阶段。完整结果及未验证项见[验收记录](../acceptance/node-plugin-registration.zh.md)，不能据此视为整个规格已全部验收。

## Problem Statement

模板作者希望在自己的工作流模板中使用自己实现的节点类型，例如调用专有系统、展示业务数据或收集特定输入。当前内置节点虽已按包组织，但 Studio 在服务端和浏览器端静态装配已知节点。第三方作者无法仅通过普通 dsh 插件向 Studio 提供新的节点能力，还需要修改 Studio 的装配代码。

仅开放执行函数不足以支撑这类模板。节点还可能需要自己的卡片业务摘要、详情交互、按钮、多语言以及宿主集成。如果这些能力没有公共边界，第三方作者必须依赖 Studio 内部实现，内置节点也会继续依赖特殊装配方式。

工作流实例保存的是定义快照和执行数据，不包含节点可执行代码。节点插件发生冲突、卸载或升级时，必须明确已有实例还能做什么，以及如何处理已经开始的执行调用。可选浏览器能力缺失则应自然减少可用界面，避免引入一套额外的节点插件加载与恢复系统。

## Solution

提供独立的节点登记与公共契约包。节点作者通过普通 dsh 插件登记节点类型，模板通过 `node_kind` 引用该类型；同一节点类型可以被多个模板复用。内置 bash、session_agent 和 form 也使用这套公共机制。

Studio 负责工作流协调、事实保存和统一的实例界面。节点负责本类型的配置解释、业务执行、业务状态、可用操作及可选业务界面。Studio 渲染标准按钮，节点提供其业务含义；复杂交互由节点在规定的业务区域内实现。

仅服务端的节点也可以获得默认手动按钮。需要业务组件、前端处理函数或多语言时，节点增加轻量浏览器入口，并直接使用宿主已有能力。正常卸载等待在途执行调用保存完成；保存失败则明确报告并沿用宿主卸载，不将未保存结果视为已接受。类型缺失或冲突暂停相关实例的新执行。可选前端能力缺失就跳过对应功能，运行错误局部保护，插件加载和重试沿用宿主机制。

本议题规范实例节点能力和 UI；与[模板插件分发规格](./template-plugin-distribution.zh.md)共同约定节点依赖、默认 bundle 和已有实例的生命周期，不改变模板资源声明、标识和名称规则，也不扩展模板的只读展示。

## User Stories

1. 作为模板作者，我希望模板能够引用自己实现的节点类型，以便表达内置节点无法完成的业务。
2. 作为模板作者，我希望多个模板能够复用同一节点类型，以便独立维护模板编排和节点能力。
3. 作为节点插件作者，我希望通过普通 dsh 插件登记节点，以便用户安装并装配插件后即可使用，无须修改 Studio 的静态装配代码。
4. 作为节点插件作者，我希望使用独立的公共契约，以便实现节点时无需导入 Studio 的工作流、DAG 或存储内部模块。
5. 作为内置节点维护者，我希望内置节点和第三方节点遵循相同协议，以便公共能力能够覆盖真实的执行和交互需求。
6. 作为用户，我希望重复的节点类型标识明确显示冲突来源，以便排查安装问题，而不是因装配顺序意外使用某个实现。
7. 作为用户，我希望移除冲突贡献后剩余有效节点恢复可用，以便继续使用已经安装的正确实现。
8. 作为节点插件作者，我希望仅提供服务端实现和操作声明即可获得标准按钮，以便简单节点无需编写浏览器界面。
9. 作为用户，我希望尚未产生执行事实的就绪节点也能显示可用操作，以便开始第一次业务执行。
10. 作为节点插件作者，我希望自行决定是否自动启动、是否开放手动操作以及何时完成，以便保留本类型的业务控制权。
11. 作为节点插件作者，我希望自行解释和校验本类型配置，以便不同类型能够使用同名业务字段，且不改变公共编排字段的含义。
12. 作为节点插件作者，我希望自行解释可序列化业务状态，并由 Studio 保存，以便恢复业务时无需另行维护工作流存储。
13. 作为用户，我希望节点卡片的身份、状态、连接点和详情入口保持一致，以便在不同节点类型之间使用相同的基础交互。
14. 作为节点插件作者，我希望可选地提供卡片业务摘要，以便呈现本类型最有用的信息。
15. 作为用户，我希望卡片最多显示一个主要业务操作和固定详情入口，以便画布保持清晰。
16. 作为节点插件作者，我希望主要操作可以随节点状态变化，以便在卡片上提供当前最合适的业务动作。
17. 作为用户，我希望其他业务操作和复杂输入出现在详情区域，以便完成业务交互时仍能查看公共运行信息和定义快照。
18. 作为节点插件作者，我希望在业务扩展区域内组织完整交互，以便自定义界面不受固定字段列表或通用表单形态限制。
19. 作为节点插件作者，我希望标准按钮能够调用服务端动作、打开当前详情或调用自己的前端处理函数，以便统一呈现不同性质的操作。
20. 作为用户，我希望重复点击、无效参数和过期操作被正确处理，以便按钮展示不能绕过实际业务校验。
21. 作为表单节点用户，我希望填写的值经公共动作通道提交给节点校验，以便有效结果能够保存并交付下游。
22. 作为 bash 节点用户，我希望继续通过标准执行操作运行命令并在详情查看输出，以便节点插件化保持已有业务行为。
23. 作为会话 Agent 节点用户，我希望继续创建或打开原会话并按节点规则完成任务，以便宿主会话交互与工作流业务完成仍保持清晰区分。
24. 作为用户，我希望已完成或当前不可执行的历史节点仍可查看信息，并在前端能力可用时打开关联对象，以便业务执行权限不会阻止正常查看和导航。
25. 作为节点插件作者，我希望查询本类型已保存的节点事实及其工作流实例和节点实例身份，以便实现业务关联而无需访问可写存储。
26. 作为节点插件作者，我希望通过通用导航打开指定工作流实例和节点实例，以便为宿主中的业务入口提供准确返回位置。
27. 作为会话 Agent 节点维护者，我希望插件自行实现会话关联、查询路由和返回入口，以便公共节点协议无需包含其他节点用不到的会话字段。
28. 作为节点插件作者，我希望独立注册自己的词表和命名空间，以便文案直接跟随 dsh 的当前语言。
29. 作为节点插件作者，我希望浏览器入口可以只注册词表而不提供业务组件，以便简单节点也能支持多语言。
30. 作为仅服务端节点的作者，我希望可以提供固定文本，以便无需为基本操作增加浏览器入口。
31. 作为用户，我希望节点界面遵循宿主风格，并适应浅色、深色、中英文和窄屏，以便第三方节点与工坊保持一致体验。
32. 作为用户，我希望在同一实例页面正常关闭详情或切换节点时保留未提交草稿，以便往返查看信息不会丢失填写内容。
33. 作为用户，我希望插件前端卸载或重载导致临时草稿丢弃时获得明确提示，以便理解哪些内容需要重新填写，同时已保存业务数据继续保留。
34. 作为用户，我希望正常卸载或重载先停止新执行调用，并等待已经开始的调用完成保存，以便不会在执行中途撤走实现或遗漏结果。
35. 作为用户，我希望卸载等待针对正在进行的执行调用，以便处于业务等待状态的节点不要求整个工作流先完成。
36. 作为用户，我希望已有实例由当前安装的同类型实现解释和恢复，以便升级节点后继续使用保存的数据；不兼容时明确阻止执行并保留查看能力。
37. 作为用户，我希望任一必需节点类型缺失或冲突时整个实例暂停新的业务执行操作及新节点业务调用，在途调用仍按保存与提交规则收尾，以便能力不完整时不会开始新的业务执行。
38. 作为用户，我希望可选业务组件未注册时仍能查看通用信息并使用有效的服务端标准操作，以便前端扩展缺失不会额外阻断执行。
39. 作为用户，我希望没有对应前端处理函数的操作不显示，以便界面不会提供当前无法执行的入口。
40. 作为用户，我希望单个节点业务组件或前端操作报错只影响相应功能，以便仍能使用工坊其余内容并看到动作错误反馈。
41. 作为用户，我希望插件加载失败的提示与重试继续使用宿主已有机制，以便无需理解另一套节点加载和恢复流程。
42. 作为模板作者，我希望此次改动保留模板只读展示及既定分发约定，以便节点扩展可以与模板分发独立演进。

## Implementation Decisions

- **独立登记与契约包。** 节点登记能力与公共契约从 Studio 独立成包，供 Studio、内置节点和第三方节点共同使用。具体包名、接口名和字段拼写在实施中确定；契约不依赖工作流、DAG、存储或具体节点实现。此决定对应 ADR 0006，并调整 ADR 0003 中契约归属和安装单元的后续方向。
- **普通宿主插件装配。** 节点插件使用固定版本 dsh 的装配、依赖注入和生命周期机制，登记来源、节点类型与实现；卸载撤销其登记。Studio 从公共登记能力获取节点，不再静态导入内置节点业务实现。登记内容变化需要通知消费者，不能假设宿主会把服务内部条目的变化当作服务依赖变化。
- **默认装配。** 用户添加一个默认 bundle，即可装配 Studio、公共登记能力、session_agent/bash/form 三个内置节点，以及通过通用模板加载插件提供的六份内置模板。各部分仍使用普通宿主插件机制；第三方节点和模板可以独立提供，不要求用户逐一添加默认组件。
- **登记作用域。** 节点与模板一样按当前 profile 装配，同一 profile 的所有工作区共享节点类型；不同 profile 可以启用不同节点插件。同类型冲突在所属 profile 内判定，不增加工作区级节点配置，不改变实例存储已有作用域。
- **具体节点类型的依赖。** 依赖方必须能够表达具体节点类型当前可用，沿用宿主服务依赖的等待、装配和撤销机制，不以补丁排列顺序保证节点先于消费者加载。仅注入公共登记服务不代表某个类型已可用；登记能力负责将类型的有效性变化通知并适配给消费者。同类型全冲突规则继续有效，不能用宿主同名服务的先注册保留行为替代。
- **类型标识与冲突。** 模板使用 `node_kind` 选择节点类型。同一登记范围出现多个相同类型标识的贡献时，所有冲突贡献不可用，并显示各自来源；移除冲突后剩余有效贡献恢复可用，不采用先到先得或后者覆盖。
- **保持节点业务自治。** 沿用就绪、动作和恢复三类业务入口，以及节点自行解释配置、业务状态和完成结果的分工。节点可以声明并直接使用固定版本宿主公开服务。是否自动启动、是否向用户开放启动、完成或取消均由节点决定；取消不视为成功完成，也不以成功结果推进下游。
- **按类型校验配置。** 延续 ADR 0004：框架校验公共字段，节点校验自己声明的业务字段；不同类型允许同名业务字段，未知字段保留但不解释，节点不能覆盖公共身份、结构或输入输出语义。
- **业务事实与持久化。** 延续 ADR 0005：节点拥有可序列化业务状态并决定对前端提供的业务数据，Studio 解释公共执行阶段、错误和完成结果，协调事实保存与 DAG 结果提交。公共协议不持续增加会话标识、命令输出等具体节点字段。
- **独立的只读展示入口。** 根据节点定义、输入和可选执行事实列举业务展示数据及当前操作。首次就绪而没有事实时也可以调用；枚举操作不得调用有副作用的就绪或动作入口。现有仅接收事实的投影能力不能单独覆盖首次操作展示。
- **动作描述。** 简单操作声明包含稳定的动作标识、文案、可用性和点击目标，并区分卡片主要操作与详情中的其他操作。三类目标为服务端业务动作、打开当前节点详情、调用节点登记的前端处理函数。服务端描述可序列化，前端处理函数通过登记名称引用，不传输函数。
- **标准交互与校验。** Studio 统一渲染简单按钮并处理请求中的状态、防重及公共错误反馈。框架和节点共同约束业务执行是否可用，服务端重新校验动作及参数。查看和导航与执行权限分开，不能因节点已完成或历史数据不能继续执行而一律禁用前端导航。复杂业务组件通过公共动作通道提交参数，不新增通用表单生成器。
- **卡片边界。** Studio 拥有卡片外框、连接点、节点身份、公共状态和固定详情入口；节点可以提供业务摘要并声明最多一个主要业务操作，主要操作可随状态变化。节点不能替换整张卡片来绕过这些公共规则。
- **详情边界。** Studio 拥有详情容器、关闭与尺寸调整、公共运行信息及定义快照。节点在业务区域提供内容、操作和完整交互，不将其限制为固定字段清单。此次只规范实例 UI，模板继续使用已有静态图和通用只读定义展示。
- **内置节点迁移。** bash 的主要操作为服务端执行，详情展示命令、输出和错误。session_agent 的主要操作为服务端启动，详情提供业务完成动作及打开原会话的前端行为。form 的主要操作打开详情，其业务组件管理表单、校验和草稿，经公共动作入口提交值及重试已完成结果的交付。公共协议保留这些既有业务语义，不统一强加开始、完成或取消按钮。
- **当前业务基线。** 输入输出遵循[节点输入输出规格](./node-input-output.zh.md)：工坊不生成占位根输入，bash 按声明交付完整 JSON，session_agent 不声明业务输出且完成时提交空对象，form 交付有效正式提交。会话默认提示词、准确返回实例、Tab 与视角保留及迟到请求保护继续遵循[会话导航规格](./session-agent-instance-navigation.zh.md)。公共运行信息、完整定义路径、快照与草稿行为继续遵循[共享定义详情规格](./shared-definition-details.zh.md)，不能在迁移时退回旧规格的占位行为。
- **本次改造的数据边界。** 本次改造前创建的实例不要求继续执行，也不新增旧格式查看适配；不自动删除或改写这些实例文件。内置节点与源模板统一改造为符合新规范，保留当前业务语义。本文关于已有实例、实现升级及插件卸载后查看与恢复的承诺，适用于按新规范创建的实例，不将本次旧格式适配纳入范围。
- **正常卸载与重载。** 先停止接受新的执行调用，等待已开始的调用结束且结果保存后再完成卸载；保存失败按下一条处理，类型不可用期间的实例调度遵守下述整实例规则。已经开始的调用可以保存合法业务结果并提交 DAG；由此产生的新就绪节点仍等待，不得启动新的业务调用。等待对象是执行调用，不是所有处于业务等待状态的节点或整个工作流。必须实际协调任务、保存和插件清理的顺序，不能仅注销登记项后假设异步任务已经结束。强制进程结束仍走恢复流程。
- **卸载期间保存失败。** 结果保存失败时明确报告错误，允许宿主完成卸载，不增加阻塞卸载或保存重试系统。未可靠保存的结果不能视为已接受或成功提交，也不能据此推进下游；恢复依据实际持久化事实处理，无法确定结果的业务保持未知且不自动重跑。已经保存的业务成功事实不因后续 DAG 状态保存失败而被抹去，仍按既有结果提交恢复规则处理。
- **已有实例与实现升级。** 实例保留定义快照和事实，使用当前安装的同类型实现，不保存可执行代码或并行运行历史实现。当前节点负责校验旧定义及业务状态；无法解释时明确阻止继续运行并保留查看能力。
- **类型缺失或冲突。** 所需节点类型取自实例完整定义快照中的全部普通节点，包括已完成节点、条件分支及尚未展开的定义，不按剩余任务或当前可执行前沿缩减。任一所需节点类型缺失或冲突时，整个实例暂不可接受新的业务执行操作，也不调度新的节点业务调用，仍保留查看能力；在途调用按卸载与保存约定收尾，可以保存结果并提交 DAG。可选浏览器能力缺失不按这一规则暂停实例。
- **依赖恢复后的调度。** 所需节点类型重新可用后，先校验实例定义及保存的业务状态；校验通过则自动解除执行暂停，按各节点原有自动或手动规则继续，不增加统一的“继续实例”操作。手动节点仍等待用户，失败或结果未知的业务不因此自动重跑，已接受的成功结果不重复执行其业务。
- **临时草稿。** 正常同页关闭详情或切换节点继续保留草稿。节点插件前端卸载或重新装配时丢弃未提交临时草稿并明确提示；已保存业务数据保留。不新增服务端草稿保存或跨页面同步。
- **通用查询与导航。** Studio 实现并公开只读的本类型已保存节点记录查询，返回节点事实、工作流实例身份及节点实例身份，不暴露可写存储；前端提供按这两个实例身份打开和定位的导航。重复定义、逐项展开和递归调用不能以定义标识代替节点实例身份。
- **会话集成归节点。** session_agent 自行解释会话业务事实、提供关联查询路由并注册宿主返回入口，通过通用事实查询和导航完成集成。公共节点协议不增加会话专属关联字段，不另建重复的会话到实例映射存储，其他节点无需实现会话关联。
- **多语言。** 节点拥有自己的词表和命名空间，通过轻量浏览器入口直接向宿主 locale 服务注册并按生命周期清理。Studio 根据节点声明的词条引用使用宿主翻译能力。纯服务端节点可以使用固定文本；浏览器入口可以只注册词表，不要求提供业务组件。内置节点遵循同一方式，Studio 不提供词表转发或代注册机制。
- **可选前端能力缺失。** Studio 能正常运行时，按实际登记能力显示界面：没有业务组件就只显示通用信息，没有前端处理函数就不显示对应操作，有效的服务端标准操作照常可用。不以其他动作替代缺失的前端行为；依赖自定义 UI 输入的操作需等待该 UI 可用后才能提交。
- **前后端贡献对应。** 复用宿主的包身份、声明来源及浏览器入口生命周期，建立节点实现与其可选浏览器能力的对应关系，不能仅凭相同 `node_kind` 混用不同来源的实现与界面。不另建浏览器插件加载器，也不把宿主包级装配误认为节点贡献的前后端原子切换；过期动作仍由服务端复核，缺失与错误按既定回退处理。
- **局部错误保护。** 节点业务组件使用局部错误边界隔离渲染异常，避免整个工坊消失；点击处理函数抛错或异步失败由公共动作调用入口反馈，不能依赖渲染错误边界捕获。插件入口加载失败、错误展示及重试沿用宿主机制，不增加节点级加载状态或重试系统。
- **宿主启动边界。** 固定版本宿主的首次启动可能因客户端入口失败而无法展示页面，这类启动失败仍由宿主处理；按登记能力回退的前提是 Studio 已能运行，不承诺绕过宿主的启动检查。
- **版本与外观。** 固定适配 dsh 0.2.0-rc.1，复用宿主公开服务、已有组件、主题和尺寸约定；实例节点 UI 兼顾浅色、深色、中英文和窄屏。用户继续自行安装本机 dsh，插件通过本地目录装配。

## Testing Decisions

- **测试边界已由用户确认。** 以现有宿主插件装配、工作流实例 HTTP 接口和真实临时存储的集成测试为主要边界，复用现有工坊页面交互测试验证用户可见行为，并在实现后进行固定 dsh 版本的真实浏览器验收。优先扩展已有入口，不为私有登记表、内部状态机或函数增加测试接口。
- **好测试验证外部行为。** 通过安装或卸载插件、创建实例、发起操作、读取结果、重启恢复以及点击页面来断言结果。不测试内部 Map 结构、私有调用顺序、组件拆分方式或类型定义的复述；生命周期顺序以新调用是否被拒绝、在途结果能否持久化、卸载何时结束等可观察行为验证。
- **复用既有先例。** 项目已有构建后宿主插件装配与卸载测试、真实 HTTP 和临时存储的实例测试、第三方节点替身的动作与取消测试、恢复与兼容性测试，以及工坊卡片、表单草稿、导航和语言切换的页面交互测试。构建产物测试已验证宿主模块装配、宿主 React 使用、词表注册及清理；扩展这些先例验证独立节点插件的装配，而不是另起测试框架。
- **外部节点完整链路。** 使用遵守公共协议的测试节点插件，经宿主装配后由模板引用；验证创建实例、首次无事实时的操作声明、执行请求、结果保存和下游推进。至少覆盖纯服务端插件及带可选浏览器能力的插件，确保接入不需要修改 Studio 的内置节点清单。
- **默认 bundle。** 在干净的隔离 profile 中仅添加默认 bundle，验证工坊、公共登记能力、三个内置节点和六份内置模板均通过公共装配机制可用；不要求逐一添加默认组件，第三方贡献仍可独立接入。
- **profile 范围。** 验证同一 profile 的多个工作区共享节点类型；不同 profile 的启用与冲突判定不相互串用。不把这项验证当作实例存储已经按 profile 隔离的证明。
- **业务边界回归。** 验证节点自行校验配置和业务参数、同名配置字段按类型解释、未知字段保留、自动和手动行为由节点决定，以及取消不提交成功结果。操作枚举和通用查看不得触发业务执行；过期、重复和非法动作仍被正确拒绝。
- **冲突与恢复。** 装配两个同类型贡献后，验证所有冲突贡献不可用、来源可诊断、相关实例拒绝新执行且保留查看；移除冲突后剩余有效贡献恢复可用。另行验证类型卸载导致缺失时，整实例的新操作和调度受到同样约束；缺失类型只出现在已完成节点、未激活条件分支或尚未展开的定义中时，也不能继续执行其他节点。
- **在途执行与卸载。** 让测试节点保持一个可控的未完成执行调用，然后卸载或重载：验证新调用先被拒绝、清理等待调用结束和保存完成、重新读取存储能看到结果。覆盖另一必需类型缺失时在途调用成功：其结果仍保存并提交 DAG，新产生的就绪节点不开始业务调用。另设只有业务等待事实而没有正在执行调用的实例，验证卸载不等待整个工作流完成。
- **保存故障。** 注入在途业务结果保存失败，验证有明确错误、宿主可以完成卸载、未保存结果不发布为成功且不推进下游；重新打开真实存储后依据已保存事实恢复，不自动重跑结果未知的业务。另行覆盖业务结果已保存而 DAG 状态保存失败，不能丢失已接受结果或重做业务。
- **依赖恢复。** 在所需类型重新可用且定义与业务状态校验通过后，验证实例无需统一继续操作即可恢复原有调度；自动节点继续、手动节点等待，失败和结果未知的业务不自动重跑，已接受成功结果不重复执行业务。校验不通过时仍禁止新执行并保留查看。
- **升级与重启。** 使用持久化数据重新装配当前同类型实现，验证可兼容数据由当前实现恢复，无法解释的定义或业务状态明确阻止执行但保留读取。恢复过程中不得盲目重复已完成或执行结果不确定的外部业务。
- **公共卡片与详情交互。** 从工坊或实例页面操作，验证公共外框和详情信息、最多一个主要业务按钮、状态变化后的操作、三类点击目标及其他操作的详情归属。复杂表单通过公共动作通道提交；已完成节点的查看和可用前端导航不受业务执行限制误伤。
- **内置节点行为。** 验证 bash 的执行和输出、session_agent 的原会话访问和业务完成、form 的输入提交和结果交付重试，均通过同一登记及 UI 协议工作；保持模板静态只读展示。
- **查询与业务导航。** 通过公开查询验证仅返回本类型已保存事实及正确的实例身份，返回数据不能成为修改底层存储的入口；覆盖同定义多次调用和逐项展开的不同节点实例。验证 session_agent 自行完成会话返回入口，并精确打开目标实例和节点详情。
- **草稿生命周期。** 验证正常同页关闭和切换详情保留草稿，节点前端卸载或重载清除临时草稿并提示，已保存事实保持不变。
- **多语言与轻量入口。** 验证纯服务端固定文案、仅注册词表的浏览器入口、宿主语言切换后的标准按钮文案，以及词表随插件清理。节点词表独立于 Studio 的词表维护。
- **前端降级与异常。** 在 Studio 可运行的前提下撤销可选组件或处理函数，验证通用信息及有效服务端操作保留，缺失处理函数的操作不显示，实例不因可选前端能力缺失而暂停。使业务组件渲染报错，验证工坊其余区域仍可用；使前端处理函数同步抛错或异步失败，验证公共动作反馈。宿主启动失败只确认其责任边界，不建设替代启动和重试机制。
- **贡献对应。** 覆盖同类型不同来源的冲突及撤销，以及浏览器入口迟到或重载；不得将一个来源的界面或处理函数配给另一来源的服务端实现，过期业务请求不能绕过当前实现的动作校验。
- **真实宿主验收。** 实现涉及 UI，按项目既有浏览器验收流程，在固定 dsh 0.2.0-rc.1、隔离数据目录和非默认端口中使用 Codex 内置浏览器，验收内置与第三方节点、语言与主题、窄屏、导航及可选前端能力缺失的实际行为。模拟宿主、HTTP 或 jsdom 测试不替代真实宿主验收；未运行或受阻的步骤明确标注未验证，不安装或升级 dsh CLI。

## Out of Scope

- 改写此前的模板插件分发方案、模板标识和名称约定，或新增模板画布及详情的业务 UI 扩展。
- 保存节点可执行代码快照、同时运行同类型的多个历史实现，或自动迁移任意旧业务状态。
- 适配本次改造前创建的实例，包括继续执行和旧格式专用查看；此范围排除不授权自动删除或改写旧实例文件。
- 强制所有节点具有相同的开始、完成或取消操作，或因本次协议调整为内置节点新增取消功能。
- 通用表单生成器、限制所有业务交互的固定字段清单，以及节点替换整张公共卡片或详情容器的能力。
- 将会话关联字段纳入公共节点协议，或维护重复的会话到实例映射存储。
- Studio 代理传输或注册节点词表，或建设独立于宿主的节点加载、错误重试和启动恢复系统。
- 服务端草稿保存、跨页面草稿同步，以及插件重载后的未提交草稿恢复。
- 自动安装缺失的节点插件、插件市场、npm 发布流水线、dsh CLI 的内置安装或版本升级。
- 工作区级节点装配、独立于宿主的卸载阻塞与保存重试系统。
- 修改公共 DAG 编排语义，或将节点模块与工作流、DAG 和存储内部实现耦合。

- 实施：公共节点契约与登记、类型依赖/冲突/卸载收尾、Studio 公共 UI、内置节点迁移、第三方示例及默认 bundle 的节点部分已落实。接口见[作者指南](../node-plugin-authoring.zh.md)。
