# 实例运行图阅读与操作体验

状态：已选定紧凑横向方案并实施（2026-09-25）。原型比较结论：A 保留一致的依赖阅读方向，配合 100% 首次视角、主动定位和短标记；B 的并行宽度及 C 的复杂分支折返代价不适合本期运行图。

## 交互原型

在原型分支运行 `npm run prototype`，访问 `http://127.0.0.1:3091/?variant=A`。A 为紧凑横向，B 为纵向，C 为按依赖层折行；底部切换条或焦点不在表单/按钮内时的左右方向键切换方案。URL 的 `variant`、`scene`、`lang`、`theme` 保留比较条件，执行进度只保存在内存。切换布局保留进度，切换样例或重置会清空模拟状态。

原型复用工坊页面组件及 React Flow / Dagre，独立预览外壳模拟宿主侧栏并提供主题变量；未依赖本机 dsh 服务。测试样例使用内置模板节点名称及人工构造的分支、逐项和嵌套图，不读取或修改真实实例；所有条件只展示不求值。模拟推进只用于比较图的状态和导航，不是 DAG 引擎的运行语义实现。C 目前固定每三个依赖层折行，`if`、`for`、分叉与汇合不参与折返点的选择；复杂图只能用来发现这种固定折行的风险，不能把 C 的自动排布当成候选最终算法。

试用重点：首次能否读清并操作节点，多个并行项能否区分并定位，条件全文是否易于查看，展开详情和推进时是否迷失位置，以及全图与阅读比例切换是否方便。折行方案固定每行三个依赖层，复杂分组可能使其比横向更宽；这是待评价的限制，不预先视为最终方案。

比较原型作为决策的原始材料保存在独立分支 `codex/prototype-instance-graph-2026-09-25`（`2203fc1`）；它回答“哪种布局便于持续阅读和操作运行图”。正式画布使用实例快照，不提供方案切换入口。原型仅用于比较布局，正式验收以 `DagCanvas` 为对象。

## 已确认目标与范围

- 优先让用户看清节点名称与状态、方便操作当前步骤；长流程允许超出一屏，保留查看全图的入口。
- 本期一起优化节点间距、默认缩放与定位、节点信息层次，以及必要的画布导航。
- 视觉风格沿用 dsh 宿主，兼顾浅色/深色、中英文和窄屏。
- 本期固定紧凑横向：依赖从左到右，逐项和分支纵向展开；不提供纵向模式、排布字段或切换控件。
- 条件和逐项表达式使用简短标记；点击或键盘聚焦时可查看完整表达式，长表达式不再统一撑开该层所有边。
- 执行推进时保持用户正在查看的视角，通过主动定位入口访问屏幕外的待处理节点，不自动跟随后台执行。

## 实施前问题与依据

当前前端采用 React Flow 与 Dagre。`build-canvas-graph.ts` 按同一 DAG 层的最长边标签计算统一横向间距，因此一条长条件表达式会拉长该层所有无标签边。首次打开使用全图适配，节点的名称、状态和按钮一起缩小。

以包内 `github-spec-kit-workflow` 模板初始平铺结构为例：10 个位置、9 条串行边，卡片尺寸为 184 × 96，最长标签让各层级间距达到 228，图宽约 3,892。若间距统一降至现有最小值 88，图宽约 2,632，减少约 32%，但仍无法保证在常见窗口里同时看清全部节点。这是按源码与内置模板计算的示例，不是对用户打开实例的运行快照测量。

间距还需容纳逐项实例的聚合出口，不能只按串行模板压缩。现聚合出口宽 60，距成员右边缘 8。

## 布局比较

| 候选 | 阅读与操作收益 | 需要验证的代价 |
| --- | --- | --- |
| 紧凑横向，初始显示可读的局部，另提供全图与待处理节点定位 | 保持依赖方向一致，适合分支与嵌套；局部节点可正常阅读和操作 | 长链仍需水平平移；仅缩间距不足以改善导航 |
| 纵向流程，分支向两侧展开 | 串行流程可沿竖直方向阅读，适合窄窗口 | 长链仍超出一屏；并行分支、逐项展开与嵌套可能形成宽图 |
| 串行流程按行折返 | 可利用二维空间，在一屏放下更多串行节点 | 换行处阅读方向与连线绕行需明确；拓扑展开后如何保持位置稳定 |

采用紧凑横向布局，配合可读的首次视角及主动导航。理由是依赖阅读方向统一，逐项展开和嵌套可以沿用同一空间语义，而可读性由初始缩放保障。纵向仍然面临长链超屏与并行宽图；折行对纯串行有收益，但会增加分支绕线及动态展开时的位置变化。此选择以通用运行图的持续操作为目标，不仅针对截图中的单条链。

## 正式交互方案

### 布局与节点

- 依赖从左到右排列，分支及同一位置的逐项实例纵向排列，嵌套 DAG 在同一画布内保留分组边界。
- 普通串行边以现有最小间距 88 为起点做视觉校验，标签长度不参与全层统一间距计算。聚合出口与分组边界必须获得足够空间，不能因缩短普通边而与下游重叠。
- 名称、状态和操作入口在正常比例下具有清晰层次，优先使用宿主字号、图标和交互尺寸；长名称可换行，仍过长时提供完整名称的可访问查看方式。节点尺寸与布局尺寸同步，避免文字或操作区溢出卡片。
- 缩放至全图概览时允许文字和按钮变小；提供一键恢复到 100% 阅读比例的入口。

### 首次打开与视角保留

- 首次打开以 100% 阅读比例显示。全图在该比例能放下时居中展示；放不下时定位一个需关注的普通节点，同时尽量保留它的上下游，不能为了包含所有邻居而自动缩小到不可读。
- 建议首次定位优先级：执行存在错误或结果不明的未完成节点 → 待人工处理的节点（已建立对话但未完成，或尚未启动的就绪节点）→ 运行中的节点。各类内部沿图的稳定阅读顺序选择，不假定存在唯一的“当前节点”，也不根据不存在的执行时间猜测“最近节点”。
- 没有这些对象时，从流程起点以可读比例展示；空图显示空状态。旧实例不可执行时仍可正常浏览已有图，导航不恢复其执行能力。
- 执行状态刷新、切换已打开 Tab、窗口尺寸变化及抽屉开关不触发自动全图适配或自动跟随。拓扑实际展开可以重新布局；本期不承诺所有节点的坐标永久固定，但单纯状态变化应保持几何稳定。
- 每个已打开实例保留自己的视角；关闭 Tab 后重开、刷新页面或重启宿主时按首次打开规则处理，本期不新增持久化视角偏好。

### 画布导航

- 保留平移、缩放操作，明确提供“查看全图”“缩放重置”及“聚焦当前”入口，使用宿主风格与中英文词表。
- “查看全图”由用户主动触发，适配全部节点及嵌套边界；“缩放重置”只恢复当前视野中心的 100% 阅读比例，不跳回流程起点。
- “聚焦当前”只有一个候选时直接定位并恢复 100% 比例；多个候选时展示可选择的轻量列表，包含名称、现有状态、必要的分组路径和逐项身份，以区别同名实例。异常、待人工处理及运行中的项均可通过该入口访问，排序遵循首次定位规则。没有候选时给出“无待处理节点”的反馈。
- 定位只改变画布视角，不启动节点、不提交结果，也不自动打开详情。详情抽屉打开时，主动定位尽量把目标放在未被遮挡的区域；抽屉开关本身不移动画布。
- 窄屏下导航仍可使用，不以自动折行或改变布局方向响应窗口大小，避免窗口变化重排整图。

### 条件与逐项标签

- 边有 `if` 时显示“条件”，有 `for` 时显示“逐项”，两者都有时均需可辨认；无表达式的边不添加标签。
- 点击或键盘聚焦标记可以查看完整的原始表达式，文本可换行和复制；同时具备两种表达式时分别标明类别。不把表达式解释成未得到业务确认的自然语言结论。
- 详情浮层可关闭、可使用 Escape 退出，键盘可操作；触屏不依赖悬停。关闭浮层不执行节点或改变视角。表达式变化时展示最新内容，标记随对应边消失时浮层关闭。
- 短标记及其点击区域不得覆盖节点按钮；保留边方向与既有边状态语义，状态区分不能仅依赖颜色。

## 验收建议

- 用截图对应的十节点串行模板验证：首次打开不需要先放大就能读清名称与状态、点击操作；普通边不再被远处的长条件标签统一拉长。全图与 100% 阅读比例可以往返切换。
- 用含长 `if/for` 表达式的图验证：短标记不遮挡卡片，鼠标、键盘和触屏均能查看全文；表达式长度不改变无关节点间距。
- 用分叉汇合、多个并行节点、逐项展开、聚合出口与嵌套 DAG 验证：节点、分组及聚合出口不重叠，关系不增删，不因优化布局改写执行事实。
- 用运行中、待人工处理、执行错误、结果不明、全部完成和空图验证首次定位及导航；并行节点可区分，同名逐项实例可分别定位。
- 在执行刷新、展开、Tab 切换、窗口缩放、抽屉开关与改宽时验证视角规则；纯状态变化不造成几何跳动。
- 在宽屏与窄屏、浅色与深色、中英文下做浏览器视觉及键盘验收；测试覆盖用户可观察的导航与标签行为，以及必要的几何不重叠约束，不固定整图每个节点的绝对坐标。
