# 标识符字符规则与定义名称

状态：2026-10-15 已实施；最终 npm run check 的 200 项测试通过；真实宿主新增 3 条及既有 39 条 E2E 按各 case 最后一次执行结果全部通过（含首轮失败选择器迁移后的定向复验）。详细实际结果见[验收记录](../acceptance/identifiers-and-data-references.zh.md)。本次按用户授权以本地规格为需求来源，不依赖 Issue tracker，不创建 Issue。

## Problem Statement

模板作者面对多套不一致的命名规则：根模板 ID 已限制为小写 ASCII，内部节点、嵌套 DAG 和显式边 ID 仅检查字符串；节点插件的 kind、动作 ID、handler 名称和逐项展开的 key 又各自处理。作者无法通过一套明确规则预判标识是否合法，错误可能直到登记、引用或实际展开时才暴露。

内部实体目前通常直接以 ID 展示。若统一使用小写 ASCII，现有中文 ID 承担的业务含义就会丢失；根模板已有的可读名称能力需要扩展到其他定义实体，并始终与身份引用分开。

业务字段名与身份标识也容易混淆。输入输出对象的字段名应遵循 JSON 对象规则；for 数组每项固定字段 key 的值则是逐项标识，需要明确的字符和唯一性约束。它不是引擎自动生成的运行实例 ID，也不会因为某个字段看起来像订单号就被自动推断出来。

## Solution

统一所有作者提供的定义及插件标识：模板根 ID、普通节点和嵌套 DAG ID、显式边 ID、node_kind、动作 ID、handler 名称，以及 for 每项 key 的值，均满足正则 `^[a-z0-9]+(?:[._-][a-z0-9]+)*$`。字符片段仅由小写 ASCII 字母或数字组成，片段间可使用单个点号、下划线或连字符。首字符可以是数字，不能使用空串、大写、中文、空白、首尾或连续分隔符。暂不增加长度上限，不自动裁剪或改写不合法的值。

例如 a、0、review_v2、review.zh、review-step 合法；中文名称、Review、_review、review_、review..zh、review-_task 和带空白的标识均不合法。匹配必须覆盖整个原始字符串，不能接受末尾换行等额外字符。各类标识继续按原字符串精确比较，并保持各自已有的唯一性范围。

根模板、普通节点、嵌套 DAG 和有显式 ID 的边均支持可选 name。提供时必须是非空、非纯空白字符串，允许中文和同名；省略时显示 id。根模板也由 name 必填改为可选。运行实例沿用定义名称，身份、依赖、布局及操作仍通过原有 ID 定位；节点插件动作继续使用已有 label。

输入输出及嵌套对象的业务字段名与 JSON 对象的字符串键规则保持一致，不套用身份标识正则。现有 Nunjucks 语法、上下文和消费位置契约继续适用，不把字段名合法等同于一定能作为普通顶层变量直接引用。系统生成的实例 ID 保持现有不透明身份契约。

项目内模板、示例和夹具同步调整为合法 ID，并把原中文定义 ID 的业务含义保留到相应 name 中；不建立旧格式兼容分支。

## User Stories

1. 作为模板作者，我希望模板根 ID 有明确且一致的字符规则，以便能够在登记前检查自己的命名。
2. 作为模板作者，我希望普通节点 ID 与模板根 ID 使用相同规则，以便不必记忆不同字符集。
3. 作为模板作者，我希望嵌套 DAG ID 使用同一规则，以便深层定义仍能一致命名和引用。
4. 作为模板作者，我希望显式边 ID 使用同一规则，以便错误和详情中的边身份可以准确定位。
5. 作为模板作者，我希望边 ID 继续可以省略，以便不为了统一规则被迫给每条边命名。
6. 作为节点插件作者，我希望 node_kind 遵循同一字符规则，以便服务端与浏览器端使用一致的能力名称。
7. 作为节点插件作者，我希望动作 ID 遵循同一字符规则，以便声明与调用能精确对应。
8. 作为节点插件作者，我希望 handler 名称遵循同一字符规则，以便动作目标与处理入口能精确对应。
9. 作为模板作者，我希望点号、下划线和连字符都能作为单个分隔符，以便使用清晰的英文业务命名。
10. 作为模板作者，我希望数字可以出现在标识开头，以便无需额外遵循程序变量命名规则。
11. 作为模板作者，我希望不合法的大小写、中文、空白和分隔符得到明确错误，以便及时修正定义。
12. 作为模板作者，我希望系统不自动裁剪或转换我的 ID，以便声明、引用和诊断始终对应原值。
13. 作为模板作者，我希望暂不引入额外长度上限，以便无需迁就没有实际需求的限制。
14. 作为模板作者，我希望 from 和 to 继续引用定义 ID，以便名称相同或改名不会改变依赖关系。
15. 作为模板作者，我希望布局转折位置继续按定义 ID 定位，以便可读名称不会干扰排布。
16. 作为模板作者，我希望定义 ID 仍在整份定义中唯一，以便嵌套实体和显式边不会产生身份歧义。
17. 作为模板维护者，我希望同一 profile 中的模板 ID 冲突继续被明确报告，以便不存在先登记者覆盖后登记者的情况。
18. 作为节点插件作者，我希望能力名称沿用已有登记范围和冲突处理，以便此次字符规则变更不会重构插件装配语义。
19. 作为模板作者，我希望根模板的 name 可以省略并回退 ID，以便最小模板不必重复填写名称。
20. 作为模板作者，我希望普通节点可以提供中文 name，以便在使用 ASCII ID 时保留业务可读性。
21. 作为模板作者，我希望嵌套 DAG 可以提供 name，以便分组和递归定义具有清楚的业务名称。
22. 作为模板作者，我希望有显式 ID 的边可以提供 name，以便在查看该边时理解其业务用途。
23. 作为模板作者，我希望未提供 name 的实体直接显示 ID，以便名称能力保持可选。
24. 作为模板作者，我希望空串、纯空白及非字符串 name 被拒绝，以便不会出现无内容或错误类型的显示名称。
25. 作为模板作者，我希望不同实体可以同名，以便展示文案不必承担唯一身份的职责。
26. 作为工作流使用者，我希望同名实体仍可分别查看和操作，以便不会因为标签相同而操作错任务。
27. 作为工作流使用者，我希望模板预览和实例界面采用相应定义名称或 ID 回退，以便名称展示保持一致。
28. 作为工作流使用者，我希望实例沿用创建时定义快照中的名称，以便源模板后续改名不会悄悄改变已有运行。
29. 作为节点插件作者，我希望动作仍通过已有 label 提供文案，以便无需新增重复的动作命名机制。
30. 作为模板作者，我希望输入输出对象字段名遵循 JSON 规则，以便能够保留中文及带业务标点的字段。
31. 作为模板作者，我希望嵌套对象属性遵循同一 JSON 字符串键规则，以便不同层级的数据命名一致。
32. 作为模板作者，我希望字段名合法范围与表达式访问能力分别说明，以便不会把合法 JSON 字段误当作可直接书写的顶层变量。
33. 作为上游节点开发者，我希望明确由自己在展开数组每项中提供 key，以便不会依赖引擎自动推断业务编号。
34. 作为上游节点开发者，我希望 key 的值采用同一标识规则，以便在输出数据时就能避免非法逐项标识。
35. 作为工作流使用者，我希望中文、空白或其他非法 key 报错，以便不合法的展开数据不会被静默改写。
36. 作为工作流使用者，我希望同次展开中重复 key 被拒绝，以便不同项的逐项标识没有歧义。
37. 作为模板作者，我希望不同批次可以复用相同 key，以便逐项标识不被提升为全局身份。
38. 作为下游节点开发者，我希望展开时仍移除 key 后传递业务输入，以便原有输入合并契约保持稳定。
39. 作为工作流使用者，我希望非法展开结果沿用现有失败与提交回滚行为，以便不会留下部分创建的下游任务。
40. 作为工作流使用者，我希望任务顺序、聚合顺序和重启恢复仍遵循原有规则，以便名称与字符调整不会改变执行结果。
41. 作为调用方，我希望系统生成的运行实例 ID 继续是不透明身份，以便无需解析它或将业务 key 当作实例 ID。
42. 作为项目维护者，我希望内置模板、开发模板和受影响夹具统一迁移，以便当前项目资源能够直接通过新规则运行。
43. 作为项目维护者，我希望稳定的名称展示和同名定位场景保存为真实宿主 E2E，以便后续改动能够重复验收。
44. 作为项目维护者，我希望文档、作者指南和 Skill 入口与最终规则一致，以便用户读到的契约与实现对应。

## Implementation Decisions

- **校验归属。** DAG 编译入口负责定义实体的 ID 与通用名称校验；模板登记复用一致规则并承担模板身份冲突诊断；独立节点公共契约及登记、展示和调用边界负责 kind、动作 ID 和 handler 名称的合法性。校验应位于相应已有公共入口，避免只在 UI 某条路径拦截。
- **模块边界。** 公共节点契约和登记保持独立，节点插件不反向依赖 Studio 的工作流、DAG 或实例状态类型。复用现有模块能力，不为命名规则预建新包、通用框架或可配置命名策略。
- **完整匹配与精确身份。** 所有作者标识按上述规则完整匹配原值，不进行 trim、大小写转换或其他自动修复；字符串精确相等，暂不设额外长度上限。定义引用、登记查找及重复判断使用同一原始身份。
- **引用字段。** from、to 与布局 start_at 是既有定义身份的引用，继续按其原有引用范围与目标 ID 校验，不创建新身份，也不改为名称匹配。点号是普通标识字符，不获得路径层级语义。
- **唯一性边界。** 整份定义内所有显式 ID 保持唯一，包括根、嵌套实体和边。同一 profile 中的模板、节点能力延续既有冲突处理；动作与 handler 名称延续各自已有契约范围，不扩大为跨插件全局名称，也不在本次重构其唯一性机制。for 的 key 只要求在同次展开结果中唯一。
- **通用名称。** name 成为上述 DSL 定义实体的可选显示字段；缺省采用 ID，提供时必须是非空、非纯空白字符串。名称允许中文及重复，不接受错误类型，不套用身份字符规则。根模板名称由必填改为可选；无需迁移为另一套字段。原名称字符串保持作者提供的内容，不把合法名称自动裁剪成另一份值。
- **名称消费。** 模板列表、模板及实例中实体的现有标题与标签使用名称或 ID 回退；有显式 ID 的边在现有身份或详情展示位置采用对应名称，不因新增 name 建立新的边编辑或业务交互界面。查看定义仍能取得原 ID。插件动作文案继续使用 label。
- **显示与结构分开。** 图构建、连线、层级路径、布局查找、递归目标、节点请求和操作分派继续使用原有 ID、定义路径或实例身份。不能直接把原本同时充当图索引的显示标签替换成 name 后继续按标签查找。运行实例从其定义快照取得名称，不增加可独立编辑或持久化的实例名称副本。
- **业务字段。** 输入输出及嵌套对象的字段名接受 JSON 字符串键，不增加身份字符规则或额外保留名称限制。此决定只约束字段名，不扩大已有 Schema 支持类型或改变数据合并、安全复制和原型链处理契约。
- **表达式范围。** 文本插值与边表达式继续使用已实施的 Nunjucks 语法、上下文和结果契约。特殊名字在已有对象下可通过库的括号属性访问；合法顶层 JSON 字段不因此自动获得新的引用写法。本变更不新增根上下文变量、字段别名或另一套访问语言。
- **逐项标识。** 固定字段名 key 仍由上游在展开数组每项中显式提供，引擎不从其他字段推断，不自动填充值。仅收紧该字段值的字符规则；移除 key 后合并业务输入的规则不变。普通业务对象中的同名字段不因存在 for 而在所有位置被自动当作逐项身份。
- **错误与执行。** 定义错误在编译或模板判定阶段报告；动态 key 在实际读取展开结果时检查，保留条件关闭或上游跳过时不求值该边的既有语义。失败沿用现有初始化、提交错误与原子回滚边界，并定位相应实体、字段或数组项。字符校验不要求提前执行动态表达式。
- **实例身份与恢复。** 系统生成的工作流实例 ID 和 DAG 内实例 ID 保持原有生成、查询、持久化与恢复算法。key 是逐项标识及诊断元数据，不承担实例 ID 生成、数组重排重关联或增量计算职责。名称变化也不构成身份变化。
- **项目迁移。** 更新项目内置及开发模板、相关示例和测试夹具中的非法标识与所有引用；原中文节点、DAG 和命名边的业务含义转入相应 name。同步断言与文案，保留原业务链路和中英文体验，不引入旧格式兼容分支。
- **文档归属。** 实施时同步公共 DAG 规则、节点及模板作者指南、阅读导航和相关 Skill 文档入口；领域词汇表只维护定义标识与定义名称等术语，不复制字符正则和执行规则。本规格维护行为及预期，实际宿主结果在验收记录中单独保留。

## Testing Decisions

测试通过现有公开入口验证可观察行为，不为复用一个正则单独建立测试专用接口，也不以私有函数或内部模块布局作为验收对象。测试边界以已有的 DAG 公共 API、插件登记与宿主接口、真实宿主浏览器三类入口为主；沿用项目既有测试和隔离夹具，避免新增执行框架。

- **DAG 公共 API。** 沿用既有 DAG 引擎用例，通过编译、初始化、查询、提交及保存恢复验证节点、DAG、显式边的 ID 与 name。合法标识矩阵覆盖字母、数字开头和三种分隔符；非法矩阵覆盖中文、大写、空串、前后及内部空白、首尾和混合连续分隔符、换行、NUL、其他控制或不可见字符。尤其验证末尾换行不能被部分匹配接受。长度用明显较长的合法字符串验证未引入任意上限，不以资源耗尽作为验收方式。
- **名称矩阵。** 根模板、节点、嵌套 DAG 和有显式 ID 的边分别覆盖缺省、中文、重复名称；空串、纯空白、null 和其他非字符串显式值拒绝。同名而不同 ID 可以分别定位，异名而重复 ID 仍按原有规则拒绝。未命名边继续允许省略 ID，不新增命名要求。
- **逐项展开。** 沿用引擎的展开、逆序完成聚合及提交回滚用例，验证合法 key、中文及业务斜杠等非法 key、缺失和非字符串 key、同批重复以及不同批次复用。上游输出由普通节点或现有表达式计算产生时，实际消费的 key 均受相同规则约束；不因结果结构无法静态推导而漏掉运行时检查。条件关闭或上游跳过时保持不求值，显式空数组保持原语义。
- **回滚与恢复回归。** 提交产生非法 key 时，对比提交前后公开快照和前沿，确认没有部分创建的任务或已发布的半完成状态。合法展开部分完成后保存并恢复，验证实例身份、逐项信息、未完成任务、原始聚合顺序和定义名称均保持；不把重新计算 key 或业务重执行作为恢复前提。
- **模板与节点集成。** 沿用现有模板登记、节点插件登记及工作流实例集成测试，验证根模板可无 name、模板同名不冲突、同 ID 冲突仍不可用、节点 kind 与动作/handler 名称合法性，以及服务端与浏览器端消费一致。不为了测试建立新的全局动作注册系统。
- **数据契约回归。** 沿用输入输出、对象字段复制与文本表达式用例，验证中文、空串、点号、连字符和转义后的特殊字符业务字段名不受 ID 正则影响；已有自有属性安全复制、合并冲突和 Schema 检查仍成立。表达式只断言已实施的库访问能力，不能以任意顶层字段直接可引用作为新增预期。
- **真实宿主浏览器。** 沿用现有模板管理、DAG、布局和节点详情场景，以浏览器完成模板浏览、实例创建、实体查看和节点操作，断言中文 name、缺省 ID 回退、两个同名实体独立操作、有显式 ID 的边名称在现有展示位置可见、嵌套及递归名称和宿主重启后的定义快照行为。还需核对模板和实例的连线与布局引用未随显示名称改变。
- **UI 与运行约定。** 新增稳定场景保存为可重复 E2E，每条 case 自行准备数据并可单独运行，复用隔离的真实 dsh 宿主；包含与名称显示有关的中英文、浅深主题、窄屏及长名称检查。默认无界面、不录屏、不主动截图，不增加演示性固定等待。先运行对应新增 case，再运行受影响的既有 case；类型检查不能代替真实浏览器执行。
- **实施后验证。** 运行项目 check 与上述对应真实宿主用例。项目检查通过与真实宿主通过分别报告；失败、环境限制和未验证项按实际记录，不提前标记整体验收通过。实施与验证状态以页首及独立验收记录为准。

## Out of Scope

- 重做文本插值、选择其他表达式库、改变 Nunjucks 语法或引入特殊根变量、自动字段别名及另一套数据访问语言。
- 收紧业务 JSON 字段名、改变既有 Schema 类型、允许隐式类型转换或改变输入输出合并与安全访问契约。
- 自动从 order_id 等业务字段识别编号、自动生成或转换 for.key、取消现有逐项 key 要求、重排后按 key 重新关联任务、增量执行或重新计算已保存决策。
- 改变系统生成的实例 ID 格式、唯一性边界、任务提交协议、恢复算法及实例树结构。
- 更改既有标识的唯一性作用域、建立跨插件全局动作命名空间，或为此新增通用登记和配置框架。
- 强制给所有边补 ID、为无显式 ID 的边增加本期名称展示承诺、将边名称变成新操作入口，或为运行实例新增独立可编辑名称。
- 为旧标识建立兼容分支、旧快照迁移工具或旧数据自动改写流程；不据此删除或修改现有用户实例。
- 改变工作流调度、依赖激活、跳过、递归、展开数量、聚合顺序、节点业务完成及失败重试语义。
- 安装或升级 dsh CLI、升级固定宿主版本、建立插件发布分发流程，或将 references 目录纳入 Git。
