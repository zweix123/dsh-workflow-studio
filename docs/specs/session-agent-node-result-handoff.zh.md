# Agent 节点模式与结果交付提案

状态：已实施（2026-10-13）。业务交付与恢复的实际结果见[Agent 验收记录](../acceptance/agent-result-handoff.zh.md)，本轮卡片及记录入口复验见[节点操作位验收](../acceptance/node-action-positions.zh.md)。

后续界面调整见[节点操作位与输入界面](./node-action-positions.zh.md)：台前对话、台后记录及完成入口统一接入卡片操作位，详情只读，多条记录从节点插件的选择浮窗进入；该界面已实施，本文业务交付与恢复规则继续有效。

## 用户故事

作为工作流使用者，我希望 Agent 节点既能承载持续对话，也能在台后执行任务，并通过宿主结构化输出工具将符合 DAG 声明的结果交付下游；文件路径是其中一种结果，节点不局限于文件交付。

## 背景与现行基线

session_agent 节点对应普通的 dsh ReAct 对话。仅靠前置提示词，难以保证对话最终准确产出符合 DAG `output_schema` 的字段。虽然插件可以读取会话历史，但历史可能经历上下文压缩；完整记录也可能超过结果提取时的上下文容量。因此，不能把“提交时将全部聊天记录交给模型提取”作为可靠前提。

节点行为由各节点自行定义，Agent 节点可以围绕主体对话增加交付操作。已选方向是：交付子 Agent 使用结束时主对话的上下文，并按需读取相关产物，提取 DAG 要求的结构化结果；不强制主对话先生成专门的交付说明。结果通过校验后才交付 DAG，信息不足或提取失败时保留会话与未完成的节点，供用户补充或重试。上下文获取方式与容量限制仍需核实，不能承诺无限长的全部历史均可纳入，也不能缺少依据时猜测结果。

当前实现基线以[节点输入输出规格](./node-input-output.zh.md)为准：session_agent 拒绝非空 output_schema，用户手动完成时提交空对象，不生成占位业务字段。本次实现更新该基线，状态见文末。

## 已确认的设计边界（2026-10-13）

### 配置与范围

- 一个 Agent 节点覆盖台前、台后两种模式。区别在于是否关联用户可进入并持续交流的实际对话，而非仅指执行是否有人参与；底层子 Agent 拥有 Session 日志不等于台前对话。
- 类型采用 `node_kind: agent`，包名为 `dsh-workflow-node-agent`；`mode` 为 `foreground | background`，省略时默认 `foreground`。自动启动沿用 `is_auto_start`，默认 false。
- 本期不增加 `is_end_auto`、主对话的“结束任务”工具、节点停止或取消功能，也不建设自定义 trace 界面。
- 本次只调整内置模板，不建设旧配置或旧实例的兼容、迁移能力；这不授权删除既有数据。

### 台前与台后执行

- 台前保留现有结束操作的按钮文案（当前中文词条为“完成”），不因增加交付阶段而改名。有输出声明时，结束操作启动交付，结构化结果通过校验是节点业务完成的必要条件；业务完成与向 DAG 成功提交结果仍是两个事实。
- 台前交付子 Agent 只整理和核验结果，不补做业务任务或修改业务产物。材料缺失或核验失败时，保留原对话供用户补充或重试。
- 台前主对话生成期间禁用“完成”，当前轮次结束后才允许发起交付；服务端也须检查该条件，不能只依靠按钮状态。交付开始时固定本次对话依据，之后新增消息不混入本次交付；这不等于已经对工作区文件建立快照。
- 台后子 Agent 直接承担任务执行与结果交付。
- 台后按工作区复用一个不运行对话任务的父 Agent，为子 Agent 提供工作目录、权限等运行环境，不要求用户打开或操作父会话；不同工作区不共享父 Agent。各节点使用独立的子执行和记录。

### 结构化结果与人工完成

- 声明输出时，subagent 通过宿主原生 `structured_output` 工具提交结果，结构由 DAG 的 `output_schema` 约束，不另建一套节点输出格式，也不从普通文本回复猜测结果。节点将 DAG 声明转换为宿主 `outputSchema` 接受的 JSON Schema；最终捕获结果仍须通过公共输出校验。无法保持语义的声明不能静默降级。
- `structured_output` 由宿主依据 `outputSchema` 为子 Agent 提供，用户无须另行配置工具。子 Agent 按任务要求读取和核验产物，程序强制检查 DAG 输出结构；本期不增加通用文件路径校验规则或工作区文件快照。读取失败或材料不足时交付失败，不把结构合法等同于任务语义已经正确。
- 未声明输出或声明为空时，不需要结构化输出工具；台前跳过额外的交付子 Agent，台后仍需执行任务。不把“无输出”当作跳过任务或忽略失败。
- 当前实现只有自动启动字段 `is_auto_start`，默认 false，没有 `is_end_auto`。本期不新增自动结束配置或主对话的“结束任务”工具，采用人工完成流程。下游就绪后是否启动，由下游自己的启动配置控制。
- 台前由用户点击“完成”触发结果交付；结果校验成功后提交 DAG，无须第二次点击。无输出声明时跳过交付子 Agent，以空对象完成。
- 台后先执行任务、生成并保存合法结果，然后等待用户点击“完成”再提交 DAG；点击不重新执行任务。等待人工确认期间，已保存结果不能被恢复流程当作已获准提交而自动推进。
### 执行记录、失败与恢复

- 台后执行记录只供观看，不提供向执行中的 Agent 发送补充指令或持续交流的能力。
- 每次任务执行或结果交付尝试均保留记录入口和结果，重试不覆盖此前尝试。台前主对话与交付子 Agent 的记录分别关联。
- 后台父会话不出现在普通对话列表；节点列出历次尝试并直接打开对应的原生子会话记录。若固定 rc.1 宿主不能满足父会话隐藏要求，须明确反馈并重新讨论降级，不自行降低要求或增加自定义 trace 界面。
- 执行中断且未保存确定结果时，标记结果未知并保留已有记录，由用户决定是否重新执行，不自动重跑。已获准提交且成功结果已保存时，只重试向 DAG 提交该结果，不重新执行任务；台后待人工确认的结果在重启后继续等待确认。
- 普通失败不自动重试：台前保留原对话，用户可补充材料后再次点击“完成”，基于当次对话依据启动新的交付尝试；台后由用户手动重新执行任务，产生新的执行记录。成功且已获准提交的结果只重试 DAG 提交。

## 实施前技术验证

- 后台父会话在运行中、完成后及重启后均不进入普通对话列表，也不被宿主新聊天流程复用。不能把空白会话暂时不可见当作可靠隐藏。
- 后台父 Agent 的创建、复用和释放，以及工作区、权限、模型配置的继承；同工作区多节点并行时子执行仍独立，不相互覆盖。
- 原生子会话在运行中、完成后及重启后的记录入口和实际展示；不能把 Conversation 日志入口可用扩大为宿主所有 trace 调试功能均可用。
- 主对话压缩后的上下文继承、原子固定已结束轮次边界和长对话交付质量；能力不足时明确失败，不猜测或静默截断关键材料。
- DAG 声明到宿主 JSON Schema 子集的映射保持语义，以及有效结果保存、人工确认、DAG 提交之间的恢复边界。

这些是实现事实与验收问题，不是新增产品功能。若验证推翻已确认方案，应带具体证据反馈后再调整。

## 已有静态调查依据

### Trace 入口

对固定 rc.1 安装包的静态核实：`dsh-client-ui-workspace` 的公开 `UiWorkspace.openSession` 接受子会话地址；`dsh-api-session-controller` 的 `SessionAddress` 包含父、子 Session 标识与执行模式，`page`、`follow` 支持按此地址读取历史和跟随事件。纯 subagent 因而具备直接进入宿主 Conversation 查看记录的接口基础，无须先打开父对话。不能将此结论扩展为宿主所有 trace 或专用调试功能均已支持子会话。

完成后及重启后的读取需要持久日志和有效子会话身份信息；具体 UI 表现与记录完整性仍需真实宿主验证，历史可读也不代表一次性执行可以恢复。实现应保存完整子会话地址，不能把子会话 ID 当作普通会话地址使用。

### 台前上下文

已静态核实 `@deepseek-ai/dsh-subagent-fork-in-process@0.2.0-rc.1` 发布包：原生 fork 声明支持 `outputSchema`，使用同一结构化输出驱动；在启动时同步截取父会话截至最后一个 `turn/end` 的事件前缀。取得父 Agent 后，同步检查空闲状态并立即调用 fork，可固定调用当时的已结束轮次边界；不能先经过其他异步操作，再假定 fork 仍使用先前记录的边界。原生请求没有指定过去历史截点的参数。

子 Agent 继承该边界重建的有效上下文；压缩事件遮蔽的旧内容不会自动重新进入模型请求，因此不能将 fork 描述为让模型重读完整未压缩聊天。产物文件也不随 fork 固定，读取时可能已变化。下一次人工重试使用重试时的对话边界；当前证据仅证明接口和静态实现可行，尚未真实宿主验证长会话交付质量。

## 验收场景与预期

以下为验收目标，实际通过、失败与未验证范围见文末验收记录。UI 场景按项目约定沉淀为独立可重复的真实宿主 E2E。

| 场景 | 预期 |
| --- | --- |
| 内置模板和默认配置 | 使用 agent；缺省 mode 为台前，缺省 is_auto_start 不自动启动 |
| 台前有输出 | 持续原对话，点击“完成”启动交付；工具提交的合法结果保存后交付 DAG，不需二次确认 |
| 台前无输出 | 点击“完成”以空对象结束，不额外启动交付子 Agent |
| 主对话生成中结束 | 按钮不可用，直接提交完成请求也被拒绝；不截取未完成轮次 |
| 交付边界与压缩历史 | 子执行使用启动时已结束轮次重建的上下文，后续消息不混入；缺少材料时明确失败 |
| 台后有输出或无输出 | 执行任务并保存合法结果或空对象，等待人工完成；查看记录不能向子 Agent 继续发消息 |
| 输出缺失或不合法 | 不接受普通文本作为结构化交付，不补造业务字段，不推进下游 |
| 台前失败后补充重试 | 延续原对话，重新点击完成后使用新的上下文边界；两次交付记录均可查看 |
| 台后失败后重试 | 仅人工触发新的执行尝试，旧记录保留，不自动循环重试 |
| 台后待确认时重启 | 恢复已保存结果并继续等待确认，不自动执行或提交 |
| 已获准提交但 DAG 提交失败 | 只重试已保存结果，不重复业务执行或交付模型调用 |
| 执行中断且结果未知 | 保留可用记录，显示未知结果，不推断成功、不自动重跑 |
| 下游启动 | 本节点完成后按 DAG 依赖产生就绪状态，下游仅按自身启动配置执行 |
| 工作区隔离与 trace | 同工作区复用后台父 Agent，不同工作区隔离；父会话不出现在普通列表，历次子记录在运行中、完成后和重启后均有可用入口 |
