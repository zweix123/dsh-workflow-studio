## 详情视觉分区调整（2026-10-14 最终设计）

本节为本轮最终设计，下文已同步修订。实施与本轮验收已完成；详细结果及剩余覆盖限制见上述验收记录。

- 模板详情与实例详情采用统一的内容分板块规则，不为不同工作流模板单独定制详情页面。
- 配置字段原样展示：YAML 键保持原名，键的 i18n 留待后续研究；值使用配置本来的语言。不采用将配置键改为中文显示名的方案。
- 配置沿原直接字段顺序平铺，不额外按“标识与类型”“输入与输出声明”“其他配置”重排或增加分类标题。分板块指 UI 的视觉区分，不意味着强制增加标题层级。不按 `prompt`、`command` 等扩展字段名推断业务含义，也不将多个配置字段合并改写。仅对 DAG 隐藏其 `dag` 子项数组，子项继续通过画布查看。
- 实例保留与模板对应的配置内容和顺序，本期只在配置之后增加一个运行区域。插件详情与运行标识属于该运行区域的内部内容，不再与配置分别并列。
- 定义 `id` 来自模板配置；节点实例编号、所属 DAG 实例编号、实际输入输出、执行状态和逐项身份来自运行数据，不是模板配置字段。模板的嵌套关系也不等同于某次执行产生的父 DAG 实例身份。
- 执行详情优先通用展示；天然存在的节点类型差异复用已有只读 `ClientNode.Panel` 接口承载。Studio 为该区域提供“节点插件详情 · <kind>”标题、“以下内容由节点插件提供”的说明，以及独立边框和适配宿主主题的背景；插件只提供区域内部内容。
- 公共状态、实际输入和最终输出由 Studio 展示，插件提供尝试记录、待确认结果、stdout/stderr 等差异内容，尽量避免重复。此次使用已有执行记录，不新增所有节点统一的执行历史机制。
- 详情沿用只读边界；旧正文中涉及在详情内填写、提交或执行业务操作的描述已由[节点操作位与输入界面](./node-action-positions.zh.md)及 [ADR 0007](../adrs/0007-node-actions-and-readonly-details.md)取代。

- 模板直接平铺配置；实例在同样的配置之后，用留白、分隔线和轻微背景变化区分运行区域。运行字段同样平铺，不再嵌套“运行概况”“输入与输出”“运行标识”等分类标题。插件内容保留明确的来源标示和视觉边界。
- 本轮不新增折叠机制，不补出配置未写的默认字段，不截断或改写配置内容；优先解决重复层级、字段排版及内容来源区分。

## Problem Statement

模板与实例已共享定义正文，但实例运行区位于配置之前且嵌套多层分类标题，节点插件内容与配置、公共运行字段的来源难以区分。用户需要直接阅读原配置，并将其与实例创建快照和实际运行结果准确对应。

## Solution

模板与实例共享画布元素公共结构、定义引用和只读定义详情正文。实例继续按运行事实投影画布，在既有右侧抽屉中先平铺配置，再展示运行区域。定义详情从实例创建时保存的 `detail.definition` 快照读取；源模板修改或删除后，既有实例仍展示原配置。

## Implementation Decisions

- 模板与实例的画布节点、边明确使用共同的展示类型；公共部分包含定义引用和渲染所需字段，实例部分保留运行身份与状态。两种图的转换逻辑分别处理静态定义和运行展开，不用模板图反推执行事实，不新增后端接口、持久化格式或通用节点继承体系。
- 定义引用使用从根定义出发的完整路径；根 DAG 对应空路径。嵌套、递归与同名节点不能仅凭定义 ID 定位。`for` 的各项实例引用同一份定义，同时保持各自实例身份、运行状态、输入输出及业务面板。
- 普通节点、嵌套 DAG、根 DAG、等待和跳过位置均可查看定义详情。实例页面标题区域新增“根 DAG 详情”入口，选择当前根实例；已有卡片仍只有详情按钮打开抽屉。根入口与卡片共用抽屉及已保存宽度。
- 实例详情配置末尾的“运行信息”显示状态与可用的运行字段：节点实例或 DAG 实例（以 `定义 ID · 实例 ID` 展示）、所属 DAG 实例（同样结合父实例的定义 ID 与运行 ID）、状态、逐项身份、输入、输出。组合仅用于页面展示，底层身份及协议不变，不从组合文本解析身份；父实例快照缺失时仍展示已有父实例 ID。只展示对象实际具有的可选信息；根实例不显示所属 DAG 实例。等待与跳过位置没有实例 ID、逐项身份、输入或输出，运行区只显示所属 DAG 实例和状态；定义 ID 在配置中显示，不伪造实例；仅在定义缺失时保留已知定义 ID 作为诊断。
- 运行字段中的状态、抽屉标题状态与画布保持一致：业务正在运行、执行错误或结果未知时显示对应状态，其余沿用 DAG 阶段状态；刷新后同步更新，不把失败或未知执行显示为就绪。
- 普通节点的已有只读 `ClientNode.Panel` 保留在运行区域内部。Studio 提供“节点插件详情 · <kind>”标题、“以下内容由节点插件提供”说明、明显边框和主题背景；插件负责内部尝试记录、待确认结果、stdout/stderr 等差异内容。公共状态、实际输入、最终输出及公共执行错误由 Studio 展示，避免重复。命令日志明确标为 stdout/stderr，待确认结果不能标作已交付输出。
- 运行区域通过留白、分隔线和轻微背景变化区分；字段平铺，不再嵌套运行概况、输入与输出、运行标识等分类标题。插件无内容时不占位；插件缺失时保留已有可用数据，渲染失败时在来源区域提示错误。等待/跳过位置及 DAG 不装配节点插件面板。
- 模板与实例共用同一配置正文，以 `dl` 字段列表按原直接字段顺序展示值，不增加配置分类或标题层级。字符串完整展示，对象、数组及其他非字符串值以 YAML 展示；字段名与内容不翻译，不按扩展字段名推断业务，不补默认值、不合并改写、不截断。YAML 从当前定义对象或实例创建快照生成，保留嵌套结构、字段顺序及值类型，不生成共享对象锚点，不主动折行长字符串；不是源文件视图，不还原注释、锚点或原排版。运行身份、实际输入输出和插件数据维持现有展示，复杂运行值继续使用 JSON。仅当对象类型为 DAG 时隐藏 `dag` 子项数组，普通节点的同名扩展字段仍展示；子项由画布分别查看。
- 详情保持只读，不新增折叠机制；业务动作继续从卡片操作位进入，表单浮窗与草稿、Agent 会话及记录入口沿用既有行为。
- 定义定位失败时，保留已知运行信息，定义区显示“无法定位此对象的定义。”，不误用根定义或同名节点；不可定位的普通节点不装配依赖定义的业务面板。
- 模板与实例详情共用宽度调整行为：拖拽左侧边界，或聚焦边界后使用左右方向键按 10px 调整；默认 320px，宽度限制沿用实例页（通常至少 300px、最多画布可用宽度的 70%，不足 300px 时占满可用宽度）。调整不重置画布视口。模板在同一详情 Tab 内切换卡片、查看根 DAG、关闭重开抽屉及切换 Tab 时保留宽度，不新增模板宽度持久化；实例继续保存宽度并在宿主重启后恢复。
- 保留既有关闭、点击画布空白保持打开和画布视口规则。所选实例更新后同步运行信息；所选等待位置消失时关闭抽屉，不自动改选新实例。
- 分区标题、字段标签、根入口和缺失提示随宿主中英文切换。共享正文沿用宿主主题，长文本及复杂值在宽窄屏、浅深色主题中可阅读；新增正文不扩大画布卡片。

## 可观察验收标准

1. 模板与实例的相同节点直接字段顺序和值完全一致；实例使用创建时快照，源模板改变后配置不变。原语言、多行长文本、嵌套 schema、0/false/空对象数组完整保留；input_schema、output_schema、schema、uiSchema 及其他复杂配置呈现可解析回原值的 YAML，运行输入输出仍为 JSON。DAG 仅隐藏 `dag`，普通节点同名字段仍展示。
2. 模板正文只有配置；实例正文先配置后运行区域。运行身份、状态、逐项身份和实际输入输出不混入配置；运行字段在同一列表平铺，无旧分类标题。
3. 插件内容位于运行区域内部，明确标题和来源说明，主题背景及边框可辨。Bash stdout/stderr 与 Studio 已交付输出分别标示；Agent 待确认结果及尝试记录不冒充最终输出；公共错误不重复展示。
4. 等待/跳过没有伪造实例或输入输出；根/嵌套 DAG、逐项实例保持既有定位与身份。无插件内容不占位，插件缺失/失败时仍可读配置与公共运行数据。
5. 中英文运行标签与插件说明随宿主切换，配置键值不变；浅深色及 390px 窄屏无横向溢出，长正文能滚动。既有拖拽/键盘宽度、实例重启恢复、卡片操作和表单草稿不退化。

## Testing Decisions

- 复用模板与实例组件测试，精确断言配置与末尾运行区域及对应字段：普通节点、根/嵌套 DAG、等待/跳过位置的定义定位、字段顺序、长文本、schema、扩展字段和 DAG 子项隐藏。避免以整个抽屉文本代替分区断言。
- 覆盖源模板变化后实例仍显示快照且不请求模板详情接口；嵌套同名节点与递归定义定位；`for` 各项共享定义但运行身份、输入输出分别显示；等待位置消失关闭抽屉，状态变化同步。
- 保留会话操作、bash 输出/错误和表单交互回归；补充查看根 DAG 或另一节点后返回表单，草稿不丢失，提交失败保留草稿、完成后只读。模板详情始终不装配业务操作。
- 刷新普通节点的业务状态，精确检查运行区状态字段与抽屉标题一致，覆盖执行错误、结果未知、正在运行和 DAG 就绪阶段。
- 通过 `e2e/workflows/node-details.e2e.ts` 验证模板只读定义、配置原顺序与准确内容、实例快照、运行区在末尾及字段归属、命令日志与交付输出的区分、等待/跳过位置省略空块、根 DAG 没有插件块，以及中英文、浅深主题和窄屏滚动；同时回归既有表单、Bash 和 Agent 操作。
- 同一文件独立准备宽度调整场景，验证模板拖拽、方向键、宽度边界、关闭重开/卡片/Tab 切换、视口不变与窄屏适配，并验证实例宽度调整及真实宿主重启恢复。
- 公共画布类型由生产调用端类型检查验证；既有图投影测试继续检查拓扑、分组、递归、逐项关系、布局与状态刷新，不固定绝对坐标。不重复新增已有源模板删除与重启快照测试。
- 实施中运行相关图与组件测试，交付前执行完整类型检查、构建和测试。按 `dsh-browser-e2e` 在固定 dsh `0.2.0-rc.1`、临时 `DSH_HOME`、非默认端口与 Codex 内置浏览器验收正常/错误路径、主题、语言、键盘和宽窄屏，逐项记录预期、实际及未验证项。

## Out of Scope

- 合并静态与运行图的生成算法、修改 DAG 语法或执行规则、重建通信协议及实例存储迁移。
- 运行实例编辑定义、原始 YAML 查看、模板热更新、结果手工编辑和新节点业务能力。
- 新增全局状态管理、表单草稿持久化或测试框架。
