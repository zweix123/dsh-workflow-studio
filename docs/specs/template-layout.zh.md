# 模板作者可配置的实例运行图排布

状态：代码、自动化测试与浏览器视觉验收已完成（2026-09-26）。验收以本规格与 `docs/dag-syntax.zh.md` 为准。

本规格接续[实例运行图阅读与操作体验](./instance-graph-readability.zh.md)、[实例 Tab 产品规格](./instance-tab.zh.md)和 [DAG 语法规范](../dag-syntax.zh.md)。领域术语遵循[工作流工坊词汇表](../../CONTEXT.md)。此前固定横向的要求适用于未配置排布的模板和实例；配置了有效 `layout` 的 DAG 层按本规格展示。

## Problem Statement

实例运行图目前固定从左到右排布。长链需要大量水平平移，模板作者即使了解流程的阅读重点，也无法指定从哪个位置改为纵向、何时另起一列。直接按固定层数折行又可能拆散条件分支、汇合、逐项实例组或嵌套 DAG，使依赖难以辨认。作者需要可预期、可诊断的展示配置，同时不能让排布配置改变工作流执行或使既有模板失效。

## Solution

在每个 DAG 定义上提供仅影响该层展示的可选 `layout`。作者声明默认方向 `horizontal` 或 `vertical`，并通过按顺序列出的段配置，用本层顶点定义 ID 指定 `start_at` 和从该点起采用的方向。方向持续到下一段开始或该层结束。纵向段从上到下阅读；连续纵向段向右另开一列，后一列在整图高度内居中，连接从前一列底部清楚地通向后一列顶部。不同方向的段也向右接续，新的段靠整图中线放置。

转折只能落在静态依赖图的完整结构边界。条件分支及其汇合、同一执行位置的 `for` 实例组和嵌套 DAG 分组保持完整。横向段的分支和逐项实例沿竖直方向展开，纵向段沿水平方向展开；聚合出口分别位于右侧和下方。多入边、合法跨段边及运行时展开后的实例连接必须保持方向、状态和端点可辨。

无效 `layout` 产生非阻断诊断：受影响的 DAG 层回退到现有横向排布，模板仍可选，工作流实例仍可创建和执行。创建对话框与已有实例画布采用已确认的 INFO/WARN 摘要条，按需独立展开详情。未配置 `layout` 的旧模板和旧实例保持现有横向画布，不显示排布提示。

## User Stories

1. 作为模板作者，我希望给一个 DAG 层声明默认排布方向，以便让长流程按预期阅读。
2. 作为模板作者，我希望用本层顶点的定义 ID 指定新段起点，以便配置不依赖运行时实例身份。
3. 作为模板作者，我希望段起点使用 `start_at`，以便不与依赖边的 `from` 混淆。
4. 作为模板作者，我希望新段方向持续到下一转折点，以便用少量配置表达长链排布。
5. 作为模板作者，我希望连续纵向段能另起一列，以便把长链放入较易阅读的二维空间。
6. 作为查看实例的用户，我希望较短纵向列在整图高度内居中，以便从上一列底部转到下一列顶部时容易找到续接位置。
7. 作为查看实例的用户，我希望横向、纵向混合时仍能顺着段的顺序阅读，以便理解方向变化后的依赖。
8. 作为模板作者，我希望转折点不能拆散一个条件分支及其汇合，以便图形不会误导读者。
9. 作为模板作者，我希望同一 `for` 位置展开的全部实例及其聚合出口作为整体排布，以便逐项身份和输出关系保持清楚。
10. 作为模板作者，我希望嵌套 DAG 在外层作为一个分组排布，内部另用自己的 `layout`，以便两层配置互不干扰。
11. 作为查看实例的用户，我希望横向段的条件分支和逐项实例上下展开，以便沿用现有阅读规则。
12. 作为查看实例的用户，我希望纵向段的条件分支和逐项实例左右展开，以便分支方向与主流程方向清楚区分。
13. 作为查看实例的用户，我希望多入边、跨段边和逐项实例连接有明确端点与箭头，以便在运行图展开后仍能追踪依赖。
14. 作为模板作者，我希望对未知、重复、乱序或结构上不安全的转折点收到定位明确的原因和修正建议，以便修改 YAML。
15. 作为模板作者，我希望排布警告不阻止选择模板或创建实例，以便展示配置失误不影响业务流程。
16. 作为查看既有实例的用户，我希望看到来自模板快照的排布诊断，以便理解为什么某层回退到横向。
17. 作为查看既有实例的用户，我希望 INFO/WARN 提示可分别展开和收起，以便先阅读摘要、需要时再查看详情。
18. 作为使用旧模板的用户，我希望未配置 `layout` 时图形和操作保持现有横向行为，以便无需迁移模板。
19. 作为工作流执行者，我希望排布字段不改变依赖、`if`、`for`、实例身份、输出和恢复结果，以便相同模板在不同排布下仍有相同执行事实。
20. 作为模板作者，我希望用户文档提供可复制的 YAML 示例和错误示例，以便知道如何设置并修正转折点。
21. 作为窄屏或深色主题用户，我希望提示和画布仍可阅读、可操作，以便不依赖特定窗口或主题。
22. 作为键盘用户，我希望能展开、收起并阅读排布诊断，以便无需鼠标完成排错。

## Implementation Decisions

- `layout` 是 DAG 定义上的可选展示字段，仅对声明它的那一层生效。根 DAG、普通嵌套 DAG 和递归产生的每次 DAG 实例均按各自所引用定义的本层配置投影；父层不穿透子 DAG 内部。
- `layout.direction` 是本层起始部分的默认方向，只接受 `horizontal`、`vertical`。`layout.segments` 按声明顺序给出后续段；每项用 `start_at` 引用本层直接声明的普通节点或嵌套 DAG 定义 ID，并用 `direction` 指定该段方向。边 ID、孙层顶点及递归自引用的虚拟执行位置不能成为段起点。
- 段从 `start_at` 所指顶点开始，持续到下一段之前。多个段起点不得重复、逆依赖顺序或落在无法确定先后关系的并行位置；不能用首个顶点制造空的默认段。此类配置给出修正建议。
- 转折点的静态安全规则以完整结构区域为边界，宁可拒绝有歧义的转折，也不拆散分叉及汇合。例：A 分叉至 B/C，在 M 汇合，随后是 N；B、C、M 不可作为新段起点，N 可以。同一 `for` 执行位置和嵌套 DAG 在父层始终为不可拆的整体。规则由展示层校验，不改变 DAG 引擎的合法性判定。
- 同层段整体按顺序向右接续。横向段内依赖从左到右；纵向段内依赖从上到下。纵向段按整图高度居中；连续纵向段为相邻列，跨列连接从前段末尾到后段起点。混合方向也在右侧新区域开始，不沿上一段末尾向下无限延伸。
- 条件分支与 `for` 实例组始终沿本段主方向的垂直方向展开：横向段上下展开，纵向段左右展开。逐项实例按原始项索引保持稳定顺序，聚合出口位于主方向的下游。等待和跳过的执行位置不得被排布提前展开成实例。
- 线条与端点跟随方向变化。合法跨段连接、多入边、条件边、逐项聚合连接及递归连接应避免穿过卡片和分组标题，并保留箭头、状态样式、条件与逐项短标记及全文查看能力。运行事实仍来自实例运行图与实例连接，不由布局推断。
- 对每层单独检查配置。该层任一配置项无效时，整个该层回退到标准横向排布；其他层仍可按自己的有效配置展示。诊断至少包含级别、DAG 路径、相关 `start_at`、原因、修正建议及回退范围。缺少 `layout` 不构成诊断。
- 排布诊断不复用模板致命错误。模板目录读取仍用原有 DAG 与节点合法性检查决定能否创建实例；展示配置无效只产生 WARN。INFO 表示某层自定义排布已应用。模板选择和实例详情从同一诊断语义生成提示，既有实例以保存的模板快照为准。
- INFO 与 WARN 均使用相同的摘要条布局和“查看详情／收起详情”交互，分别用级别文字及蓝色／琥珀色辅助区分；各条独立展开。创建对话框的提示位于模板选择框下，实例提示位于画布上方。详情展示可复制的配置定位与修正文字，适配中英文、浅色／深色和窄屏。
- `layout` 不参与依赖解析、`if`／`for` 求值、实例 ID、执行状态、输入输出、结果提交、运行图持久化或恢复决策。模板快照继续保留原定义；当前画布只改变该快照到视觉图的投影。
- 实施时分别更新面向用户的 DAG 语法文档和本产品规格。语法文档应提供可复制的纯横向、纯纵向、连续纵向列、混合方向、嵌套与非法转折示例，并明确错误如何修正。

## Testing Decisions

- 主要验证接缝采用现有的“模板读取 → 工作流实例创建 → 保存的模板快照与实例运行图 → 详情画布”链路。测试用户可见的创建能力、诊断内容、节点与边的相对位置和执行事实；不固定 Dagre 的每一个绝对坐标，也不把私有布局步骤作为断言对象。
- 先沿用模板目录与实例接口的现有测试，验证有效 `layout` 被保存在模板快照中，非法 `layout` 返回 WARN 但不使模板不可选、实例不可创建；真正非法 DAG 仍按原有错误拒绝。
- 沿用现有画布投影测试，覆盖长链、横纵向切换、连续纵向列与居中、多入边、跨段边、条件分支、分叉汇合、`for` 多实例与聚合出口、嵌套与递归。几何断言关注次序、边端点、分组包含与不重叠；实例连接断言关注真实来源与目标。
- 沿用现有客户端交互测试，验证创建对话框和实例画布的 INFO/WARN 摘要、独立展开、键盘操作、中英文文案及警告非阻断。无 `layout` 的旧模板与旧实例无提示。
- 沿用持久化与 DAG 引擎行为测试，以相同定义仅增删 `layout` 对比依赖激活、`if`／`for` 结果、实例身份、输出和恢复后快照，防止展示字段侵入执行语义。
- 浏览器视觉验收覆盖长链、分叉汇合、逐项多实例、嵌套与递归、旧实例快照，并在宽屏／窄屏、浅色／深色和中英文下检查节点、分组、边及诊断。原型中已确认的提示方案 B 只作为交互参照，正式验收以真实模板和实例画布为准。
- 完成相关代码检查、类型检查、构建与项目测试；只有针对具体失败或残余风险才扩大测试范围。

## Out of Scope

- 图上自由拖动、保存手工坐标、拖线编辑依赖、模板可视化编辑器。
- 自动替作者选择转折点，或按窗口尺寸改变模板声明的方向和段边界。
- 修改 DAG 编排、执行结果、节点族、运行时恢复格式或工作流实例身份。
- 把已确认的一次性提示原型直接作为正式 UI 或公开模板。
- 插件发布、分发和 dsh CLI 安装。

## Further Notes

- 原有横向方案及其适用范围见[实例运行图阅读规格](./instance-graph-readability.zh.md)。本规格中的自定义排布仅在有效配置存在时覆盖该层展示。
- INFO/WARN 的摘要与展开交互已由用户在一次性浏览器原型中确认。原型仅表达提示视觉与操作，不是布局算法或诊断数据源。
- 转折点安全策略由用户委托实施者细化。本规格规定可观察的合法／非法边界和回退行为；具体图算法可在实施中选择，但不得放宽分支、实例组和嵌套分组的完整性要求。
- 浏览器验收在本地 dsh 宿主中检查了连续纵向列、分叉汇合、嵌套分组、无效配置回退和无源模板的旧实例快照；逐项多实例和递归使用同一真实画布组件与引擎快照检查。验收覆盖宽窄画布、浅色／深色、中英文和诊断的键盘展开／收起。
