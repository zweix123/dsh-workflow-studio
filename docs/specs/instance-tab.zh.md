# 实例 Tab 产品规格

状态：实例创建、存储、详情改版、删除与运行时初始化已实施（2026-09-23）。

## 已确认的范围

- 本轮完成工作流实例创建、保存、列表、删除和 DAG 查看，不驱动真实任务执行。
- 工作流实例代表基于模板创建的一次独立运行，不是可反复执行的长期配置；领域术语见 [词汇表](../../CONTEXT.md)。
- 直接使用宿主现有工作区，与宿主工作区一一对应，不维护另一套工作区。
- 实例管理 Tab 按工作区分组展示实例，每组提供新建实例入口。
- 创建时从插件专属的全局模板目录读取并选择工作流模板，所有工作区共用模板库；每个模板一个子目录，配置文件使用 YAML，解析后的定义对象交给 DAG 引擎。
- 实例保留创建时的模板快照和本次运行输入，后续源模板的修改或删除不影响已有实例。
- 创建时由独立于 DAG 引擎的工作流运行时生成根输入并初始化引擎；详情展示已产生的节点实例、等待和跳过状态，不只是定义结构图。
- 创建流程只收集实例名称和模板，不要求用户填写运行输入；运行时按根 DAG 的 `input_schema` 为每个声明字段生成类型正确的空值。
- 实例沿用宿主官方存储能力及其实际配置的存储作用域，刷新和重启后保留，不额外承诺 profile 隔离。
- 宿主移除工作区后，已有实例保留在“未关联工作区”组，仍可查看。
- 普通工作区和“未关联工作区”中的实例均可永久删除。
- 本期画布只展示图，不实现节点点击、节点检查器或场景回放；点击工作流实例只负责进入该实例的详情视图。
- DAG 必须在同一画布平铺，不采用进入子 DAG 后切换层级的浏览方式。
- 节点沿水平方向排布，`for` 逐项展开和递归沿垂直方向排布；更具体的视觉效果后续讨论。
- 只展示初始化实际产生的展开实例。依赖尚未执行的上游节点输出的 `for` 或递归保持等待，不伪造展开结果。

## 问题陈述

当前创建表单要求用户填写 YAML 运行输入，后端直接用这份输入初始化 DAG。节点业务执行尚未接入，这让实例创建依赖一份本期不需要用户准备的输入，也没有为后续节点执行留下独立的运行时边界。

## 方案

创建实例时，工作流运行时依据根 DAG 的输入声明生成占位运行输入，再调用 DAG 引擎完成初始化。`string` 填 `""`，`number` 填 `0`，`boolean` 填 `false`，`object` 递归填充其声明属性，`array` 填 `[]`；省略输入声明时使用 `{}`。保存生成的运行输入、模板快照和初始 DAG 快照。创建表单不再提供 YAML 输入编辑。

本期只初始化 DAG，不提交节点输出。初始创建的节点保持 `ready`，依赖尚未收到上游输出的位置保持等待；条件、逐项展开和递归只按引擎初始化时实际发生的结果展示。未来节点输入由 DAG 引擎根据依赖传递，运行时再负责节点执行及结果提交；本期不预造节点输出，也不改变 DAG 的输入输出校验规则。

## 用户故事

1. 作为创建工作流实例的用户，我希望只选择模板并填写实例名称，以便在尚未接入业务执行时也能创建实例。
2. 作为查看实例的用户，我希望看到真实的初始化快照，以便分辨已创建、等待和跳过的执行位置。
3. 作为重新打开实例的用户，我希望占位运行输入和初始化快照被保存，以便刷新后仍看到相同的初始状态。
4. 作为模板作者，我希望根输入按声明类型填充，以便模板无需人工输入也能通过当前的根输入校验。
5. 作为后续执行层的开发者，我希望运行时与 DAG 引擎分开，以便将来在运行时接入节点业务执行和结果提交。

## 实现决策

- 创建请求只包含工作区、实例名称和模板标识，不接受用户提供的 YAML 运行输入；创建表单移除该编辑项及其对应的校验反馈。
- 工作流运行时承担占位根输入的生成和 DAG 初始化；实例服务调用运行时，并保存生成的输入和初始化快照。DAG 引擎继续负责输入校验、初始展开和状态管理。
- 占位值覆盖根 `input_schema` 的每个声明字段及对象的嵌套声明属性；数组为空，不生成虚构元素。`null` 不是合法的声明字段占位值。
- 本期不调用节点结果提交接口，节点输入不独立补造。后续执行接入点在代码中用英文 TODO 标注，说明占位初始化是当前范围内的临时实现。
- 模板编译、根输入初始化及保存全部成功后才创建实例；失败时不留下残缺实例，并保留创建表单中的名称和模板选择。

## 测试决策

- 以现有实例创建接口测试为主要验证边界：断言无需 YAML 输入即可创建，保存的根输入符合声明类型，快照保持初始化状态，刷新或重启后内容不变；非法模板或初始化失败不产生实例。
- 以现有创建表单交互测试验证输入编辑项已移除，创建请求只携带名称、工作区和模板。测试可观察行为，不绑定占位生成函数的内部组织方式。

## 范围外

节点业务执行、节点输出占位生成、结果提交、后台推进、失败恢复，以及把初始化快照用作可恢复的运行状态，均不在本期范围内。

## 后续说明

该占位输入只满足当前初始化需求，不表示真实业务输入；后续接入实际执行时需要重新设计运行输入的来源和节点结果提交方式。

## 约束与参考

- DAG 格式、输入校验和初始展开行为遵循 [DAG 语法文档](../dag-syntax.zh.md)，参考项目的旧模板语法不自动成为本项目标准。
- 参考 `references/dsh-workflow-ui` 的工作区与实例关系，以及该项目和 `references/yak-lang/playground` 的 DAG 可视化实现；界面可以独立设计。
- 保持与宿主 `@deepseek-ai/dsh@0.1.6-alpha.2` 对齐，并兼顾浅色/深色主题、中英文和窄屏。
- 参考项目通过宿主官方 `@deepseek-ai/dsh-storage-domain` 保存实例，使用 `defineDomain`、`ctx.storageDomain.open` 和领域存储的读写接口。本机安装的 `0.1.6-alpha.2` 已核实提供该能力；本次实现已按该能力接入。
- 当前宿主默认存储根为 `${DSH_HOME}/storages`，未设置 `DSH_HOME` 时为 `~/.dsh/storages`，可由宿主配置覆盖；不自动按 profile 隔离。参考项目文档中的“当前 profile”不能作为本项目的默认存储承诺。

## 模板发现与创建规则

1. 模板路径为 `${DSH_HOME}/dsh-workflow-studio/templates/<模板ID>/workflow.yaml`，默认 DSH home 为 `~/.dsh`；目录名作为模板 ID 和本期选择器的展示名称。打开创建表单时重新读取模板目录。没有可用模板时展示放置路径；非法模板只标记为不可用并禁止选择，本期不分析或展示具体原因。
   插件随包提供 `openspec-workflow`、`github-spec-kit-workflow` 和 `matt-pocock-wayfinder-workflow` 三个内置示例，取自 `references/yak-lang/examples/` 中对应的 code agent workflow（Wayfinder 使用 v2 内容，名称去掉 v2）。宿主每次加载时遍历包内 `templates/` 下的模板目录，把整个目录复制到上述目录；同名内置模板目录整体替换，其他用户模板目录不受影响。目录格式校验作为独立函数，读取 `workflow.yaml`、解析 YAML 并编译 DAG 定义，供模板发现和实例创建复用。
2. 创建表单包含实例名称和模板。名称默认由模板名称加时间生成，允许修改，同一工作区内不得重名。编译、运行时根输入生成和 DAG 初始化全部成功才保存实例；失败保留表单中的名称、模板选择并给出错误反馈，其中模板无效只提示状态，不展示解析或编译原因。成功后关闭表单，将实例加入所属工作区卡片；用户点击实例时打开 DAG 图。

## 本期验收范围

- 实例列表与宿主工作区对应，可在各工作区下选择本地 YAML 模板、填写名称，无需填写运行输入即可创建实例并查看初始化图。
- 无可用模板或模板非法时提示不可用，不分析具体原因；名称重复或初始化失败时有明确错误反馈。创建失败不留下残缺实例，并保留表单内容。
- 刷新或重启后，实例及其初始图仍可查看，使用保存的模板快照和运行输入，不受源模板变化影响。
- 移除宿主工作区后，其实例在“未关联工作区”中仍可查看。
- 每个实例可通过行尾操作菜单删除；删除前需二次确认。删除成功后，列表与计数立即更新，已打开的该实例详情 Tab 关闭；取消或失败时实例保留。
- 同一画布平铺展示，节点横向排布，已经产生的 `for` 和递归实例纵向排布；未产生的展开保持等待语义。
- 本期没有真实节点执行、节点点击或详情侧栏；展示适配宿主浅色/深色主题、中英文和窄屏。

## 删除实例

每个实例行右侧提供与 dsh 侧边栏对话项相近的“⋯”操作入口：鼠标悬停时显示，键盘聚焦和触屏时也可使用。点击“⋯”只打开菜单，不进入实例详情；本期菜单只有“删除实例”一项。普通工作区与“未关联工作区”的实例使用相同的删除入口。

点击“删除实例”后弹出与宿主风格一致的确认框，显示目标实例名称，并明确提示删除不可恢复。取消时不改变实例；确认后执行永久删除，移除该实例保存的模板快照、运行输入和初始图状态，不影响源模板或宿主工作区。删除期间防止重复提交；失败时保留实例、显示错误并允许重试。删除成功后从列表移除实例、更新所属分组的计数，并关闭该实例已打开的详情 Tab；关闭其他详情 Tab 的行为保持不变。

## 实例详情改版交互与画布

工坊顶部固定显示实例管理、模板管理两个 Tab；点击实例后，按实例 ID 新增以实例名称命名、可关闭的详情 Tab。创建成功只更新实例管理页，不新增或切换 Tab；从总览再次点击已打开的实例时切回原 Tab，不重复创建或请求详情。实例详情占满 Tab 内容宽度，不显示实例列表，也不增加返回按钮。关闭详情 Tab 只关闭页面，不删除实例；关闭当前 Tab 时激活右侧相邻 Tab，若没有则激活左侧相邻 Tab。切回实例管理时保留总览滚动位置。窄屏时 Tab 行可横向滚动。页面刷新后回到默认的实例管理 Tab，关闭所有临时详情 Tab；本期不增加 URL 路由或深链接。

实例管理是普通页面，主区域以工作区卡片总览实例；宽屏两列、窄屏一列。每张卡片展示工作区名称和实例名称，可创建的工作区提供新建入口；“未关联工作区”可查看和删除实例，不可创建。页面不显示固定实例侧栏或空白详情栏。点击新建后，弹出参考宿主设置页风格的居中创建表单，右上角用 × 关闭，底部只有“创建实例”按钮；点击遮罩或按 Escape 也可关闭。表单保留模板选择、实例名称及校验错误。每个新打开的实例首次适配全图；只切换 Tab 或改变窗口尺寸时，各实例保留自己的缩放和平移。

页面跳转方面，本期只实现实例管理与实例详情之间的跳转。模板管理 Tab 暂不提供内容；模板详情以后按具体模板打开临时 Tab，本期不显示，也不实现模板列表、详情或增删改。图中节点不可点击。

详情画布接入 React Flow 和 Dagre 的基础能力，不提前移植完整调试台。首次打开实例时自动适配全图；之后保留用户的缩放和平移，仅在用户触发“适应画布”时重新居中。节点不可拖动、不可连线。

嵌套 DAG 在同一画布中使用可见分组边界；边带方向箭头，按 `pending`、`active`、`inactive` 区分样式，只在存在 `if` 或 `for` 时显示标签。`for` 实例和递归实例纵向排列。画布提供 Dagre 自动布局、平移、滚轮缩放、放大、缩小和适应画布；本期不增加小地图、节点选择、动态连线、递归深度折叠、节点检查器、场景回放或真实执行。
