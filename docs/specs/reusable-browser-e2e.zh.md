# 可重复运行的浏览器端到端测试

## 目标与规则

把功能验收沉淀为随 Git 保存的 TypeScript 测试，后续用一个命令重跑，并得到确定的通过／失败结果。

- `npm run test:e2e` 自动检查工具、构建插件、准备隔离环境并运行真实宿主浏览器测试。
- 固定依赖版本；只使用用户已安装的 dsh `0.2.0-rc.1`，不安装／升级 CLI，不修改日常 profile。
- 每条用例独立的临时 home、工作区和测试数据；使用空闲非默认端口，不能复用或停止别人的宿主。
- 首批用例用明确的页面操作和精确断言，运行时不依赖模型或 AI 操作缓存。
- 正常结束及场景失败时保存证据、停止本轮进程并清理临时数据；重启场景保留本轮数据再验证恢复。
- Web 登录使用本轮宿主的临时启动凭证；不把 token 写进测试代码、追踪、日志或长期验收记录。
- 默认无界面执行操作和断言，不录屏、不主动截图；需要观察时通过 `--headed` 弹出浏览器实时观看，不增加演示等待。
- 成功退出 0，失败退出非 0；保留机器可读报告、逐步操作记录和脱敏日志。当前框架失败时自动留下诊断截图；浏览器网络 trace 关闭，避免记录 Web cookie。
- 新 UI 功能及修复应补充相关可重复用例；探索性浏览器验收和截图不能代替这些断言。

## 首条验收场景

依据[结构化表单](./form-structured-fields.zh.md)和[节点输入输出](./node-input-output.zh.md)，从真实页面完成工作区添加、实例创建和表单操作。

1. 为数组新增未填写的布尔项，提交应拒绝；明确输入 `false` 后可以提交。
2. 修改对象数组并删除中间项，保存准确的字符串、`0`、`false`、空对象与空数组。
3. 下游 form 应采用上游真实值而非兜底默认值；新增字段保留默认值。
4. 两级表单提交后只读，下游节点详情中的输入应与交付结果一致。
5. 真正停止并重启同一个隔离宿主，重新打开原实例，输出和只读状态保持。
6. 全新环境再次执行同一用例应通过，不依赖上一轮的浏览器或数据。

首批范围不包含真实模型调用、空 bash 命令执行、所有主题／语言／窄屏组合，或既有规格的全部异常场景。
