# 模板管理 Tab 产品规格

模板与实例共用定义详情正文及画布元素类型的后续要求见[模板与实例共享定义详情](./shared-definition-details.zh.md)；本文的模板只读浏览与定义字段展示规则继续生效。

状态：需求已确认，待实施。

本规格接续[实例 Tab 产品规格](./instance-tab.zh.md)、[模板作者可配置的实例运行图排布](./template-layout.zh.md)和 [DAG 语法规范](../dag-syntax.zh.md)。术语遵循[工作流工坊词汇表](../../CONTEXT.md)。先前实例规格中“模板管理 Tab 暂不提供内容”的范围由本规格更新；实例创建与实例运行图仍按各自规格工作。

## Problem Statement

模板管理 Tab 目前为空。用户虽能在创建工作流实例时从本机模板目录选择工作流模板，却无法在工坊里浏览目录中的模板、了解其完整 DAG 结构，或查看 session_agent 提示词等节点配置。模板目录中的无效项也缺少便于定位问题的展示。实例运行图描述一次具体执行，不能代替尚未运行的模板定义图。

## Solution

模板管理 Tab 提供只读模板列表。用户打开有效模板后，在可关闭的详情 Tab 中查看完整静态 DAG 图：嵌套 DAG 在同一画布展开并保留分组，节点及 DAG 的直接配置字段可从右侧详情阅读，条件与逐项边可查看表达式。模板图遵循有效的 `layout` 配置及其非阻断诊断。无效模板留在列表并显示校验错误，但不能打开。模板内容使用作者写入的语言，不由插件翻译。

本期不展示原始 YAML，也不提供模板的创建、编辑、删除或手动刷新。同步整理内置模板：现有 `description` 保留为定义字段；`source`、`references` 的链接保留为 YAML 注释；未被使用的 `playground` 示例块删除。

## User Stories

1. 作为工坊用户，我希望模板管理 Tab 不再是空白，以便知道本机有哪些工作流模板。
2. 作为工坊用户，我希望看到模板目录中的所有模板，以便同时找到内置模板和自行放入的模板。
3. 作为工坊用户，我希望列表用目录名标识模板，以便与创建工作流实例时选择的模板 ID 一致。
4. 作为工坊用户，我希望中英文模板分别作为独立条目出现，以便选择作者实际编写的版本。
5. 作为模板作者，我希望模板中的 ID、描述、提示词和其他内容按原文显示，以便插件不改变模板的表达语言。
6. 作为工坊用户，我希望进入模板管理 Tab 时看到重新扫描后的目录内容，以便外部增删或修改模板后能看到当前结果。
7. 作为工坊用户，我希望在没有模板时看到明确的空状态和模板放置位置，以便知道如何提供模板。
8. 作为工坊用户，我希望在目录读取失败时看到错误反馈，以便区分读取失败与空目录。
9. 作为模板作者，我希望无效模板仍出现在列表并显示校验错误，以便找到需要修复的目录。
10. 作为工坊用户，我希望无效模板不能打开，以免把不可靠的定义误认为可用模板。
11. 作为工坊用户，我希望点击有效模板后打开独立、可关闭的详情 Tab，以便在模板列表和多个详情之间切换。
12. 作为工坊用户，我希望重复点击同一模板切回已经打开的详情 Tab，以免产生重复页面。
13. 作为模板作者，我希望模板图显示所有静态定义的节点和依赖，以便查看尚未运行到的分支和后续步骤。
14. 作为模板作者，我希望嵌套 DAG 在同一画布展开并保留分组边界，以便同时看到整体流程和层级关系。
15. 作为模板作者，我希望递归引用以有限的回环标记呈现，以便看清递归关系而不产生无限图形。
16. 作为模板作者，我希望 `for` 在模板图中保持定义层面的节点和边，以便不把尚不存在的运行实例画出来。
17. 作为模板作者，我希望图卡只显示定义 ID、类型和详情入口，以便在复杂图中保持可读。
18. 作为模板作者，我希望点击节点或 DAG 后在右侧看到其直接配置字段，包括已有的 `description`、session_agent 提示词、bash 命令、schema 和扩展字段，以便检查完整配置。
19. 作为模板作者，我希望长文本在详情中完整可读，以便核对提示词、命令与复杂配置。
20. 作为模板作者，我希望嵌套 DAG 的右侧详情不重复列出整个 `dag` 子项数组，以便从图上的子项分别查看配置。
21. 作为模板作者，我希望 `if` 与 `for` 边有简短标记并能查看表达式全文，以便理解条件与逐项依赖。
22. 作为模板作者，我希望有效 `layout` 同样作用于模板图，以便预览作者声明的阅读方向和段边界。
23. 作为模板作者，我希望无效 `layout` 给出原因并回退横向，同时仍能打开模板，以便展示配置失误不妨碍检查业务定义。
24. 作为键盘、窄屏或深色主题用户，我希望列表、图、详情和诊断仍可阅读和操作，以便不依赖特定输入方式或显示环境。
25. 作为使用实例页的用户，我希望模板详情沿用工坊与宿主的视觉和 Tab 交互，以便在模板定义与实例运行图之间切换时保持熟悉的操作。

## Implementation Decisions

- 模板管理是只读浏览入口。使用现有本机模板目录和目录校验结果；不创建第二套模板存储，也不改变工作流实例创建所用的模板身份、校验或快照规则。
- 列表扫描目录中的每个模板子目录，按现有模板 ID 规则以目录名显示。六个内置英文及 `.zh` 版本各为独立条目；不按宿主语言合并、筛选或翻译模板内容。列表不显示根 DAG ID、节点数量或 `description`。
- 每次激活模板管理 Tab 时重新扫描。没有手动刷新、文件监听或自动轮询。空状态给出当前模板放置位置；读取失败与目录为空分别反馈。
- 列表保留编译或节点校验失败的模板，显示已有校验错误并禁用详情入口。有效 DAG 的 `layout` 警告不视作模板无效，仍可打开；布局诊断按现有规则展示。
- 有效模板的详情通过只读接口重新读取并返回经过现有校验的定义，不返回原始 YAML。模板 ID 必须限定在模板目录下，不能将详情接口用作任意文件读取入口。打开失败时保留列表并给出可理解的反馈。
- 模板详情按模板目录 ID 打开临时 Tab；同一 ID 只开一个。Tab 的关闭、焦点、相邻 Tab 激活及窄屏滚动沿用现有实例详情交互。页面刷新后不恢复临时详情 Tab。
- 模板图投影完整静态 DAG 定义，区别于实例运行图的已创建实例、等待位置和真实实例连接。显示全部直接及嵌套定义；每层依赖保持在本层，嵌套 DAG 保留可见分组。递归自引用用有限标记表达，不无限展开。`for` 保持静态依赖，不按假设输入生成实例组。
- 画布使用与实例详情一致的节点、DAG 分组、线条、导航和宿主主题风格，但不显示就绪、执行、完成等运行状态，也不装配节点业务操作。图卡只显示定义 ID、类型和详情入口，不显示简短描述。
- 点击普通节点或 DAG 打开右侧只读详情，按定义中的直接字段顺序列出字段和值；长文本完整显示，复杂值可阅读。节点类型字段及其他扩展字段按原值展示，不要求各节点包新增预览界面。DAG 详情不重复列出 `dag` 子项数组；子项通过画布分别查看。根 DAG 也可查看其自身字段。
- 边的方向及 `if`、`for` 标记与实例图一致；有表达式时可用鼠标或键盘查看全文。边 ID、端点和表达式保留其定义语义，不显示运行期激活状态。
- 模板图按每层有效 `layout` 展示；无效层给出与现有布局诊断一致的原因和回退范围，并仅让该层回退横向。布局设置不进入 DAG 执行、实例身份或持久化决策。
- 保留内置模板现有的根 DAG 与嵌套 DAG `description` 字段；普通节点若由作者提供 `description`，按一般直接字段展示。本期不要求该字段、不新增专门的模板描述语义或列表摘要。
- 内置模板中的 `source`、`references` 不再是解析后的定义字段；现有链接改成 YAML 注释供维护者阅读。四份带有 `playground` 的内置模板删除整个未使用的示例块，包括其中的场景描述。英文和中文版同步调整结构；其他自定义字段仍按现有 DAG 规则保留，不增加针对这些字段名的拒绝校验。
- 插件自身控件文案跟随宿主语言；模板字段值不翻译。字体、间距、图标、交互状态、浅色与深色主题以及窄屏行为沿用宿主与工坊现有模式。

## Testing Decisions

- 主要验证接缝沿用现有“模板目录扫描与校验 → 只读模板接口 → 模板 Tab 与详情 Tab”链路，以用户能看到的结果为断言，不固定内部投影函数或图布局的绝对坐标。
- 沿用模板目录与工作流实例接口测试的先例，验证有效及无效模板的目录身份、错误、详情读取和重新扫描；非法模板不能打开，`layout` 警告不阻止打开；详情请求不能越过模板目录。
- 沿用现有客户端交互测试，验证空状态、读取失败、列表禁用项、详情 Tab 的打开/复用/关闭、进入模板 Tab 时重新扫描、节点与 DAG 字段详情、边表达式、无执行操作及中英文界面文案。
- 沿用现有画布投影测试，以可观察的节点和边关系验证长链、条件分支、`for`、嵌套 DAG、递归回环与 `layout` 回退；关注完整性、分组、相对顺序和可读性，不断言布局库生成的每个绝对坐标。
- 沿用内置模板双语同构与目录校验测试，确认清理元数据后六份模板仍有效、两种语言的 DAG 结构一致，且解析后的定义不含 `source`、`references`、`playground`。
- 浏览器验收在真实宿主中检查宽窄屏、浅色与深色主题、键盘交互、长提示词、复杂嵌套及布局诊断；检查结果应与实例页的视觉和交互一致。

## Out of Scope

- 模板新增、导入、编辑、删除、发布、分发、从模板详情创建工作流实例，以及 dsh CLI 安装。
- 原始 YAML 查看、编辑或复制入口；手动刷新按钮、文件监听和实时更新。
- 模板翻译、语言自动切换或把英文和中文版合并成一个模板。
- 图上自由拖拽、连线编辑、手工坐标保存，以及根据模板图启动节点业务。
- 为没有描述的普通节点批量编写 `description`，或为 `description` 建立新的必填规则。
- 在模板图上伪造工作流实例、`for` 逐项实例、执行状态、业务输出或真实运行连接。

## Further Notes

- 实例 Tab 原有“无效模板只标记不可用、不展示原因”的规则继续适用于实例创建表单；本规格只要求模板管理列表展示校验错误。
- 先前模板排布规格描述的是实例运行图。本规格让同一份作者配置作用于静态模板图，但不改变该字段对工作流执行无影响的约束。
- 本规格只定义本期可观察的产品行为；静态图的具体投影算法与组件拆分在实施时选择，优先复用现有画布能力。
