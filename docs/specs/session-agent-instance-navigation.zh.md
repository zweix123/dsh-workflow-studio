# Session agent 对话返回工作流实例规格

状态：正式规格，需求与测试边界已确认，待实施（2026-10-03）。本文作为代码实现、测试与审查的验收依据，不表示功能已经交付。

## Problem Statement

工作流使用者可以从实例运行图中的 session_agent 节点详情打开关联的 dsh 对话，在对话中持续处理节点任务。对话界面缺少返回所属工作流实例的入口，用户处理完任务后需要重新寻找实例与节点，才能查看流程状态或执行原有的完成操作。

现有工坊在切换到宿主对话页面时会卸载，已打开的详情 Tab 和画布视角保存在页面组件中。即使增加一个打开工坊的按钮，也不能据此回到指定实例，或恢复此前的阅读位置。用户从宿主侧边栏直接打开对话、刷新页面或重启宿主后，也应能根据已经保存的节点关联找到所属实例。

同一节点定义可以在逐项展开或嵌套执行中产生多个节点实例。返回位置必须由具体关联确定，不能通过节点名称、定义 ID 或最近访问记录猜测。

## Solution

在有关联的 dsh 对话标题栏增加“返回实例”按钮。用户点击后打开所属工作流实例的详情 Tab，并打开该对话对应的节点实例详情。入口使用宿主公开的标题栏动作插槽，不新增对话内容 Tab。

同一浏览器页面运行期间，切出工坊再返回时保留已打开的实例和模板详情 Tab，以及各自的画布缩放和平移；目标实例已经打开时复用其 Tab。返回时读取最新实例状态，同时保留已有视角，不因刷新数据或打开节点详情自动重新适配全图。

对话归属来自已经持久化的节点业务事实。即使用户未从工坊进入当前对话，或刷新、重启后临时页面状态已经清空，只要关联的工作流实例仍存在，入口就可以重新找到目标。普通对话、另行 fork 的子对话以及所属实例已删除的对话不显示返回入口。

## User Stories

1. 作为工作流使用者，我希望从节点详情继续打开原有关联对话，以便保持现有的实例到对话路径。
2. 作为工作流使用者，我希望在关联对话的标题栏看到“返回实例”，以便无需重新寻找工作流入口。
3. 作为工作流使用者，我希望点击返回后直接进入所属工作流实例详情，以便继续处理同一次运行。
4. 作为工作流使用者，我希望返回后打开当前对话对应的节点实例详情，以便明确刚才处理的任务。
5. 作为工作流使用者，我希望同名节点也能被准确区分，以便不会进入另一实例或另一层 DAG 中的任务。
6. 作为工作流使用者，我希望逐项展开产生的多个对话分别返回各自节点实例，以便逐项工作互不混淆。
7. 作为工作流使用者，我希望重复往返复用已打开的实例 Tab，以便不会不断产生重复页面。
8. 作为工作流使用者，我希望目标实例尚未打开时自动增加其详情 Tab，以便无需先在工坊打开它。
9. 作为工作流使用者，我希望返回时此前打开的其他实例 Tab 仍然存在，以便能够继续比较多个运行。
10. 作为工作流使用者，我希望返回时此前打开的模板详情 Tab 仍然存在，以便能够继续对照模板。
11. 作为工作流使用者，我希望已打开详情 Tab 的相对顺序保持不变，以便继续使用熟悉的位置。
12. 作为工作流使用者，我希望返回已打开实例时保留其画布缩放和平移，以便不丢失原来的阅读位置。
13. 作为工作流使用者，我希望其他已打开实例和模板的画布也保留各自视角，以便切换 Tab 后能够接着阅读。
14. 作为工作流使用者，我希望打开对应节点详情不强制移动已有画布视角，以便返回操作不会覆盖我主动调整的位置。
15. 作为工作流使用者，我希望首次打开目标实例时沿用现有可读的首次画布视角，以便不依赖已不存在的历史位置。
16. 作为工作流使用者，我希望关闭详情 Tab 后能再次通过关联对话打开它，以便关闭页面不破坏节点关联。
17. 作为工作流使用者，我希望从宿主侧边栏直接打开关联对话时也有返回入口，以便功能不依赖进入对话的路径。
18. 作为工作流使用者，我希望刷新页面后仍能从关联对话找到所属实例，以便临时页面状态清空不影响导航。
19. 作为工作流使用者，我希望重启宿主后仍能找到关联实例和节点，以便持续处理尚未结束的工作。
20. 作为工作流使用者，我希望普通对话不出现无效返回入口，以便不会被误导为工作流任务。
21. 作为工作流使用者，我希望 fork 出的子对话不自动继承原节点归属，以便独立探索不会指向未经确认的任务关联。
22. 作为工作流使用者，我希望节点完成后，只要实例和关联仍存在就能返回查看，以便回顾已经完成的工作。
23. 作为工作流使用者，我希望返回时看到实例的最新执行状态，以便不会依据进入对话之前的旧数据做判断。
24. 作为工作流使用者，我希望返回只改变页面位置，以便正在运行的对话可以继续处理任务。
25. 作为工作流使用者，我希望节点完成仍通过已有完成操作明确触发，以便导航不会被误当作业务完成。
26. 作为工作流使用者，我希望实例删除后不再出现有效的返回入口，以便保留下来的对话不会导航到已删除的数据。
27. 作为工作流使用者，我希望点击过程中实例被删除时看到“实例已不存在”的反馈，以便理解返回失败的原因。
28. 作为工作流使用者，我希望查询失败与没有关联实例有不同反馈，以便临时故障不会被误判为关系丢失。
29. 作为工作流使用者，我希望查询或加载失败后能够重试，以便不必重新创建对话或实例。
30. 作为工作流使用者，我希望快速切换对话时入口只对应当前对话，以便较慢的旧请求不会把我带到错误实例。
31. 作为工作流使用者，我希望连续点击返回不会产生重复 Tab 或重复业务操作，以便界面在请求较慢时仍可预测。
32. 作为使用键盘或辅助技术的用户，我希望返回入口和错误反馈可访问，以便不用依赖鼠标、悬停或纯图标理解操作。
33. 作为使用不同语言和屏幕尺寸的用户，我希望入口在中英文、浅色与深色、宽屏与窄屏下均可用，以便保持宿主一致的操作体验。
34. 作为项目维护者，我希望导航复用现有持久关联和宿主公开能力，以便无需升级宿主或同步第二套业务关系。
35. 作为项目维护者，我希望临时阅读状态与业务执行状态分开，以便恢复页面不会覆盖最新运行事实。

## Implementation Decisions

- **固定宿主与入口。** 继续适配 dsh 0.2.0-rc.1，使用该版本公开的 conversation.session.header.actions 插槽放置返回动作。沿用宿主标题栏按钮、主题变量、尺寸和交互状态，使用中英文词表。对话内容 Tab 的点击用于切换内容视图，本功能不把内容视图伪装成跳转动作，也不接管宿主整个标题栏。
- **关联的身份。** 查询以当前 dsh 对话 ID 为入口，返回完整的工作流实例 ID 与节点实例 ID。节点定义 ID、名称、工作区 ID 或单独的节点实例 ID 都不能替代这对目标身份。仅认已经实际创建的、由 session_agent 节点直接关联的对话；节点已经完成不影响导航资格。
- **事实来源。** 使用现有工作流实例存储中的节点执行事实反查归属。首次加载或重启后都可以从持久事实恢复查询能力；不依赖本次浏览历史，不新增持久化反向关系表，不向宿主 Session 额外写入工作流 metadata，不要求迁移已有实例。
- **模块职责。** session_agent 负责解释自身业务状态中的对话关联，工坊实例服务负责组合实例身份、节点实例身份并提供查询。优先复用节点已有的公开投影，必要时提供节点自有的最小查询能力；公共执行器、通用存储和客户端不直接解析节点私有 business 结构。节点包继续不依赖工作流、DAG 或实例存储类型，不为此建立跨所有节点类型的通用导航框架。
- **查询接口。** 在现有插件 HTTP 服务边界增加只读的对话归属查询，成功结果明确区分“有关联”和“无关联”；有关联时至少返回上述两项目标身份。请求错误、服务错误与合法的无关联结果分开处理，客户端验证响应。查询本身不启动节点、不创建对话、不改写执行事实。
- **显示范围。** 打开或切换对话时按当前对话查询归属。普通对话、fork 子对话、尚未建立有效关联的对话和已删除实例的对话不显示可用返回按钮。fork 的父子关系不参与此次查询，不沿 parentSession 推断继承。
- **导航协调。** 客户端插件装配层提供跨工坊挂载周期的目标导航能力；先准备目标，再通过宿主公开的 layout.selectPanel 打开工坊。工坊读取目标并加载实例，激活或新建目标详情 Tab，按节点实例身份打开详情。此处新增的是插件内导航，不新增 URL 路由、深链接或浏览器后退协议。
- **刷新与请求顺序。** 每次返回都核实目标仍然存在，并取得最新实例详情。数据更新与临时展示状态分开；沿用实例版本规则，迟到的旧响应不得覆盖更新结果。对话切换、后续导航与插件释放会使此前请求失效，旧响应不得更改新对话入口或抢走当前页面；重复点击不创建重复详情 Tab。
- **Tab 恢复。** 同一浏览器页面运行、插件客户端仍保持加载期间，在工坊组件之外保留已打开的实例与模板详情 Tab 身份、相对顺序和当前选择。切出工坊再返回不因组件卸载丢失这些信息；执行返回动作时目标实例成为当前 Tab，其他详情 Tab 的相对顺序保持不变。没有该实例 Tab 时沿用工坊现有新增与排列规则。
- **视角恢复。** 为每个仍打开的实例和模板详情 Tab 分别保留画布的缩放与平移。已保留视角优先于首次视角初始化；重新加载数据、恢复 Tab、打开目标节点详情、窗口或抽屉尺寸变化不得自动全图适配。用户此前查看的位置即使没有完整包含目标节点，也保留其位置，同时在详情中明确显示所选节点。
- **首次打开。** 目标实例没有可恢复视角时，沿用现有首次打开规则显示画布，并打开目标节点详情。此次返回不新增强制居中规则；用户仍可使用已有画布导航操作主动改变视角。
- **状态生命周期。** 临时 Tab 和画布状态仅属于当前浏览器页面中的插件客户端；不写入实例业务存储、Session、localStorage 或其他跨刷新持久介质，不跨浏览器页面同步。关闭某个详情 Tab 即释放该 Tab 的临时视角；刷新、插件客户端重新初始化或宿主重启后，可以根据持久关联重新打开目标，但不恢复此前整组临时 Tab 与视角。
- **已有偏好。** 实例抽屉宽度继续遵循现有保存规则，不因新增临时状态机制被覆盖。此次确认的跨页面保留范围是 Tab 与画布视角；表单草稿、未完成创建表单、浮层和其他临时编辑状态继续遵循各自已有规格，不自动纳入恢复范围。
- **删除与加载失败。** 归属查询确认实例已删除后隐藏有效返回入口。点击后目标失效时显示“实例已不存在”，不显示旧实例的可操作详情，不转向其他实例；如果已进入工坊，则提供现有实例管理入口。删除成功后清理对应 Tab 的临时状态，后续返回不能恢复它。归属查询或详情加载失败须有可重试反馈，不能当作无关联处理，也不能伪装为成功返回。
- **保持执行语义。** 返回操作不创建新对话、不重发初始提示词、不停止当前对话、不触发节点开始或完成、不提交 DAG 结果。节点详情继续遵守现有状态和操作权限，手动完成仍由已有完成入口触发；只读或不可执行的历史实例不会因导航恢复执行能力。
- **适配与访问性。** 返回按钮具有明确文字或完整的可访问名称，键盘可达且焦点可见；窄屏不覆盖宿主已有标题栏动作。加载与重试有可理解的反馈，浅色、深色和中英文均使用宿主既有样式与词表机制。

## Testing Decisions

- **已确认的测试边界。** 复用现有实例 HTTP 集成测试验证归属查询、删除和持久化恢复；复用工坊页面组件测试验证入口、定位、临时状态与并发反馈；使用隔离的真实 dsh 宿主和 Codex 内置浏览器验收完整往返。用户已确认这三个层次，优先扩展现有入口，不为私有查询函数、状态容器或组件内部组织另建测试边界。
- **可观察行为。** 断言返回的目标身份、用户看到的 Tab 与节点详情、画布视角是否保留、明确错误与业务副作用是否发生。不得用断言内部 Map、Hook、函数调用顺序或固定整图布局坐标替代用户行为；视角保留允许布局引擎合理的浮点容差。
- **既有先例。** 实例路由测试已经覆盖 session_agent 的持久对话、重试复用、逐项独立 Session、删除与重新打开存储；节点详情组件测试已经覆盖“打开对话”和完成操作；工坊与模板页面测试已经覆盖 Tab 去重、关闭、语言切换及画布交互。本功能沿用这些 fixture、公开 HTTP 路由和页面入口。
- **真正的跨页面验证。** 组件测试必须覆盖工坊卸载后重新挂载，并区分保留同一个插件客户端状态与创建全新客户端状态。仅在同一个始终挂载的工坊中切换详情 Tab，不能证明跨宿主页面恢复成立。真实宿主验收必须实际从实例进入对话再返回。
- **真实持久化恢复。** 服务端验证关闭并重新打开同一测试存储后仍能反查原关系；客户端验证刷新后临时状态清空但入口仍然有效。仅重建内存对象不能代替宿主重启验收。

| --- | --- | --- |
| NAV-01 | 从节点详情打开对话，再点击标题栏返回 | 原对话被复用；回到正确实例和节点详情；不新增业务动作或 Session |
| NAV-02 | 从宿主侧边栏直接打开关联对话 | 无需先访问工坊即可显示入口并准确返回 |
| NAV-03 | 两个工作流实例内有相同节点定义或相同运行节点 ID | 各对话通过完整身份返回各自工作流实例，不串实例 |
| NAV-04 | 同一定义经逐项展开或嵌套产生多个节点实例 | 每个对话分别打开关联的具体节点详情，不按名称或定义 ID 猜测 |
| NAV-05 | 同时打开多个实例与模板详情 Tab，调整各自视角后往返 | Tab 不丢失、不重复、相对顺序不变；目标被激活；各画布恢复各自缩放与平移 |
| NAV-06 | 目标实例已打开且视角位于另一处，返回时打开目标节点详情 | 恢复已有视角并显示正确详情，不自动适配全图或强制居中 |
| NAV-07 | 目标从未打开，或其 Tab 已主动关闭后再返回 | 只新建一个目标详情 Tab，采用现有首次视角，打开正确节点详情 |
| NAV-08 | 刷新页面或重启隔离宿主后，从原对话返回 | 已持久化关联仍可查询；不要求恢复旧临时 Tab 与视角；节点关联不重建 |
| NAV-09 | 普通对话、fork 子对话、未有效关联的对话 | 不显示可用返回按钮，不沿 fork 父链猜测工作流归属 |
| NAV-10 | 关联节点已经完成，但实例仍存在 | 仍可返回查看；不会重新开放已完成节点的业务操作 |
| NAV-11 | 实例在打开对话前已删除，或在入口显示后被删除 | 无有效关联时隐藏入口；点击竞态显示实例已不存在，不复活缓存实例或临时 Tab |
| NAV-12 | 归属查询失败、详情加载失败，然后重试 | 与无关联结果分开；显示可重试错误；恢复后能正常返回 |
| NAV-13 | 延迟旧请求，快速切换不同对话或发起后续导航 | 旧结果不覆盖当前入口、不导航到旧目标；连续点击不产生重复 Tab |
| NAV-14 | 对话期间实例状态推进，再返回；同时安排旧详情响应迟到 | 展示最新运行事实；旧数据不回退状态；保留已有画布视角 |
| NAV-15 | 对话仍运行时返回，再重新进入同一对话 | 导航不会停止对话、重发提示词、完成节点或推进 DAG；已有执行行为继续成立 |
| NAV-16 | 宽屏与窄屏、浅色与深色、中英文及键盘操作 | 按钮、加载、错误和重试均可用；焦点明确，标题栏动作不重叠，详情目标可辨认 |

- **自动化检查。** 实施后运行项目现有类型检查、构建和完整测试。与本功能无关的既存修改及失败单独列出，不擅自重写已有工作，也不通过删除断言、跳过场景或旧构建产物获得通过结果。
- **真实宿主验收。** 使用本机固定版本 dsh，创建临时 DSH_HOME；插件注册与宿主启动使用同一个临时目录和非默认端口，通过 Codex 内置浏览器执行关键场景。普通导航可以使用无需真实模型响应的测试对话；确实需要模型运行且缺少认证的场景标记未验证，不索取或复制用户凭据。接口调用和 jsdom 测试不能冒充浏览器端到端验收。
