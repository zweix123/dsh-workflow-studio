# 节点卡片交互提案

状态：已确认提案，待实施（2026-09-23）。本规格描述实例详情画布的下一阶段能力；现有只读画布规格在该能力交付前继续适用。

## Problem Statement

工作流实例目前只展示初始化后的 DAG 快照。用户可以看到节点实例已就绪、执行位置在等待或已跳过，却不能从卡片查看所选对象，也不能逐个推进已就绪的节点实例。状态和操作缺少明确的视觉分工，用户无法在画布上完成一次最简单的工作流推进。

## Solution

每张卡片右上角持续显示带文字的状态，底部左侧放当前可用的主要操作，右侧放“详情”。普通节点实例就绪时，用户点击 `▶ 执行`；工作流运行时按该节点的输出声明构造占位输出，提交给 DAG 引擎，并保存推进后的实例运行图。用户逐个执行新出现的就绪实例。卡片或 `ⓘ 详情` 打开一个暂不展示业务数据的检查器。

本期继续使用现有节点实例、DAG 实例和执行位置状态，不增加排队中、执行中或失败状态。等待与已跳过的位置没有节点实例，也不提供执行操作。

## User Stories

1. 作为工作流使用者，我希望在卡片右上角看到状态图标和文字，以便快速判断节点是否可以执行。
2. 作为工作流使用者，我希望状态在未悬停时仍可见，以便浏览大型 DAG 时不用逐个探索卡片。
3. 作为工作流使用者，我希望在就绪的普通节点实例卡片左下角看到 `▶ 执行`，以便明确知道下一步可以做什么。
4. 作为工作流使用者，我希望每次点击只执行我选中的节点实例，以便自行控制推进顺序。
5. 作为工作流使用者，我希望一个 `for` 实例组中的每张实例卡片分别提供执行按钮，以便逐项推进。
6. 作为工作流使用者，我希望执行成功后当前卡片显示“已完成”，以便确认这次操作生效。
7. 作为工作流使用者，我希望提交结果使边重新判定、下游实例按 DAG 规则出现或跳过，以便看到真实的图变化。
8. 作为工作流使用者，我希望新出现的就绪节点等待我再次点击执行，以便一次操作不会自动运行整个下游。
9. 作为工作流使用者，我希望等待位置显示“等待”，且没有执行按钮，以便不会误以为它已经是可执行的节点实例。
10. 作为工作流使用者，我希望已跳过位置显示“已跳过”，且没有执行按钮，以便理解该位置没有产生节点实例。
11. 作为工作流使用者，我希望嵌套 DAG 分组显示自身的运行中或已完成状态，但不提供普通节点的执行按钮，以便区分编排容器与可提交结果的节点。
12. 作为工作流使用者，我希望点击卡片空白处或右下角的 `ⓘ 详情` 都能打开详情，以便方便地选中目标。
13. 作为工作流使用者，我希望点击 `▶ 执行` 不同时打开详情，以便操作结果符合按钮含义。
14. 作为工作流使用者，我希望详情显示所选卡片的名称、状态和关闭入口，以便知道当前选中对象；本期无需输入、输出和依赖内容。
15. 作为工作流使用者，我希望宽屏时在右侧检查器查看详情，窄屏时在抽屉查看，以便不因设备宽度失去操作能力。
16. 作为工作流使用者，我希望打开和关闭详情、切换实例 Tab 或改变窗口尺寸时保留原有画布缩放和平移，以便继续查看原位置。
17. 作为工作流使用者，我希望执行成功后的图在刷新和宿主重启后仍保持一致，以便工作流实例确实代表一次持续的运行。
18. 作为工作流使用者，我希望源模板后续修改或删除不改变既有工作流实例的推进结果，以便继续查看创建时的运行。
19. 作为工作流使用者，我希望提交无法通过 DAG 校验时看到错误，且卡片保持就绪，以便修正问题而不误认节点已完成。
20. 作为使用键盘或辅助技术的用户，我希望状态和操作有可读名称、可见焦点与独立点击目标，以便不用依赖颜色、悬停或单个符号理解卡片。
21. 作为工作流使用者，我希望已打开详情的节点完成后，检查器同步显示它的新状态，以便不用关闭重开。
22. 作为工作流使用者，我希望已选中的等待位置在上游推进后消失时关闭其详情，以便不会继续看到指向旧位置的内容，尤其是在该位置展开为多个实例时。
23. 作为工作流使用者，我希望在旧页面点击已不再就绪的节点时看到最新图，而不是重复完成节点，以便避免过期页面造成错误操作。

## Implementation Decisions

- 区分创建时固定的模板快照和会随执行变化的实例运行图。运行图保存 DAG 实例、普通节点实例、执行位置及其各自状态和关系；前端由运行图的服务端投影渲染画布，不能以模板结构或画布节点反推执行事实。`waiting`、`skipped` 属于尚未产生实例的执行位置；普通节点实例仅有 `ready`、`completed`；DAG 实例仅有 `running`、`completed`。
- 卡片头部放名称和右上角状态；状态同时使用图标、文字和宿主主题色。底部固定操作区中，主要操作在左，详情在右。正常尺寸使用图标加文字；空间受限时可收成图标，但仍提供提示和可访问名称。卡片高度随操作区调整，避免按钮挤压名称。
- 只有处于 `ready` 的普通节点实例显示 `▶ 执行`。已完成实例、DAG 分组以及等待和已跳过的执行位置不显示执行按钮。所有可见卡片都有详情入口。
- 点击卡片非操作区域或详情按钮打开对应对象的详情；执行按钮拥有独立事件目标，不触发详情。选择普通节点实例时使用实例身份，不只用定义 ID；`for` 产生的不同实例分别处理。DAG 分组仅以标题或自身区域响应详情，不能吞掉子节点的点击。
- 本期详情只提供所选对象名称、状态、关闭按钮及空白正文，不加载输入、输出、日志、依赖解释或编辑表单。宽屏使用右侧检查器，窄屏使用抽屉；详情开关不重新适配全图。所选实例状态变化时同步更新检查器；所选等待位置因推进而消失时关闭检查器，不猜测应选中新生成的哪个实例。
- 创建工作流实例时，继续按根 DAG 的输入声明构造运行输入的零值，并由引擎分发给结构入口。无输入声明时使用空对象。
- 每次点击执行，仅对目标普通节点实例按输出声明构造占位输出：字符串为 `''`，数字为 `0`，布尔值为 `false`，数组为 `[]`，对象递归构造其声明字段；不额外生成未声明字段。工作流运行时将该输出提交给 DAG 引擎，前端不自行改写状态。
- 占位输出参与真实的 `if` 和 `for` 判定。`false` 可以关闭条件边，`[]` 可以使逐项展开的目标执行位置跳过。跳过位置没有节点实例或输出；不为其补值，也不改变现有 DAG 语法与输出校验规则。
- 模板中的 `for` 边始终是定义边，不因执行改写模板。该边求值后，运行图记录判定结果及逐项身份；目标实例在全部前驱满足后创建时，形成指向各个目标实例的实例连接。零项或条件关闭时不产生目标实例及实例连接，位置仍按引擎规则跳过。实例组的出边以聚合后的组输出为来源，不把每个逐项实例的输出当成下游的独立输入；尚未解析的边仍以定义关系和运行状态呈现。画布只绘制这些有依据的关系，不按实例数量做笛卡尔积连线。
- 使用宿主已有的 `dsh-storage-domain` 持久化工作流实例。模板快照和版本化实例运行图由服务端维护；运行图是可恢复执行的权威动态数据，包含恢复所需的实例身份、位置/边状态、逐项输入与输出等，展示快照只是其投影。提交成功后原子保存一次运行图变更，再向客户端返回新投影；刷新或宿主重启时由保存的运行图恢复可继续推进的执行。当前 DAG 引擎仅提供查询快照而没有状态导出/恢复接口，实施时须补足这一能力，不能把现有展示快照直接当恢复格式。
- 提交失败时，使用引擎的事务回滚语义，不保存部分推进；目标节点仍显示就绪，并向用户呈现校验错误。不新增“失败”节点状态，也不把失败提交当作一次已完成执行。
- 服务端根据工作流实例身份与当前运行图中的节点实例身份执行操作，并生成占位输出；客户端不提交自造的节点输出。节点实例身份须随运行图持久化，在刷新和恢复后保持可寻址，不依赖重新执行初始化时偶然得到相同的 ID。服务端须核对目标仍在可执行前沿；过期或重复请求不得使同一节点成功提交两次，并应让客户端取得最新投影。请求期间按钮可暂时禁用，但不引入新的持久节点状态。
- 使用宿主现有组件、主题变量和图标风格，兼顾浅色／深色主题、中英文和窄屏。状态含义不能只靠颜色表达。

## Testing Decisions

- 优先验证用户可观察的服务端行为，不针对零值生成的私有函数或组件内部状态写镜像测试。
- 沿用工作流实例 HTTP 路由的现有集成测试入口，覆盖创建后逐个执行、不同 Schema 类型的占位输出、`if`／`for` 分支、逐项实例独立执行、实例连接与组聚合关系、提交错误回滚、过期与重复请求、刷新和宿主重启后的继续推进及实例身份保持。现有实例创建与持久化测试是先例。
- 沿用工坊页面的现有组件测试入口，覆盖状态与操作的显示、点击目标互不干扰、详情检查器／抽屉的开关、所选对象状态变化与等待位置消失、键盘可达性、中英文名称，以及等待、已跳过和 DAG 分组没有执行按钮。现有 Tab、画布和实例交互测试是先例。
- 测试在公开服务边界检查推进后的快照与持久结果，在页面边界检查用户可见操作；不把 React Flow 布局坐标或存储内部格式当作验收条件。

## Out of Scope

- 真实节点业务任务、自动执行所有就绪节点、任务调度、排队、执行中、执行失败、取消、暂停、重试和重跑已完成节点。
- 详情正文中的输入、输出、依赖原因、日志、历史尝试、编辑或场景回放。
- 给已跳过位置构造实例或输出，改变 `for` 零项、条件边与 DAG 输出边界的现有语义。
- 修改工作流模板、拖动节点、手动连线或改变 DAG 定义。

## Further Notes

- 本规格扩展现有[实例 Tab 规格](./instance-tab.zh.md)的只读画布阶段；两者的交付阶段应保持清晰。
- “占位输出”仅用于本期无真实节点任务时推进执行，它符合输出声明的类型，但不代表业务计算结果。其零值可能让条件分支关闭或逐项展开为空。
- 本期零值数组会让从占位输出读取该数组的 `for` 边得到零项，因此这类逐项实例通常不会在本期交互中出现；运行图和连线语义仍需覆盖已有非空输入或以后真实节点输出产生的实例组。
- 如果一个合法 DAG 的占位输出导致最终输出缺少必需字段，现有引擎会拒绝并回滚该次提交；本期将其作为可见的提交错误处理，不把缺失字段补零，也不改变被跳过位置的状态。
- 产品用语沿用[词汇表](../../CONTEXT.md)中的“工作流实例”“节点实例”“执行位置”“实例组”“可执行前沿”。
