# form 对象与数组字段规格

状态：2026-10-07 已实施，自动化与真实宿主已执行场景通过。验证范围、宿主未执行项和审查结论见[验收记录](../acceptance/form-structured-fields.zh.md)。本文是本次实施与代码审查依据。

## Problem Statement

工作流使用者需要填写数量不固定的列表，每项包含多个字段，例如每项填写名称和数值。现有 form 只支持字符串、数字和布尔值，不能直接编辑对象与数组；用户只能将结构化结果写成 JSON 文本再交给其他节点处理。

本次仅补齐五种类型的填写能力、数组增删和组合嵌套，并保留原有表单能力。不能借此增加其他表单逻辑或改变公共 DAG 规则。

## Solution

form 根据输出契约生成字符串、数字、布尔值、对象和数组字段。对象展示其声明的子字段，数组允许用户添加、删除和填写元素；元素可以是五种类型中的任意一种，因此支持对象数组、对象中的数组和数组中的数组。数组长度由实际填写决定，空数组合法。

标量字段继续使用原有控件、枚举、标题、说明和默认值。已有预填按字段整体采用，不与默认值合并；新增数组项应用该项配置的默认值，没有默认值的标量等待用户填写。正式提交通过服务端校验后形成真实节点结果，沿用草稿、只读、结果交付重试和恢复规则。

## User Stories

1. 作为模板作者，我希望使用字符串、数字和布尔值，以便原有表单继续有效。
2. 作为模板作者，我希望声明对象字段，以便将相关字段组织在一起。
3. 作为模板作者，我希望声明数组字段，以便收集数量不固定的数据。
4. 作为模板作者，我希望数组元素可以是标量，以便收集名称或数值列表。
5. 作为模板作者，我希望数组元素可以是对象，以便每项收集多个参数。
6. 作为模板作者，我希望对象和数组可以组合嵌套，以便表达实际数据结构。
7. 作为模板作者，我希望字段结构仍由输出契约决定，以便不维护另一份字段清单。
8. 作为模板作者，我希望嵌套字段可以配置标题和说明，以便用户理解每项含义。
9. 作为模板作者，我希望嵌套标量可以使用原有控件，以便长文本、数字和布尔值保持原有填写体验。
10. 作为模板作者，我希望嵌套标量保留枚举能力，以便限制可选值。
11. 作为模板作者，我希望保留默认值，以便减少重复填写。
12. 作为模板作者，我希望错误的结构、注解或控件配置在模板判定时被拒绝，以便不在填写时才发现配置无效。
13. 作为工作流使用者，我希望新增数组项，以便按实际数量逐项填写。
14. 作为工作流使用者，我希望删除任意数组项，以便移除不需要的数据。
15. 作为工作流使用者，我希望删除一项不改变其余项的内容和相对顺序，以便不会发生数据串项。
16. 作为工作流使用者，我希望可以删除全部数组项并提交空数组，以便明确表达没有数据。
17. 作为工作流使用者，我希望新增项使用其配置的默认值，以便延续既有默认值能力。
18. 作为工作流使用者，我希望没有默认值的标量留待填写，以便系统不猜测业务值。
19. 作为工作流使用者，我希望每项独立编辑，以便修改一项不会修改其他项的默认内容。
20. 作为工作流使用者，我希望沿用同名上游预填，以便继续处理前序节点产生的数据。
21. 作为工作流使用者，我希望预填的零、假、空字符串和空数组被保留，以便它们不会被默认值替换。
22. 作为工作流使用者，我希望已有预填对象保持其已提供内容，以便系统不会自动合并子字段默认值。
23. 作为工作流使用者，我希望部分预填对象的缺失字段由我补充，以便提交内容明确。
24. 作为工作流使用者，我希望预填仅包含表单声明的字段，以便无关上游内容不会混入结果。
25. 作为工作流使用者，我希望编辑不会修改上游输入或模板默认值，以便其他节点和表单项不受影响。
26. 作为工作流使用者，我希望关闭详情或切换节点后保留当前页面草稿，以便继续填写嵌套内容。
27. 作为工作流使用者，我希望已删除的项不会因重新初始化而恢复，以便草稿反映我的操作。
28. 作为工作流使用者，我希望错误反馈能指出具体字段或数组项，以便修正无效内容。
29. 作为工作流使用者，我希望提交失败后保留填写内容，以便修正后再次提交。
30. 作为模板作者，我希望服务端递归检查完整性、类型和枚举，以便绕过页面也不能提交无效结果。
31. 作为模板作者，我希望正式提交每层都只包含声明字段，以便结果边界一致。
32. 作为工作流使用者，我希望正式提交保持对象结构和数组顺序，以便下游收到我填写的数据。
33. 作为工作流使用者，我希望提交成功后所有嵌套控件和增删操作都只读，以便已接受结果不会改变。
34. 作为工作流使用者，我希望结果交付失败时只重试已接受结果，以便不会再次开放填写或覆盖结果。
35. 作为工作流使用者，我希望重启后保留已接受的结构化结果，以便恢复工作流时不丢失数据。
36. 作为工作流使用者，我希望不同节点实例的表单和数组项互不影响，以便并行填写不会串用草稿。
37. 作为工作流使用者，我希望新增界面兼容中英文、深浅主题和窄屏，以便继续在宿主中正常填写。
38. 作为项目维护者，我希望只扩展 form 的业务能力，以便保持公共节点协议、DAG 和存储的职责边界。

## Implementation Decisions

- **范围与模块。** 改动集中在 form 节点的服务端校验、前端字段解析与渲染、文案和必要样式。继续通过现有公共节点动作与草稿接口工作，不增加 API、公共状态或持久化格式。节点包不得依赖 Studio 的 DAG、工作流或存储内部实现；不为本次能力引入完整表单库或通用表单框架。
- **五种类型。** 输出契约继续使用现有标量简写以及带属性声明的对象、带元素声明的数组。数组的所有元素遵循同一元素契约。按声明结构递归处理，不人为限定为两字段或一层对象数组；不增加联合类型、null、元组、动态对象键或新的类型转换规则。
- **字段归属。** 输出契约是字段名、类型和嵌套结构的唯一来源。输入契约仍只声明同名预填字段；每个已声明的预填字段与对应输出字段结构类型一致，递归比较对象属性和数组元素类型，不以对象引用相等判断，也不按键顺序判断。输入输出顶层字段集合仍可不同。
- **注解与控件。** 补充 schema 沿 properties 和 items 递归配置标题、说明、默认值及标量枚举，可选 type 必须与输出契约一致。uiSchema 沿既有 RJSF 约定，以对象子字段名和数组 items 递归定位，叶子仍只支持原有 ui:widget 子集。注解无需重复列出全部字段，但不能增加未知字段或冲突结构；省略注解时直接根据输出契约生成表单。不宣称支持完整 JSON Schema 或完整 RJSF。
- **原有标量能力。** 单行、多行、数字、布尔开关和单选控件继续有效；枚举只用于字符串、数字和布尔值，数组中的标量及对象内部标量同样适用。枚举值须符合字段类型，标量默认值须属于对应枚举。对象和数组自身不增加枚举或新的控件选择。
- **预填整体优先。** 已接受结果优先于草稿，已有草稿优先于初始化。首次初始化逐顶层输出字段判断上游同名字段是否存在：存在则采用其声明范围内的完整值，不与该字段默认值或任何子字段默认值合并；只有字段不存在才进入默认值初始化。存在的零、false、空字符串、空对象和空数组都不是缺失。部分预填对象允许展示其已有字段，其缺失字段留给用户填写，正式提交仍须完整。错误类型继续报错，不转换，也不回退到默认值掩盖错误。
- **默认值初始化。** 没有预填值、且该字段或新增项有显式 default 时，复制并采用整个默认值，不再与子字段默认值合并。结构化默认值必须完整符合对应输出结构及其嵌套枚举，且不包含未声明字段；不接受需要在运行时补全的无效默认值。没有整体默认值的对象按声明子字段初始化，子字段各自应用已有默认值；没有整体默认值的数组从空数组开始，不凭 items 的默认值生成首项。没有默认值的标量保持待填写，不自动写入空字符串、零、false 或首个枚举值。
- **新增与删除。** 新增仅在数组末尾追加一项，按元素声明应用上述默认值初始化规则，支持在任意数组层级操作。删除只移除选中的一项，保持剩余值和相对顺序；允许删到零项。数组默认值只用于初始化，用户删除后不重新补回。尚未填写完整的项可以存在于页面草稿，不能为了满足可序列化值类型而自动填入业务值。
- **预填取值范围与提交范围。** 预填时按输出契约递归只取已声明字段，对象数组的每项同样处理，不修改原始输入；未声明上游字段不显示、不进入草稿和结果。正式提交则递归拒绝任何层级的额外字段，不通过静默剔除使无效提交成功。每层声明对象的全部字段必须存在，数组每项必须符合元素结构。此规则只属于 form，不改变 DAG 对额外字段的公共语义。
- **空值与完整性。** 空数组合法，包括嵌套数组；空字符串仍是合法字符串。无默认值且未填写的标量保持缺失，不能把视觉上的空控件或未选中开关视为已填写。没有声明子字段的对象允许为空对象；有声明子字段的对象必须在提交时填齐。用户可通过既有控件写入 false、零或空字符串。不新增可选字段、非空字符串限制或数组最少项规则。
- **数据隔离。** 编辑、增删、初始化和只读展示不能修改上游对象、源默认值、其他数组项或其他节点实例的数据。草稿更新按路径复制所修改的容器；完整结果继续通过既有动作通道提交，不把路径标识、列表行身份或 UI 临时数据加入业务输出。缺字段草稿通过既有页面行为处理，不新增服务端草稿协议。
- **提交与恢复。** 服务端接受前递归执行类型、完整性、有限数字、枚举及字段范围校验，错误能定位到嵌套字段和数组下标。类型校验的递归扩展是本次必要部分，不增加新的业务校验关键字。无效提交不完成节点、不推进下游，页面保留草稿。成功后包含增删按钮在内的编辑能力关闭；结果交付失败、重试、防重和重启恢复继续使用已经接受的确定结果。
- **界面。** 对象采用简单子字段分组，数组采用逐项填写和添加、删除操作，沿用宿主尺寸、主题、语言及键盘交互。保留原有标题、说明与控件含义，不增加排序、复制、折叠、表格模式或布局设计功能。

## Testing Decisions

用户已确认沿用现有测试边界：主要在工作流实例 HTTP 集成入口验证模板判定、正式提交、下游结果和恢复；在现有节点详情界面测试边界验证填写和草稿；最后在固定版本真实宿主中执行浏览器验收。不新增测试专用生产接口，不断言私有函数或内部状态形状。

已有先例包括 form 枚举拒绝、真实结果交付下游、预填零／假／空字符串、接受后禁止修改、交付失败重试，以及关闭详情和切换节点保留草稿的测试。按这些入口扩展外部行为场景：

| 场景 | 预期结果 |
| --- | --- |
| 原有三种标量、所有既有控件、枚举与默认值 | 现有模板和填写行为继续成立 |
| 两字段对象列表 | 可增删多项，提交保持每项字段及顺序，下游收到同一结构 |
| 标量数组、对象中的数组、数组中的数组 | 每层按声明正确编辑、增删和提交 |
| 初始空数组、删除全部项、嵌套空数组 | 均可形成合法空数组，删除内容不被默认值恢复 |
| 新增项有整体默认值或仅子字段默认值 | 按已确认初始化规则生成独立项，无默认值标量保持未填写 |
| 整体结构化 default 缺字段、额外字段或嵌套枚举无效 | 模板判定失败，不在运行时合并或补全 |
| 上游对象部分缺字段，缺失子字段有 default | 保留已提供值，不补默认值；补齐前提交失败，手动补齐后成功 |
| 上游值为零、false、空字符串、空对象或空数组 | 不被默认值替换；部分对象仍受提交完整性检查 |
| 预填有嵌套额外字段 | 页面与提交内容只包含声明字段，原始上游数据不变 |
| 直接请求提交顶层或嵌套额外字段 | 服务端拒绝，不静默剔除后接受 |
| 缺字段、嵌套错误类型、非法枚举、非法数组元素 | 服务端拒绝并指出位置，节点与下游不推进，草稿保留 |
| 编辑一项、删除中间项、重新打开详情 | 其余项不串值，相对顺序和页面草稿保持，默认值与上游不变 |
| 草稿清空字段或删除项后重渲染 | 不自动重新应用预填或默认值 |
| 切换节点、刷新页面、插件卸载 | 保持既有草稿保留／丢弃边界，不新增持久化或同步 |
| 成功提交与结果交付失败重试 | 全部嵌套编辑及增删关闭，重试使用已接受结果，不能覆盖 |
| 保存后重启 | 已接受结构化结果恢复，未提交页面草稿不恢复 |
| 多个节点实例与共享配置默认值 | 草稿和结果相互独立，无对象引用导致的数据串用 |

实施期间运行相关测试和类型检查，完成后执行完整检查。使用 dsh-browser-e2e 技能，在 dsh 0.2.0-rc.1 的隔离 home 和工作区中验收增删、嵌套填写、预填、默认值、错误提交、草稿、只读和下游结果；覆盖中英文、浅深主题、窄屏及必要键盘操作。真实宿主结果按项目约定记录；接口或组件测试不能代替真实宿主验收。环境受阻时保留明确的失败或未验证项，不写成整体验收通过。

## Out of Scope

- 列表排序、复制项、批量导入、文件上传、富文本、折叠、表格模式和可视化表单设计器。
- 新增 required、长度、范围、格式、唯一性、最少／最多项等校验配置；条件联动、远程选项、计算字段和自定义表达式。
- 对象或数组整体枚举、联合类型、null、元组、动态键、schema 引用和完整 JSON Schema／RJSF 支持。
- 预填与默认值深度合并、自动补全已存在的预填对象、隐式类型转换或自动生成标量业务值。
- 服务端草稿保存、跨页面同步、提交后再编辑、工作流回退、新的重试机制或通用表单引擎。
- 改变 DAG 的类型、额外字段、for、依赖、聚合、持久化协议及公共节点注册规则。
- 迁移现有内置模板的 JSON 文本输入流程、修改其他节点能力、升级或安装 dsh CLI、发布分发。
