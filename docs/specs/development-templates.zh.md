# 开发用节点功能模板与默认装配

状态：已实施；类型检查、构建、175 项自动化与 9 条真实宿主浏览器用例通过。Agent 真实模型体验未验证，具体范围见[验收记录](../acceptance/development-templates.zh.md)。

## 行为规则

- 默认 `dsh-workflow-bundle` 只装配正式节点、Studio、加载器和内置业务模板，不依赖或登记开发模板。
- `packages/dsh-workflow-dev-templates` 是独立纯配置插件包，按 form、bash、agent 组织主模板，并按实际需要提供 Bash 重试专题。声明只使用已有模板加载器，不重复启用节点、Studio 和业务模板。
- `npm run install:dev` 构建后向独立 `.local/dsh-dev/` home 装配默认 bundle 和开发模板；`npm run dev` 同样装配后启动宿主，安装和启动使用同一 home。用户仍自行安装固定版本 dsh。
- 开发模板是普通模板，从现有模板列表、创建流程和实例页面体验，使用真实节点、快照、持久化及恢复。不增加开发运行语义、分类字段或专门页面。
- form 展示标量、对象与数组、默认值、枚举名称、多选、草稿、真实下游预填及提交只读；bash 展示手动/自动启动、输入引用、附属脚本、日志/输出、无输出及失败重试；agent 展示台前交流与交付、嵌套台后自动执行、记录及人工确认。
- 根 `examples/` 的 review-templates、all-nodes、echo-node 删除。作者指南直接引用正式节点、模板、bundle 和公共契约实现；有效集成断言迁入开发模板测试或已有独立夹具，第三方接入继续由联合装配测试验证。
- 开发模板无需覆盖内部故障或所有配置组合。测试夹具独立准备前置条件，不依赖被删除的作者示例；历史验收保留适用版本说明。

## 验收场景

1. 只添加默认 bundle 时，开发模板不登记；开发附加包只声明模板，全部资源可解析、校验并创建实例。
2. 隔离真实宿主中添加开发包后，现有列表显示四份开发模板及准确来源，不出现节点重复冲突；宿主重启后模板和已创建实例保留。
3. form 修改对象/数组、枚举和多选后交付真实数据，下游预填保留 0、false 和空数组，不被备用默认值覆盖；提交后结果只读。
4. bash 从上游接收中文、引号、换行和 Shell 特殊字符，手动和自动节点均原样交付；日志区别于业务输出，无输出命令完成后根 DAG 完成；重启不重跑已成功命令。
5. Bash 重试专题前两次失败不推进，第三次有效输出推进下游；原命令保持不变。
6. Agent 主模板的台前/台后配置、输入提示词引用、嵌套结果交付有效；真实模型执行单独记录，不把确定结果测试或模板浏览称为模型验收。
7. 既有默认模板、第三方登记及联合装配的生命周期回归保持通过；无当前文档或夹具依赖已删除的 examples。
