## 结论与依据

基础设计语言大体一致，但弹窗、表单控件和状态色尚未统一。主要问题集中在 Studio 自定义样式与已经采用宿主组件的 Form 浮窗之间。应先修复无效主题变量，再对齐同类组件；不需要重新设计整套 UI。

依据：

- [项目 UI 约定](../../AGENTS.md)：优先复用宿主组件和主题变量，同类界面保持一致。
- [Form 填写浮窗规格](../specs/form-dialog.zh.md)：宿主 Modal、Button、Input 为已经实施的呈现基准。
- [实例管理规格](../specs/instance-tab.zh.md)：新建和删除确认框参考宿主风格。
- [模板管理规格](../specs/template-management.zh.md)、[共享定义详情规格](../specs/shared-definition-details.zh.md)：模板与实例详情的展示依据。

本次是人工视觉与样式审查，不是上述规格的完整业务验收，也不替代既有 E2E。

## 原始发现（4abefa3）

### 1. 错误色变量未定义，实际呈现丢失错误语义（优先处理）

位置：[Studio 样式](../../packages/dsh-workflow-studio/src/client/pages/workflow-studio/styles.ts)，涉及模板错误、删除菜单与确认、新建校验、运行错误、节点错误文字及状态点。

引用的 `--dsw-alias-label-error` 在真实宿主的相关元素计算样式中为空。宿主有效变量为 `--dsw-alias-state-error-primary`。

实际操作与结果：

| 场景 | 预期 | 实际 | 状态 |
| --- | --- | --- | --- |
| 新建同工作区同名实例 | 校验提示具有错误色 | 浅色提示为普通文字色 `rgb(15, 17, 21)` | 不一致 |
| 打开删除菜单及确认框，不确认删除 | 危险操作具有明确颜色语义 | 深色菜单和确认按钮为普通文字色 `rgb(249, 250, 251)` | 不一致 |
| 执行开发 Bash 重试模板的首次失败，打开节点详情 | 画布错误状态与记录错误使用同一语义色 | 浅色画布“执行异常”为 `rgb(15, 17, 21)`，错误点背景透明；记录摘要错误为红色 `rgb(236, 19, 19)` | 不一致 |
| 同一失败切换深色 | 错误语义随主题一致 | 画布文字为 `rgb(249, 250, 251)`，记录摘要为红色 `rgb(242, 90, 90)` | 不一致 |

建议：统一使用宿主有效的错误色变量，并覆盖校验、危险操作和执行异常。详情运行区与记录全文中的 `role="alert"` 也应核对颜色规则；目前有普通或次级文字色，不应只改摘要。

### 2. 同类弹窗采用两套表面、边框和圆角规则（优先处理）

位置：Studio 的 `.dsh-workflow-create-*`、`.dsh-workflow-delete-*`；对照 [Form 浮窗](../../packages/dsh-workflow-node-form/src/client.tsx) 使用的宿主 Modal。

| 属性 | 新建实例 | 删除确认 | Form / 宿主 Modal |
| --- | --- | --- | --- |
| 面板背景 | `bg-base` | `bg-base` | `bg-layer-2` |
| 深色背景实测 | `rgb(21, 21, 23)` | 使用相同 `bg-base` 规则 | `rgb(44, 44, 46)` |
| 桌面圆角 | 32px | 20px | `radius-panel`，实测 28px |
| 面板描边 | 0.5px `border-l2` | 0.5px `border-l2` | 无描边 |
| 遮罩 | 固定黑色 40% | 同左 | 宿主 `bg-mask-1`，浅色 24%、深色 50% |

390px 窄屏下，新建面板宽 370px、圆角 18px，Form 面板宽 342px、圆角 28px。两者均未观察到面板横向溢出，但留白和边界语言仍不同。浅色主题面板均为白色，背景差异被隐藏，不能据此认定已经统一。

建议：新建和删除确认优先复用宿主 Modal，保留各自业务内容与必要尺寸，统一浮层材质、遮罩和圆角。

### 3. 同类输入框和主按钮的边界与规格不同（中优先）

实际比较新建实例与 Form 浮窗：

| 属性 | 新建实例 | Form |
| --- | --- | --- |
| 输入描边 | 0.5px `border-l2` | 0.5px `border-l4` |
| 输入圆角 | 8px | `radius-md`，实测 12px |
| 输入背景 | `bg-layer-2` | `bg-layer-3` |
| 深色输入背景 | `rgb(44, 44, 46)` | `rgb(53, 54, 56)` |
| 主按钮圆角 | 8px | 12px |
| 主按钮高度 | 最小 32px | 最小 36px |
| 深色主按钮文字 | `rgb(53, 54, 56)`，使用 `label-primary-inverted` | `rgb(15, 17, 21)`，使用宿主 Button 的 `label-primary-foreground` |

浅色输入描边也不同：新建为黑色 10% 透明度，Form 为黑色 16%。这不是仅在深色主题出现的问题。

建议：同等尺寸与用途的输入框、主按钮采用宿主组件及相应字段样式。紧凑画布动作可以保留紧凑规格，不要求与弹窗主按钮同大。

### 4. 布局警告未采用有效宿主警告色（中优先，源码及变量核对）

`.dsh-workflow-layout-notice` 使用 `--dsw-alias-state-warning-primary`，在真实宿主计算样式中为空；实际有效变量是 `--dsw-alias-state-warn-primary`。目前会采用固定回退色 `#a8690d`，而本轮深色宿主警告色解析为 `#f59e0b`。

建议：改用宿主有效警告变量。此次未单独触发布局诊断条，以上结论来自源码和真实主题变量核对，不宣称已复验诊断条的全部视觉状态。

## 已一致与可保留的边界

- 工坊主体、文字层级、Tab 高亮、hover 背景总体使用宿主主题变量；主题切换正常。
- 模板预览与实例画布共用节点、连线和详情样式，观察到的基础呈现一致。
- 实例卡片、模板卡片和普通节点均使用 `bg-layer-1` 与 0.5px `border-l2`，基础配色一致。
- 详情字段细分隔、运行区的轻微底色、插件来源的独立边框承担不同信息层级；不能仅因 0.5px 与 1px 同时出现就认定错误。
- 卡片、菜单与画布的小圆角仍散落着 5/6/7/8/9/10/11/12px 等常量，建议后续按角色映射宿主圆角变量，优先统一同类控件，不机械统一所有数字。
