日期：2026-10-13。范围：Studio 模板预览、实例运行图的客户端布局与边渲染，无新增模板字段或工作流执行规则。

依据：[实例运行图阅读与操作体验](../specs/instance-graph-readability.zh.md)、[模板作者可配置的实例运行图排布](../specs/template-layout.zh.md)。

## 环境与方法

- macOS arm64；Node v26.7.0、npm 11.19.0、pnpm 11.25.0；用户已安装 dsh 0.2.0-rc.1。
- 浏览器 E2E 使用隔离 `DSH_HOME` 与工作区、默认 workflow bundle、Chromium；宽屏 1440 × 900，窄屏 390 × 844。测试结束由夹具停止宿主并清理临时数据，不使用日常 profile 或模型凭据。
- [布局自动化测试](../../packages/dsh-workflow-studio/tests/serial-chain-layout.test.ts)读取独立串行链夹具（与 OpenSpec 四阶段示例同构），覆盖初始与推进后的运行快照、方向、多个外围通道、嵌套边界与真实并行分支。
- [浏览器用例](../../e2e/workflows/serial-chain-layout.e2e.ts)通过页面浏览模板、创建实例、提交需求和切换设置；读取实际卡片位置与 SVG 路径，断言四条边全部可见且路径不穿过卡片。

提交前将新增布局测试切换到[独立串行链夹具](../../e2e/fixtures/core-regression/templates/serial-chain/workflow.yaml)，避免依赖同时存在于工作区的另一批未提交 OpenSpec 模板修改。夹具使用真实表单与 Bash 节点，保留相同四阶段及跨节点依赖结构；独立夹具的 5 条布局自动化测试与真实宿主浏览器用例再次通过（报告 `01a13521-8dda-7bb2-91a7-aaee15f9c918`）。原 OpenSpec 模板的真实验收结果保留如下。
