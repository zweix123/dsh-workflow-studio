## 固定版本真实宿主

### 环境与入口问题结论（2026-10-04）

本机 CLI 与宿主设置页均确认 `0.2.0-rc.1`。被测为上述基线后的当前工作区构建；新建临时 DSH_HOME、web profile、空工作区，在非默认端口 31976 启动，未读取或修改日常 profile、凭据或实例。未安装或升级 CLI，没有把 references 中其他版本当作验证证据。

先在干净 profile 中仅添加 `packages/dsh-workflow-bundle`，真实页面可进入工坊并列出六份有效内置模板。随后另行添加 `examples/echo-node` 与[浏览器验收夹具](../../packages/dsh-workflow-studio/tests/fixtures/browser-node/README.md)，通过当前本地模板目录放入验收 YAML；这不是第二阶段的模板分发。

此前仅访问裸地址时返回 401，内置浏览器报告 `ERR_BLOCKED_BY_CLIENT` 并停留空白。此次使用临时宿主启动输出的完整 Web 登录地址，经正常登录建立 cookie 后，同一浏览器可进入宿主并完成以下操作。因此原先“浏览器本地访问能力不可用”的结论不再适用。`credentialOnboarding: false` 只跳过模型凭据引导，不关闭 Web 登录。

另一个已确认的安装问题：旧入口 `packages/dsh-workflow-studio` 现在只装配 Studio，缺少公共节点浏览器服务时会提示 `waiting for service: workflowNodeViews`；默认入口必须改为 `packages/dsh-workflow-bundle`。CLI 进程启动成功不等于所有客户端插件激活。[浏览器技能](../../.agents/skills/dsh-browser-e2e/SKILL.md)已同步入口及登录检查。

复现入口：对插件添加和宿主启动使用同一临时 `DSH_HOME`；执行 `dsh plugin --profile web add <仓库>/packages/dsh-workflow-bundle`，再按技能的 patch 用 `dsh --profile web --patch <临时目录>/e2e.patch.yml --host 127.0.0.1 --port <空闲非默认端口> --no-open` 启动。浏览器使用此次启动输出的完整地址登录，验收记录不保存 token。补装夹具时若报 `ERR_PNPM_UNEXPECTED_STORE`，向该临时 profile 的插件命令显式传入其原有 `--store-dir=<原路径>`，并使用 `--registry=https://registry.npmjs.org`；不改全局 npm/pnpm 配置。
