# Agent 节点

[文档导航](../../README.zh.md) · [整体 DAG 语法](../../dag-syntax.zh.md)

## 用途与最小示例

`node_kind: agent` 由 Agent 处理任务，支持可持续交流的台前模式和直接执行任务的台后模式。以下是放入 DAG 的 `dag` 数组中的节点定义；完整模板还需根 `id`、`type: dag`；可选 `name` 与统一 ID 规则见[整体 DAG 语法](../../dag-syntax.zh.md#31-工作流模板与节点类型)。

```yaml
id: discuss
type: node
node_kind: agent
prompt: 分析当前工作区的项目结构，并说明建议的下一步。
```

默认采用台前模式，手动执行后可进入宿主对话。未声明输出时，用户点击“完成”以空对象完成节点。

## 配置字段

公共 `id`、`type`、`input_schema`、`output_schema` 见 [DAG 定义结构](../../dag-syntax.zh.md#3-实体数据结构)。本类型解释以下业务字段；其他自定义字段保留，但不获得业务含义。

| 字段 | 类型 | 必填 / 默认值 | 含义 |
| --- | --- | --- | --- |
| `node_kind` | 字符串 | 必填，`agent` | 选择 Agent 节点插件 |
| `prompt` | 字符串 | 必填 | 本次任务的提示词，支持输入引用 |
| `mode` | 字符串 | 默认 `foreground` | `foreground` 台前或 `background` 台后 |
| `is_auto_start` | 布尔值 | 默认 `false` | 首次就绪时自动启动；不表示自动完成 |

`prompt` 允许空字符串或纯空白，原始配置不裁剪。台前模式先渲染 prompt；结果为空或纯空白时发送默认提示词「请先询问我希望处理什么任务。」，否则原样发送渲染结果。

## 输入如何使用

在当前节点 `input_schema` 声明所需输入，再通过 Nunjucks 默认语法写入 prompt；支持字段内条件、文本循环、局部变量、宏、raw、注释与内置能力。结构化 JSON 显式使用 dump。具体路径、类型转换与缺失值规则见[共用输入引用](../input-references.zh.md)。系统不自动追加整份输入，其他对话的上下文也不会自动成为本节点输入。

提示词宜写明任务、输入材料、允许动作、产物和人工交接方式。使用多行 `prompt: |` 保持可读性。声明输出后，明确各字段应代表的业务结果；在提示词中写“输出 JSON”不能替代结构化结果交付。

## 输出如何产生

有输出声明时使用宿主原生 `structured_output` 工具交付，并按 DAG 契约校验。省略或留空 `output_schema` 时结果为 `{}`，不自动透传输入；台前跳过额外交付子 Agent，台后仍执行任务。

DAG 的输出字段在每层对象均为必需字段，额外字段仍允许；节点按此语义映射到宿主 JSON Schema，不从普通文本解析或猜测结果。输出声明中的附加信息不会变成额外约束。结构合法不保证任务语义正确，材料缺失或读取失败应交付失败。fork 使用已结束轮次重建的有效上下文，压缩遮蔽的旧材料不会重新纳入；后续消息不混入当次交付，但工作区文件没有快照。固定 rc.1 的 fork 只包含末次完整轮次之前的事件；若该轮次之后又手动压缩，交付会明确失败，需先继续对话并等待新轮次结束，再重试“完成”，避免重新引入已遮蔽材料。长对话仍受模型容量限制，不能保证重读完整未压缩历史。`for` 展开的每个 Agent 实例各有自己的对话或子执行。本期不增加自动结束配置、结束任务工具、取消功能或自定义 trace。

## 执行与完成

手动“执行”只启动选中的就绪节点实例；`is_auto_start: true` 在首次就绪时启动。下游就绪后是否自动启动由下游自己的配置决定。

- **台前**：创建独立的普通宿主对话，可以持续交流。主对话生成中或有排队消息时，“完成”不可用，服务端同样拒绝完成请求。有输出声明时，点击“完成”启动继承已结束轮次有效上下文的原生 fork，仅整理、读取与核验已完成任务的结果，不补做任务或修改业务产物。它通过宿主按 `output_schema` 提供的 `structured_output` 工具提交结果；公共输出校验通过后保存并交付 DAG，无须第二次点击。没有输出声明时跳过额外交付子 Agent，以 `{}` 完成。
- **台后**：子 Agent 直接执行 prompt 中的任务，同样用 `structured_output` 交付声明输出。没有输出声明时仍执行任务，成功结果为 `{}`。结果保存后等待用户点击“完成”，确认不重新执行任务；重启后仍等待确认，不自动推进。按工作区复用隐藏的空闲父 Agent，工作目录、权限与当前宿主默认模型配置来自宿主，不同工作区隔离。

## 失败、重试与恢复

详情末尾的统一“运行记录”列出台后任务与台前结果交付的历次尝试，最近一次在前，最新一次默认展开；保留实际输入、当次实际提示词、结果、时间、错误和对应原生记录入口。台后有效结果在确认前标为待确认。记录只读，不支持继续发消息或重用旧结果。普通失败不自动重试：台前可在原对话补充材料后再次完成，台后可再次执行任务。中断且无确定结果时显示结果未知，用户决定是否重试。已获准提交且保存成功的结果只重试 DAG 提交。

成功业务结果若 DAG 交付失败，业务历史仍为成功，当前显示“业务完成，交付失败”；第 2 位改为“重试交付”，只重交已接受结果，不重新执行任务或提取结果。具体编排诊断在所属 DAG 详情。仅新图状态保存成功后显示已完成。

金刚位“记录”直接进入最新一次尝试，不再打开多条选择浮窗。最新尝试尚无原生地址或创建失败时禁用并说明原因，不回退旧记录；旧地址从详情历史访问。台前“对话”仍进入主对话。

开始记录必须保存成功才调用 Agent；进度保存失败后停止继续业务，最终结果保存失败不接受、不交付。当前页面显示可取得的保存错误，不保证存储故障中的诊断在重启后仍存在。待确认结果保持人工确认权，已接受成功结果只恢复交付。历史随实例保存与删除，不复制宿主完整过程、不迁移或补齐旧历史；宿主原生会话仍按宿主自己的生命周期保留。

## 完整示例

以下模板从表单取得任务，由台后 Agent 分析，保存结果后等待用户确认完成，根 DAG 返回 `summary`。

```yaml
id: analyze-task
name: 分析任务
type: dag
output_schema:
  summary: string
dag:
  - id: request
    type: node
    node_kind: form
    output_schema:
      task: string
  - id: analyze
    type: node
    node_kind: agent
    mode: background
    input_schema:
      task: string
    output_schema:
      summary: string
    prompt: |
      分析以下任务，不修改工作区文件：
      {{ task }}
      将主要结论交付到 summary 字段。
  - type: edge
    from: request
    to: analyze
```

将 `mode` 改为 `foreground` 即可持续交流，再点击“完成”整理与交付结果。模型执行和结果语义仍需实际验证。包构造与加载见[模板作者指南](../../template-plugin-authoring.zh.md)。
